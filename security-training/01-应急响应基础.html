01 应急响应基础（Windows/Linux 入侵排查）

对应 10月19日上午：应急响应实战。本文是地基，全部【背】。

一、应急响应六步法【背】

隔离取证 → 查进程 → 查持久化 → 查账户 → 查日志 → 清理加固

一句话口诀：先隔离（断网不断电），再按"进程→持久化→账户→日志"四步排查，最后清理后门+修复加固。

  1. 隔离取证：拔网线/断外联（别关机，内存里有证据）；先做内存/镜像取证再动系统。
  2. 查进程：找可疑进程、异常外联。
  3. 查持久化：找攻击者留下的"后门"，重启也还在的那种。
  4. 查账户：找新增账户、隐藏账户、克隆账户。
  5. 查日志：还原攻击者什么时候来的、干了什么。
  6. 清理加固：删后门、补漏洞、改口令、复测验证。

二、Windows 排查背诵清单

1. 进程与网络【背】

tasklist /v                          # 进程列表（看无签名/无描述/路径异常）
tasklist /svc                        # 进程与服务对应（看 svchost 挂非系统服务）
netstat -ano                         # 网络连接（看 ESTABLISHED 外联陌生IP，记 PID）
wmic process get name,processid,commandline   # 进程完整命令行（关键！）
  • 可疑特征：进程名伪装系统进程（如 svch0st.exe、scvhost.exe）、路径不在 System32、无数字签名、命令行带编码 payload。

2. 持久化排查：五个位置【背】

位置查法
① 注册表自启动HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run、RunOnce、HKCU 下同名项
② 计划任务schtasks /query /fo LIST /v，C:\Windows\System32\Tasks
③ 服务services.msc（看自启动+异常二进制路径），事件日志 7045
④ WMI 事件订阅Get-WmiObject -Namespace root\subscription -Class __EventConsumer
⑤ 启动文件夹shell:startup、shell:common startup 两个目录

补充：映像劫持（IFEO，Image File Execution Options 设置 debugger）、注册表 Userinit 项。

3. 账户排查【背】

net user                             # 本地账户列表
net localgroup administrators        # 谁进了管理员组
lusrmgr.msc                          # 图形化看账户（重点看隐藏账户）
  • 隐藏账户：以 $ 结尾的账户（如 hack$），net user 看不到，要在注册表 HKLM\SAM\SAM\Domains\Account\Users\Names 里翻（需先提权）。
  • 克隆账户：管理员组里的陌生账户，或注册表 F 值与 administrator 相同的账户。

4. 事件日志关键 ID【背，最高频考点】

事件 ID含义
4624登录成功
4625登录失败（爆破痕迹）
4720创建用户
4726删除用户
4728/4732用户被加入组（4732=加入管理员组）
7045安装新服务（Webshell 落地常用）
4698创建计划任务
1102日志被清空（高危！攻击者抹痕迹）
4688进程创建

排查入口：eventvwr.msc → Windows 日志 → 安全/系统。

三、Linux 排查背诵清单

1. 进程与网络【背】

ps -ef                              # 进程（看路径异常、隐藏进程）
top                                 # CPU 占用异常
ls -l /proc/<PID>/exe                # 进程真实路径（命令行可被伪造，这个最准）
lsof -p <PID>                        # 进程打开的文件
netstat -antup                       # 网络连接（-a全部 -n数字 -t tcp -u udp -p进程）
  • 病毒进程被删了文件还活着：ls -l /proc/<PID>/exe 显示 (deleted)。

2. 持久化排查：五个位置【背】

位置查法
① 计划任务crontab -l、/etc/crontab、/etc/cron.d/ /etc/cron.hourly/ 等
② systemdsystemctl list-units --type=service --state=running，看异常服务文件（/etc/systemd/system/）
③ rc.local/etc/rc.local、/etc/rc.d/，逐行看启动脚本
④ SSH 后门~/.ssh/authorized_keys（看陌生公钥）、/etc/ssh/sshd_config 被改端口/允许密码
⑤ 账户cat /etc/passwd 找 UID=0 的非 root 账户；awk -F: '$3==0 {print $1}' /etc/passwd

3. 日志位置【背】

/var/log/secure        # 登录认证（Debian 系为 /var/log/auth.log）
/var/log/messages       # 系统综合
~/.bash_history         # 命令历史（看下载、编译、提权动作）
last                    # 登录记录（wtmp）
lastb                   # 失败登录（btmp，爆破痕迹）

4. Webshell 排查思路【懂】

  • 特征查找：find /var/www -name "*.php" -mtime -3（近3天改动的php）
  • 内容查找：grep -r "eval(\|assert(\|system(" /var/www --include="*.php"（危险函数）
  • 对比法：与备份/源码包 diff，多出来的文件即 Webshell。

四、高频考点提示

  1. 六步法顺序不能乱，先隔离、先取证（别先杀进程）。
  2. Windows 持久化五位置 + Linux 持久化五位置，各五个，成对背。
  3. 事件 ID：4624/4625/4720/7045/4698/1102 六个必背。
  4. Linux 隐藏后门两大件：authorized_keys 陌生公钥、UID=0 账户。
  5. 关机是错的——断网不关机，内存证据会丢。
