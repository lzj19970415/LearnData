07 安全加固入门（怎么把漏洞堵上）

上一章你懂了漏洞"怎么被攻"。这一章讲反过来——怎么把它堵上。这也是你日常运维最能直接用的技能。

一、先说人话：加固是什么

  • 漏洞利用 = 把门撬开（攻击者角度）。
  • 安全加固 = 把门锁好、还加好几道锁（你作为防守方的角度）。

这两件事对着干。你学会了"攻击者怎么撬锁"，就自然知道"该在哪里加锁"——先懂破，才懂防。这也是为什么前面先学 03 的漏洞。

二、三处要加固的地方（运维最常面对）

1. 系统（Windows / Linux 本身）

人话：先保证"门面"没问题，账户和端口别乱。

具体做法（选主要的记）：

① 口令：改掉默认口令、强口令（长度≥8、大小写数字符号混、别用弱口令）
② 账户：不用 root/Administrator 干日常活、禁 root 直接 SSH 登录
③ 服务：只开要用的端口，不用的服务停掉
④ 补丁：高危漏洞（尤其能远程执行的）优先打补丁
⑤ 审计：开着登录日志、操作日志

2. 中间件（Nginx / Apache / Tomcat 这类）

人话，重点：别暴露版本信息、别让"上传目录"能执行脚本、别给不必要的目录权限。

 ① 隐藏版本号：Server Tokens off（别让人一眼看到你是啥版本）
 ② 禁目录遍历：Options -Indexes（别让人看到整个目录的文件列表）
 ③ 上传目录禁执行：Nginx 配 location 把上传目录的 php/jsp 全 deny（最实用的一条）
 ④ Web 进程用低权限账户跑，别用 root
 ⑤ 组件升级到安全版本（Fastjson / Shiro / Log4j 这些要版本达标）

3. 数据库（MySQL 这类）

人话，数据库是最值钱的地方，尤其要管住"谁、能不能远程、能不能删库"。

 ① 应用别用 root，一库一账号、给最小权限
 ② 禁 root 远程登录（只本机访问）
 ③ 关掉不需要的测试库/匿名账户
 ④ 日志要开（出错日志必开；排查时再开 general_log）
 ⑤ 注入根治：参数化查询（回到 03 讲的）

三、加固之后的"复测"（最关键，别省）

人话：加固完，用攻击者的方法再打一次，打不进去了才叫成功。

修复 → 用原来的攻击方式复测 → 确认失败/被拦 → 截图留证据 → 上监控/告警

为什么强调复测？因为很多人改了配置就以为好了，结果根本没改对。只修不复测 = 没修。 实战和考核都认这条。

四、把 03 和 07 合起来看（记忆板）

漏洞怎么攻（03）怎么防（07）
SQL 注入拼 SQL、OR 1=1 拖库参数化查询 + 最小权限
文件上传传脚本绕后缀白名单 + 改名 + 上传目录禁执行
中间件 RCE组件漏洞 / jndi升级版本 + 关端口
后门/挖矿挂持久化、开外连查持久化 + 封外连（01 篇）

规律：能用一个核心动作堵住多半（参数化查、禁执行、升级组件），再加"最小权限"做兜底。

小结（人话速记）

  1. 加固 = 堵漏洞，先懂攻才懂防。
  2. 三处加固：系统（口令/端口/补丁）、中间件（隐藏版本/禁遍历/上传禁执行）、数据库（最小权限/禁远程/参数化）。
  3. 最小权限是万能兜底：只给够用的。
  4. 复测才算加固完：用原攻击复测，堵死+截图。

动手建议：把你负责的某台 Web 服务器（测试环境）按"三处"过一遍，重点做"上传目录禁执行 + 改个强口令"，再用原方式打一次看是不是堵住了。
