# 05 规范化与模式分解（下午案例必考，上午也考）

> 师兄先说人话：**规范化就是把一张"什么都塞"的大表，拆成几张"各管一摊"的小表**。为什么要拆？大表里同一个信息存十几遍，改一处就得改十几处——忘改一处，数据就"精神分裂"了。规范化就是杜绝"一个地方改了、另一个地方忘改"的系统方法。下午案例题几乎年年考"判断范式 + 判无损分解"，上午选择题也稳定考函数依赖——这一章的分是设计好摆在那的，拿下。

## 一、函数依赖：一切从"谁决定谁"开始

**正式定义**：设 R(U) 是属性集 U 上的关系模式，X、Y 是 U 的子集。若对于 R 的任意一个可能的关系 r，X 的每一个值都有唯一的 Y 值与之对应（X 定了，Y 就定了），则称 **X 函数决定 Y**，或 **Y 函数依赖于 X**，记作 **X→Y**。

人话：知道学号，就能知道姓名——"学号决定姓名"，记作 Sno→Sname。

### 三种依赖，各配一个例子（背例子比背定义快）

| 类型 | 定义（人话） | 例子 |
|---|---|---|
| 完全函数依赖 | X→Y，且 X 砍掉任何一部分都决定不了 Y | （Sno, Cno）→Grade：光有学号定不了成绩，光有课程号也不行，**必须整键一起上** |
| 部分函数依赖 | X→Y，但 X 的某个真子集也能决定 Y | （Sno, Cno）→Sname 是**部分**：真子集 Sno→Sname 一个就够了 |
| 传递函数依赖 | X→Y，Y→Z，且 Y 决定不了 X，则 X 传递决定 Z | Sno→Sdept（学号定系），Sdept→Dean（系定系主任），则 Sno→Dean 是**传递** |

❗【易错】传递依赖成立有个前提：**Y 不能反过来决定 X**。若 X→Y 且 Y→X（相互决定），就不算传递。

### 平凡 / 非平凡依赖

| 类型 | 定义 | 例子 |
|---|---|---|
| 平凡依赖 | Y ⊆ X 时，X→Y 永远成立，没有信息量 | （Sno, Cno）→Sno |
| 非平凡依赖 | Y ⊄ X | Sno→Sname |

考试里讨论的依赖都是非平凡的——平凡依赖是"废话依赖"。

## 二、Armstrong 公理与闭包

三条公理（推理的"游戏规则"）：

| 公理 | 内容 | 人话 |
|---|---|---|
| 自反律 | 若 Y⊆X，则 X→Y | 整体能决定它自己的任何部分，天经地义 |
| 增广律 | 若 X→Y，Z 是任意属性集，则 XZ→YZ | 两边同时加同一个东西，依赖不破 |
| 传递律 | 若 X→Y，Y→Z，则 X→Z | 传话筒，一环扣一环 |

三条常用推论（考试也认）：

- **合并规则**：X→Y 且 X→Z ⇒ X→YZ
- **分解规则**：X→YZ ⇒ X→Y 且 X→Z
- **伪传递规则**：X→Y 且 WY→Z ⇒ XW→Z

### 闭包 X⁺：求候选键的核心技能

**定义**：属性集 X 在函数依赖集 F 下能"够得着"的所有属性的集合，记作 X⁺。

**求法（套圈游戏）**：从 X 出发，反复扫 F——凡是**左部已经全部在手**的依赖，就把它的右部吃进来；直到不再涨为止。

**逐步展开演示**：R(Sno, Sdept, Dean, Cno, Grade)，F = {Sno→Sdept, Sdept→Dean, (Sno,Cno)→Grade}，求 (Sno,Cno)⁺：

| 轮次 | 动作 | 当前 X⁺ |
|---|---|---|
| 起点 | 放入 X 本身 | {Sno, Cno} |
| 第 1 轮 | Sno→Sdept：左部 Sno 在手 → 吃入 Sdept | {Sno, Cno, Sdept} |
| 第 1 轮 | (Sno,Cno)→Grade：左部全在手 → 吃入 Grade | {Sno, Cno, Sdept, Grade} |
| 第 2 轮 | Sdept→Dean：Sdept 在手 → 吃入 Dean | {Sno, Cno, Sdept, Grade, Dean} |
| 第 3 轮 | 扫一遍没有新依赖可用 → 停 | = U（全部属性） |

**X⁺ = U ⇒ X 是超键；若 X 去掉任何属性后闭包都不满 U，X 就是候选键。**

顺手验证：Sno⁺ = {Sno, Sdept, Dean} ≠ U，所以 Sno 单独当不了候选键。

## 三、主属性与非主属性

| 概念 | 定义 |
|---|---|
| 主属性 | **包含在任何一个候选键里**的属性 |
| 非主属性 | 不包含在任何候选键里的属性 |

上例中候选键是 (Sno, Cno)，则 Sno、Cno 是主属性；Sdept、Dean、Grade 是非主属性。

❗【易错】主属性看的是"候选键"，不是"主键"。一张表可能有多个候选键，落在**任何一个**里都算主属性。

## 四、⚠️【必考】范式逐级讲

范式 = 规范化的"等级证书"，一级比一级严。**记住每级的"人话判断法"+典型反例**——考场上现推定义来不及，全靠条件反射。

### 1NF：属性不可再分

- **定义**：关系中每个属性都是不可再分的原子值。
- **人话判断法**：一格只放一个值。一格里塞"高数85，英语92"或"电话1、电话2"，就是没到 1NF。
- **典型反例**：学生表里"成绩"一格里塞两门课的成绩。

1NF 是关系数据库的底线，不满足的连"表"都算不上。只满足 1NF 的大表有四大罪状：**大量冗余、插入异常、删除异常、更新异常**。

### 2NF：消除非主属性对候选键的**部分**函数依赖

- **定义**：在 1NF 基础上，每个非主属性都**完全**函数依赖于候选键。
- **人话判断法**：非主属性不能"只看半个键就定"。
- **典型反例**：SC(Sno, Cno, Sname, Sdept, Grade)，候选键 (Sno, Cno)——Sname、Sdept 只由 Sno 就能决定 → 部分依赖 → **不满足 2NF**。
- **后果**：同一学生的姓名随选课门数重复 N 遍（冗余）；新生没选课时插不进表（插入异常）；学生只剩一门课时删课程连姓名一起没了（删除异常）。

### 3NF：消除非主属性对候选键的**传递**函数依赖

- **定义**：在 2NF 基础上，消除非主属性对候选键的传递函数依赖。
- **人话判断法**：非主属性必须**直接**依赖候选键，不能"隔山打牛"。
- **等价判断（好用）**：不存在这样的依赖 X→Y——X 不含候选键（不是超键），而 Y 是非主属性。
- **典型反例**：SD(Sno, Sdept, Dean)，候选键 Sno：Sno→Sdept→Dean 传递 → **不满足 3NF**（但它属于 2NF，因为没有部分依赖）。

### BCNF：所有依赖的决定因素（左部）都必须是候选键

- **定义**：每个非平凡函数依赖的**左部（决定因素）都必须包含候选键**。
- **人话判断法**：谁想"决定"别人，谁自己就得是键（或至少含着键）。
- **与 3NF 的差别**：3NF 网开一面——右部若是**主属性**可以放过；BCNF 谁的面子都不给。
- **典型反例**：Teach(Student, Course, Teacher)，规定每名教师只教一门课 → F = {Teacher→Course, (Student,Course)→Teacher}。Teacher 不是候选键却决定 Course → 违反 BCNF；但右部 Course 是主属性，3NF 放行——这是**满足 3NF 但不满足 BCNF** 的经典例子。

### 包含关系（必背口诀）

**BCNF ⊆ 3NF ⊆ 2NF ⊆ 1NF**

人话：证书等级越高（越靠左），规范越狠、冗余越少、但拆出来的表越多。3NF 与 BCNF 的差别只出在**主属性**身上。

## 五、⚠️【案例必考】判断范式的标准套路（四步流程）

下午案例题模板，照这个流程作答，一步都不跳：

**第①步：求候选键**

- 找出**从未出现在任何依赖右部**的属性——它们必须进候选键；
- 对这些属性逐个/组合求闭包：**闭包 = U 的组合就是候选键**。

**第②步：定主属性**

- 候选键中出现过的属性 → 主属性；其余 → 非主属性。

**第③步：逐条检查依赖**

| 检查项 | 若中招 | 说明 |
|---|---|---|
| 有没有一格塞多值？ | 连 1NF 都不满足 | 少见，先排雷 |
| 非主属性依赖候选键的**真子集**（部分依赖） | 不满足 2NF | 卡关等级 |
| 非主属性经中间人依赖候选键（传递依赖） | 不满足 3NF | 卡关等级 |
| 存在**左部不含候选键**的非平凡依赖 | 不满足 BCNF | 卡关等级 |

**第④步：下结论**——从 1NF 往上逐级闯关，卡在哪一级，**最高范式就是它的前一级**。

### 完整示范（照这个格式写答案）

R(Sno, Sname, Sdept, Dean, Cno, Grade)，F = {Sno→Sname, Sno→Sdept, Sdept→Dean, (Sno,Cno)→Grade}。

| 步骤 | 结论 |
|---|---|
| ①候选键 | Sno、Cno 均不出现在右部；(Sno,Cno)⁺ = U（见第二章演示），Sno⁺ ≠ U → 唯一候选键 **(Sno, Cno)** |
| ②主属性 | Sno、Cno；非主属性：Sname、Sdept、Dean、Grade |
| ③检查 | Sname、Sdept 只依赖 {Sno}（候选键的真子集）→ **部分函数依赖** → 卡在 2NF |
| ④结论 | **R 最高属于 1NF**（不满足 2NF） |

❗【易错】"最高属于第几范式"答的是**闯过了几关**，不是"缺什么"。闯过 1NF、卡在 2NF ⇒ 答 1NF。

## 六、模式分解的两大衡量标准

人话：把大表拆成小表拆得好不好，就量两把尺子。

| 尺子 | 正式定义 | 人话 |
|---|---|---|
| **无损连接性** | 分解后的各模式自然连接 = 原关系，不多一行、不丢一行 | 拆完还能**原样拼回去** |
| **函数依赖保持性** | 原函数依赖集 F 中每条依赖的左右部都落在同一个分解模式中 | 依赖关系别**拆丢**了 |

⚠️无损连接是底线（拼不回去 = 丢数据 = 重大事故）；保依赖是加分项。

**重要结论（选择题常考）**：**BCNF 分解只能保证无损，可能丢依赖；3NF 分解能做到既无损又保持依赖。**

## 七、⚠️【案例高频】无损连接判定：表格法（Chase）

考法：给 R、F、ρ（分解方案），问是否无损连接。照下面的步骤画表打勾。

**第①步：构造初始表**

- 每个分解出的模式占一行，全属性 U 中每个属性占一列；
- 该模式**含有**的属性 → 填 `aⱼ`（j 列的"正牌"标记）；**不含**的属性 → 填 `bᵢⱼ`（i 行 j 列的"占位"标记）。

**第②步：逐条用 F 中的依赖"打勾"**

- 对每条 X→Y：找出在 X 列上取值**相同**的行，把这些行的 Y 列**统一成相同的值**（有 `a` 优先统一成 `a`）。

**第③步：反复扫描**，直到表不再变化。

**第④步：判断**

- 出现**一行全是 `a`**（a₁, a₂, …, aₙ）→ **无损连接**；
- 始终没有全 `a` 行 → **有损**。

### 完整演示（照抄格式）

R(A, B, C)，F = {A→B, B→C}，ρ = {R1(A,B), R2(B,C)}。

**初始表：**

| 模式 | A | B | C |
|---|---|---|---|
| R1(A,B) | a1 | a2 | b13 |
| R2(B,C) | b21 | a2 | a3 |

**第一轮扫 F：**

- A→B：A 列上 a1 ≠ b21，没有相同的行 → 跳过；
- B→C：B 列两行都是 a2（相同！）→ 把 C 列统一：b13 改成 a3。

| 模式 | A | B | C |
|---|---|---|---|
| R1(A,B) | a1 | a2 | **a3** |
| R2(B,C) | b21 | a2 | a3 |

R1 行全 `a`（a1, a2, a3）→ **无损连接** ✅

### 反例对照（看清"有损"长什么样）

同 R 同 F，换成 ρ' = {R1(A,C), R2(B,C)}：

| 模式 | A | B | C |
|---|---|---|---|
| R1(A,C) | a1 | b12 | a3 |
| R2(B,C) | b21 | a2 | a3 |

- A→B：A 列 a1 ≠ b21 → 跳过；
- B→C：B 列 b12 ≠ a2 → 跳过。

表不再变化，**没有全 `a` 行 → 有损** ❌。人话：A→B 这条依赖在 ρ' 里断了线（A 和 B 分居两表且对不上号），拼回去会多出不该有的行。

## 八、3NF 分解：合成法（案例题手算流程）

**口诀：先求最小依赖集，一条依赖建一表，最后把键补进去。**

**第①步：求最小函数依赖集 Fm**

1. **拆右部**：X→YZ 拆成 X→Y、X→Z（右部只留单个属性）；
2. **去冗余依赖**：逐条试删 X→Y——用剩余依赖求 X⁺，若仍能推出 Y，说明这条多余，删；
3. **左部极小化**：X→Y 的左部若有多余属性（去掉后仍能决定 Y），去掉。

**第②步：建模式**——Fm 中**左部相同**的依赖合并成一组，每组建一个模式（左部属性 + 各右部属性）。

**第③步：查键**——候选键若已含在某个模式里，齐活；**没含**就单独为候选键再建一个模式。

**第④步（可选）：去冗余**——若某模式的属性集是另一模式的子集，把它去掉。

### 完整示范

R(Sno, Sname, Sdept, Dean, Cno, Grade)，F = {Sno→Sname, Sno→Sdept, Sdept→Dean, (Sno,Cno)→Grade}。

| 步骤 | 结果 |
|---|---|
| ①求 Fm | F 已最小：Sno→Sname；Sno→Sdept；Sdept→Dean；(Sno,Cno)→Grade |
| ②分组建模式 | 左部同为 Sno 的合并 → R1(Sno, Sname, Sdept)；Sdept→Dean → R2(Sdept, Dean)；(Sno,Cno)→Grade → R3(Sno, Cno, Grade) |
| ③查键 | 候选键 (Sno, Cno) ⊆ R3 ✅ 不用补 |
| ④结论 | ρ = {R1, R2, R3}，每个模式都达到 3NF，且无损连接、保持函数依赖 |

顺带一提：R1 中 Sno 是键、依赖左部全是 Sno → R1 其实已达 BCNF；R2、R3 同理。合成法保证"至少 3NF"。

## 九、反规范化：故意"往回走"

规范化的代价：**拆得越碎，查询要连接的表越多，而连接是最贵的操作**。以查询为主的系统（报表、数据仓库）宁可留点冗余，也要把连接省掉——这就是反规范化。

| 常用手段 | 说明 | 例子 |
|---|---|---|
| 增加冗余列 | 把常一起查的另一表的列复制过来 | 订单表里冗余存客户姓名，免连客户表 |
| 增加派生列 | 把算出来的结果直接存下来 | 直接存"金额"，不每次 单价×数量 现算 |
| 合并表（重新组表） | 把高频一起用的表拼回一张 | 1:1 或高频联查的表合并 |
| 分区 | 把大表按规则拆成多块存储 | 按年份/地区分区，查询只扫相关分区 |

**适用场景**：读多写少、以统计查询为主的决策分析系统（OLAP / 数据仓库）。
**不适用**：写多、一致性要求极高的交易系统（OLTP）——冗余列多一处，数据不一致的风险就多一分。

❗【易错】反规范化 ≠ 不规范化。它是"先规范化到 3NF，再**有选择地**加冗余"，不是躺回大表。

## 考前速记卡

- 三种依赖：整键才能定 = 完全；半个键能定 = 部分；隔人传话 = 传递
- 闭包求法：左部全在手 → 吃右部，循环到不涨；**闭包 = U ⇒ 候选键**
- 主属性 = 出现在任何候选键里的属性
- 1NF 一格一值；2NF 杀部分依赖；3NF 杀传递依赖；BCNF 要求左部（含）候选键
- 包含口诀：**BCNF ⊆ 3NF ⊆ 2NF ⊆ 1NF**
- 判断范式四步：①求候选键 ②定主属性 ③查依赖 ④下结论；"最高属于" = 闯过的关数
- 两把尺子：无损连接（拼得回去）+ 依赖保持（拆不丢依赖）
- Chase 判无损：初始表 → 依赖打勾 → **一行全 a = 无损**
- 3NF 合成法：最小依赖集 → 一条依赖一张表 → 键补上
- BCNF 分解保无损不保依赖；3NF 分解两者都保
- 反规范化：读多写少才用；手段 = 冗余列 / 派生列 / 合并表 / 分区

A. 完全函数依赖　　B. 部分函数依赖　　C. 传递函数依赖　　D. 平凡函数依赖

**2.** 已知 F = {A→B, B→C, C→D}，则 A 的闭包 A⁺ =（　）
A. {A, B}　　B. {A, B, C}　　C. {A, B, C, D}　　D. {A, C, D}

**3.** 关于范式，下列说法**正确**的是（　）
A. 满足 3NF 的模式必然满足 BCNF
B. 满足 BCNF 的模式必然满足 3NF
C. BCNF 允许非主属性传递依赖于候选键
D. 2NF 只需消除非主属性对候选键的传递依赖

**4.** R(A, B, C)，F = {A→B}，分解 ρ = {R1(A,B), R2(A,C)}。用表格法（Chase）判定，该分解（　）
A. 一定无损连接　　B. 一定有损连接　　C. 是否无损取决于数据量　　D. 无法判定

**5.** 关系模式 R(Sno, Sname, Sdept, Dean, Cno, Grade)，函数依赖集 F = {Sno→Sname, Sno→Sdept, Sdept→Dean, (Sno,Cno)→Grade}。判断 R 最高属于第几范式，并说明理由。

---

**答案与解析**
