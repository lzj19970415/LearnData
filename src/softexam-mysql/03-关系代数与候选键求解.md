# 03 关系代数与候选键求解（选择题和案例题的双料考点）

## 一、人话开场：一套数学符号 + 一套找"身份证"的流程

- **关系代数** = 用数学符号描述"从表里怎么取数据"。比如"找出计算机系、年龄大于 18 的学生的姓名和学号"这句话，翻译成符号就是先 σ（选行）再 π（取列），SQL 就是它的"口语版"。
- **候选键** = 能**唯一确定一行**的那一列或几列组合。学号能定位唯一一个学生，姓名不一定（重名），"学号"就是候选键。

这两块在考试里的分工：**关系代数主攻上午选择题**（给公式认功能、给需求选运算）；**候选键求解上午下午都考**，而且是下午规范化大题的**第一问**——候选键求错，后面范式判断全盘皆输。所以本篇属于"一鱼两吃"，必须吃透。

## 二、关系术语表（先把黑话说成人话）

| 术语 | 正式定义 | 人话 |
| --- | --- | --- |
| 关系（Relation） | 二维表 | 一张表 |
| 目/度（Degree） | 关系中属性的个数 | 表有几列 |
| 元组（Tuple） | 表中的一行 | 一条记录 |
| 属性（Attribute） | 表中的一列 | 一个字段 |
| 域（Domain） | 属性的取值范围 | 这个字段允许填什么 |
| 候选键（Candidate Key） | 能唯一标识元组、且不含多余属性的**最小**属性集 | 行的"身份证"，可能有多个 |
| 主键（Primary Key） | 从候选键中选定的一个 | 官方指定那张身份证 |
| 外键（Foreign Key） | 本关系中引用其他关系主键的属性 | 引用的别人的身份证 |
| 主属性 | 出现在任一候选键中的属性 | 当过候选键的列 |
| 非主属性 | 不出现在任何候选键中的属性 | 没当过候选键的列 |
| 全码（ALL-KEY） | 整个关系模式的所有属性合起来才是候选键 | 每一列都得凑齐才能认出这行 |

❗【易错】"候选键"强调**最小性**——能唯一标识但抽掉任何一列就不行的属性组合才算。如果（学号,姓名）能唯一标识，但学号自己就能标识，那（学号,姓名）**不是**候选键，学号才是。命题人常拿一个"超集"来冒充候选键。

## 三、五种基本运算（背熟符号 + 人话 + SQL 对应）

| 运算 | 符号 | 人话 | SQL 对应 |
| --- | --- | --- | --- |
| 并 | R ∪ S | 在 R **或**在 S 的行 | `UNION` |
| 差 | R − S | 在 R 但**不在** S 的行 | `NOT IN` / `EXCEPT` |
| 笛卡尔积 | R × S | 两表行**两两全部拼接** | 多表 `FROM` 不加连接条件 |
| 选择 | σ_F(R) | 按条件**横向挑行** | `WHERE F` |
| 投影 | π_A(R) | 按属性名**纵向挑列** | `SELECT A` |

口诀：**"并差积选投"——行行拼接是积，横着挑行是选择，竖着挑列是投影。**

❗【易错】选择 vs 投影是高频送命题：
- **选择 σ = WHERE（挑行）**，英文 Select 但干的是"筛选"；
- **投影 π = SELECT 列（挑列）**。
- 记法：σ 长得像"筛"的 S（Selection），π（Projection）顶根天线往下**投影子**。

另注意：并、差、交要求两关系**目数相同且对应域相容**（同型表才能做）；笛卡尔积没这个要求。

## 四、扩展运算：交、连接、除

### 4.1 交 ∩

| 运算 | 符号 | 人话 | SQL 对应 |
| --- | --- | --- | --- |
| 交 | R ∩ S | 既在 R 又在 S 的行 | `INTERSECT` |

可以用基本运算导出：**R ∩ S = R − (R − S)**——把"R 比 S 多出来的"从 R 里减掉，剩下的就是公共部分。

### 4.2 连接家族（θ连接 / 等值连接 / 自然连接）

| 类型 | 定义 | 人话 | 要点 |
| --- | --- | --- | --- |
| θ连接 | 从 R×S 中选取 θ 条件满足的元组（θ 是比较运算符） | 先积再筛 | 通用形式 |
| 等值连接 | θ 取"="的连接 | 两列值相等的拼起来 | **保留重复列** |
| 自然连接 | 在**同名属性**上等值连接，并**去掉重复列** | 最常用的"按公共字段合表" | ⚠️ 自动去重复列 |

❗【易错】等值连接与自然连接的区别只有一条，但年年考：**自然连接会去掉重复列，等值连接不会**。题目问"哪种连接的结果不出现重复属性名"——答自然连接。

### 4.3 ⚠️【必考】除法 ÷ —— "全部 / 所有"题的专属武器

**人话定义**：R ÷ S = 在 R 中，**与 S 里每一行都能配上对**的那些属性值。专治"选修了**全部**课程的学生""参加了**所有**项目的员工"这类"全部/所有"语义的需求。

**判定口诀**：题干出现"全部、所有、每一个、至少…包含所有"，基本就是除法。若写 SQL，除法 = "不存在一门课程，该生没有选"（双 NOT EXISTS 套路，11 篇细讲）。

**小例子演示**：

选课表 SC：

| 学号 | 课程号 |
| --- | --- |
| S1 | C1 |
| S1 | C2 |
| S1 | C3 |
| S2 | C1 |
| S2 | C2 |
| S3 | C1 |

全部课程表 Course：

| 课程号 |
| --- |
| C1 |
| C2 |
| C3 |

求 **SC ÷ Course**（选修了全部课程的学生）：

| 学号 |
| --- |
| S1 |

过程拆解：问每个学生"是不是把 C1、C2、C3 **全都**配上了对？"
- S1 配了 C1、C2、C3 全套 ✔ → 留下
- S2 只有 C1、C2，缺 C3 ✘ → 排除
- S3 只有 C1 ✘ → 排除

注意除法的方向性：**被除数（S1 留下）是因为它"覆盖了"除数里全部取值**；S 里哪怕出现一条 R 没覆盖的记录，结果集就排除。这就是"全部语义"的数学本质。

**教材版正式定义（含"象集"）**：x 在 R 中的**象集**，指 R 中 x 所对应的其余属性值的集合；R ÷ S 的结果，就是"象集**包含** S 中全部取值"的那些 x。一句话：**除法 = 象集的全覆盖筛选**。

| 步骤 | 动作 | 本例对应 |
| --- | --- | --- |
| ① | 确定除数上的属性（课程号） | Course 的课程号：C1、C2、C3 |
| ② | 对每个候选 x 求象集 | S1 的象集 = {C1,C2,C3}；S2 = {C1,C2}；S3 = {C1} |
| ③ | 象集 ⊇ 除数全部取值者入选 | 只有 S1 的象集盖住了 C1~C3 全套 |
| ④ | 输出这些 x | 结果 = {S1} |

## 五、⚠️【必考】候选键求解四步法（案例题第一问，流程可直接照抄）

给定：关系模式 R(U, F)，U 是全部属性，F 是函数依赖集。

| 步骤 | 操作 | 结论 | 依据 |
| --- | --- | --- | --- |
| ① | 找出**只出现在 F 右部**的属性 X右 | X右 **一定不在**任何候选键中 | 它只被推导，从不推导别人 |
| ② | 找出**只出现在 F 左部**的属性 X左 | X左 **一定在**候选键中 | 它不被任何人推出，缺了它凑不齐唯一标识 |
| ③ | 找出**左右都没出现**的属性 X独 | X独 **一定在**候选键中 | 没有任何函数依赖能推出它，必须亲自出场 |
| ④ | 令 X = X左 ∪ X独，求闭包 X⁺：若 X⁺ = U，则 X 就是候选键；**不够**再从"左右都出现"的属性里**逐个/组合补入**，求闭包逐一验证 | 闭包恰好 = U 的组合都是候选键 | 唯一性由闭包=U 保证；最小性由"从②③必选项出发、按从小到大补"保证 |

### 5.1 闭包 X⁺ 怎么算（结果属性集的"滚雪球"）

X⁺ 的算法：从 X 出发，反复扫描 F——只要某条依赖 A→B 的左部 A 已被当前集合**包含**，就把 B 添进来；直到扫一整圈没有任何新增为止，最终集合就是 X⁺。

人话：**手里有的牌能触发哪些连锁反应，连锁全部走完后的手牌总量就是闭包。**

### 5.2 完整演示例 1（简单：3 个属性）

**题**：R(A, B, C)，F = {AB→C, C→B}，求候选键。

- 第①步：右部属性 = {C, B}，左部属性 = {A, B, C}。
  - 只出现在右部的：**无**（C、B 也都在左部出现过）。
  - 只出现在左部的：**A**。
  - 左右都没出现：无。
- 第②步：必选属性 X = {A}。
- 第③步：求 A⁺。
  - A 出发：AB→C 需要 AB，手里只有 A，不触发；C→B 需要 C，不触发。
  - A⁺ = {A} ≠ U，不够。
- 第④步：从"左右都出现"的属性 {B, C} 里补，**按从小到大的组合顺序**验证：
  - 补 B：求 (AB)⁺ = {A, B} → 触发 AB→C → {A, B, C} = U ✔ → **AB 是候选键**。
  - 补 C：求 (AC)⁺ = {A, C} → 触发 C→B → {A, B, C} = U ✔ → **AC 是候选键**。
- **答案：候选键为 AB 和 AC，共两个**；主属性 = {A, B, C}（都当过候选键成员），非主属性无。

❗【易错】求出第一个候选键 AB 就停笔——**候选键往往不止一个**！必须把剩余候补组合逐一验证完，漏答直接丢分。

### 5.3 完整演示例 2（较复杂：4 个属性 + 一个大坑）

**题**：R(A, B, C, D)，F = {AB→C, C→A}，求候选键。

- 第①步盘点：左部 = {A, B, C}，右部 = {C, A}。
  - 只出现在右部的：**无**（C 在左部出现过、A 在右部——等下，A 出现在左部 AB→C 里，也出现在右部 C→A 里）。
  - 只出现在左部的：**B**。
  - **左右都没出现的：D**（F 里压根没有它）。
- 第②步必选属性 X = {B, D}。
- 第③步求 (BD)⁺：
  - {B, D} 出发：AB→C 需要 AB，缺 A，不触发；C→A 需要 C，不触发。
  - (BD)⁺ = {B, D} ≠ U，不够。
- 第④步从"左右都出现"的属性 {A, C} 里补，验证：
  - 补 A：求 (ABD)⁺ = {A, B, D} → 触发 AB→C → {A, B, C, D} = U ✔ → **ABD 是候选键**。
  - 补 C：求 (BCD)⁺ = {B, C, D} → 触发 C→A → {A, B, C, D} = U ✔ → **BCD 是候选键**。
  - 补 A 和 C：ABD、BCD 已各自成立，(ABCD) 虽然闭包也 = U，但它**包含了多余的 A 或 C**（ABD 去掉 D 不行，但 ABCD 去掉 A 后 BCD 仍是候选键），违反最小性 → **ABCD 不是候选键**，只是超键。
- **答案：候选键为 ABD 和 BCD，共两个**；主属性 = {A, B, C, D}。

**本例的大坑（❗【易错】）**：
1. **D 谁也推不出来**，很多考生看到函数依赖里没有 D 就把它忘了——它恰恰**必须出现在每个候选键里**（第③步结论）。
2. **(ABCD) 这种"全家桶"不能当候选键**——判定候选键要同时满足"能推出全部属性"和"最小性"，后者要求去掉任何一列就不再成立。命题人常拿 ABCD 当干扰选项。

### 5.4 一张表总结四步法口诀

| 口诀 | 对应步骤 |
| --- | --- |
| 右部出现踢出去 | ① 只在右部 → 排除 |
| 左部独苗必须带 | ② 只在左部 → 必选 |
| 没爹没娘亲自上 | ③ 依赖里没出现 → 必选 |
| 闭包不够逐个补，补到刚好全U住 | ④ 从左右都出现的属性里从小到大补，闭包=U 即候选键 |

## 七、自测 5 题（改编自历年真题风格）

**1.** 关系代数表达式 π₁,₂(σ₁<6(S)) 中，σ 和 π 分别对应 SQL 中的（　）。
A. SELECT 子句和 WHERE 子句
B. WHERE 子句和 SELECT 子句
C. GROUP BY 子句和 HAVING 子句
D. FROM 子句和 WHERE 子句

**答案：B**。σ 是选择（挑行）→ WHERE；π 是投影（挑列）→ SELECT。

**2.** 关系 R 与 S 进行自然连接时，下列说法正确的是（　）。
A. 需要指定连接条件为 R.A = S.A
B. 结果中同名属性只保留一列
C. 结果中会出现重复的同名列
D. 等价于 R × S

**答案：B**。自然连接自动在同名属性上等值连接，并去掉重复列——这是它与等值连接的区别。C 是等值连接的特征，D 是没有连接条件的全拼接。

**3.** 有关系模式 R(A, B, C, D)，函数依赖集 F = {A→B, B→C, C→D}，则 R 的候选键是（　）。
A. A
B. AB
C. ABC
D. ABCD

**答案：A**。只出现在左部的属性是 A（必选）；A⁺ = A→B→C→D = {A,B,C,D} = U ✔，故 A 单独即候选键。B、C、D 均为被 A 推出的属性，加进去反而破坏最小性，不是候选键。

**4.** 有关系模式 R(A, B, C)，函数依赖集 F = {AB→C}，则 R 的候选键与主属性分别是（　）。
A. 候选键 AB；主属性 A、B
B. 候选键 C；主属性 C
C. 候选键 ABC；主属性 A、B、C
D. 候选键 A；主属性 A

**答案：A**。按四步法：C 只出现在右部 → 一定不在候选键；A、B 只出现在左部 → 一定在候选键。(AB)⁺ = {A, B, C} = U ✔，候选键为 AB。主属性 = 出现在候选键中的属性 = A、B；C 从未出现在任何候选键中，是**非主属性**（这正是 05 篇判断 2NF/3NF 的关键输入）。C 项是典型干扰：把"全部属性"误当主属性。

**5.（计算题）** 有关系模式 R(W, X, Y, Z)，函数依赖集 F = {W→X, X→Y, Y→Z, Z→W}，求 R 的所有候选键。

**完整解答（按四步法照抄流程）**：
- 第①步：左部 = {W, X, Y}，右部 = {X, Y, Z, W}。
  - 只出现在右部的：**无**（X、Y、W 都在左部出现过）。
  - 只出现在左部：**无**（W 出现在 Z→W 的右部）。
  - **左右都没出现：无**。
- 第②③步：没有必选属性——四个属性全部"左右都出现"，只能逐一验证。
- 第④步从单属性开始验证：
  - W⁺ = W → X → Y → Z = {W,X,Y,Z} = U ✔ → **W 是候选键**
  - X⁺ = X → Y → Z → W = {X,Y,Z,W} = U ✔ → **X 是候选键**
  - Y⁺ = Y → Z → W → X = {Y,Z,W,X} = U ✔ → **Y 是候选键**
  - Z⁺ = Z → W → X → Y = {Z,W,X,Y} = U ✔ → **Z 是候选键**
  - 双属性组合（如 WX⁺）虽也 = U，但去掉任一属性仍成立 → 违反最小性，**只是超键，不是候选键**。
- **答案：候选键为 W、X、Y、Z 共 4 个**；全部属性都是主属性，R 属于"全码"倾向的极端情形——任何单属性都能转一圈推出全部，这是"循环依赖"类题目的典型形态。

**本题给你的提醒**：当所有属性"左右都出现"时，四步法退化为"从最小组合逐一验证"；遇到环状依赖（W→X→Y→Z→W），单个属性就可能独挑大梁。
