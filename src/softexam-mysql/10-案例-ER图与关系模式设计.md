# 10 案例实战一：ER图与关系模式设计（下午第一件套）

> 前置：ER 图的基础概念在 [02 数据模型与ER图](02-数据模型与ER图.md)；答题总纲和评分套路见 [09 案例答题总纲与评分套路](09-案例答题总纲与评分套路.md)。

这类题说白了就是一道**翻译题**：把一段中文业务描述，先翻译成一张图（ER 图），再翻译成几张表（关系模式）。它不考创意，只考翻译的准确——**实体别多别少、属性别放错位置、联系类型别判反、主键外键别漏标**。翻译规则是死的，规则背熟，这就是下午卷里性价比最高的大件之一。

## 一、题型与评分点速览

| 常见问法 | 阅卷老师找什么（评分点） |
| --- | --- |
| "指出系统中的实体及联系类型" | 实体个数对、每对联系的类型（1:1 / 1:n / m:n）对、判断依据说清 |
| "画出（或补全）ER图" | 矩形画实体、椭圆画属性、菱形画联系、连线上标 1/n/m、联系属性挂在菱形上 |
| "将ER图转换为关系模式" | 模式个数、m:n 拆出独立模式、外键齐全、组合主键标对 |

⚠️【必考】一张下午卷里，ER 题的三个小问几乎都是连招：**找实体 → 判联系 → 转模式**。而转出来的关系模式，常常又被拿去当下一道题"求候选键、判范式"的原材料（见 [12 案例-候选键与范式分解](12-案例-候选键与范式分解.md)）——所以这件套练不熟，等于连累两道大题。

## 二、完整实战：学生选课系统（一个场景走五步）

### 题干（模拟题干，先自己读一遍）

> 某高校拟开发**学生选课管理系统**，业务规则如下：
>
> (1) 学校下设若干个系，每个系有若干名学生，每名学生只属于一个系；系的信息包括系号、系名、电话；
> (2) 学生的信息包括学号、姓名、性别；
> (3) 每名学生可以选修多门课程，每门课程可以被多名学生选修，选修之后产生成绩并记录选课时间；
> (4) 每门课程由一名教师讲授，每名教师可以讲授多门课程；教师的信息包括教师号、姓名、职称；
> (5) 课程的信息包括课程号、课程名、学分。

### 第一步：读题找实体——名词筛选法

把题干里的**名词**全部圈出来，按"**人、物、事件**"过筛子：

| 名词 | 判定 | 一句话理由 |
| --- | --- | --- |
| 学生、教师 | 实体 √ | "人"，有自己的一套属性 |
| 课程、系 | 实体 √ | "物/组织"，有自己的一套属性 |
| **成绩、选课时间** | **不是实体** | 它们描述"某学生选了某门课"这个**行为**，离开选课行为毫无意义 |
| 学号、姓名、系名、电话、学分…… | 属性 | 描述上面实体自身特征的名词 |
| 选修、讲授 | 联系 | 描述实体之间"发生了什么"的动词 |

❗【易错】"成绩"是本题型最经典的陷阱。判断口诀：**"离开联系就活不下去的名词，是联系属性；自己能独立开户的名词，才是实体。"** 成绩依附于"某学生选某门课"而生，所以它是"选修"联系的属性。同理"选课时间"也是。

再补一刀：别把"选课"本身建成实体！在 ER 图里"选课"是学生与课程之间的**联系**（菱形），它转换之后确实会变成一张独立的表——但那是"联系模式"，不是实体。

### 第二步：属性归位——实体属性 vs 联系属性

| 属性 | 归给谁 | 判断理由 |
| --- | --- | --- |
| 学号、姓名、性别 | 学生实体 | 只跟单个学生走 |
| 系号、系名、电话 | 系实体 | 只跟单个系走 |
| 教师号、姓名、职称 | 教师实体 | 只跟单个教师走 |
| 课程号、课程名、学分 | 课程实体 | 只跟单门课程走 |
| **成绩、选课时间** | **"选修"联系** | 只有"某学生选某门课"发生时才存在 |

❗【易错】把"成绩"塞进学生实体，是阅卷现场的常客级错误。想想后果：一名学生要修几十门课，成绩塞进学生表就得预留几十个成绩字段——冗余爆炸，直接暴露你不懂"属性要跟最小归属单位走"。

### 第三步：判断联系类型——逐对问"一个X对应几个Y"

对每一对可能发生关系的实体，各问两句话：

| 联系 | 问自己 | 答案 | 类型 |
| --- | --- | --- | --- |
| 系 — 学生 | 一个系有几名学生？ / 一名学生属于几个系？ | 多名 / 一个 | **1:n** |
| 学生 — 课程 | 一名学生选几门课？ / 一门课被几名学生选？ | 多门 / 多名 | **m:n** |
| 教师 — 课程 | 一名教师讲几门课？ / 一门课由几名教师讲？ | 多门 / 一名（题干假设） | **1:n** |

判断方法就这么土：**拿"一"去问两端**。一端答"多"、另一端答"一"就是 1:n；两端都答"多"就是 m:n；两端都答"一"就是 1:1。土办法最不容易错。

补充：若题干还写"每名教师属于一个系"，那就再加一对**系 — 教师 = 1:n**，处理方法与系 — 学生完全一样。

### 第四步：画ER图——规范与画法

先记作图规范（考试画图就靠这四样）：

- **矩形** = 实体
- **椭圆** = 属性（主键属性名**下加下划线**）
- **菱形** = 联系（联系名写在菱形里）
- **无向边** 连接实体与联系，在靠近实体的一端标注基数 **1、n、m**

ER 图结构（文字版画法）：

```
┌──────┐ 1        n ┌──────┐ m        n ┌──────┐ n        1 ┌──────┐
│  系  │───<所属>────│ 学生 │───<选修>───│ 课程 │───<讲授>────│ 教师 │
└──────┘            └──────┘            └──────┘            └──────┘
```

各实体与联系的属性清单（图中每个椭圆）：

```
系   ——（系号, 系名, 电话）      系号为主键（属性名加下划线）
学生 ——（学号, 姓名, 性别）      学号为主键
课程 ——（课程号, 课程名, 学分）  课程号为主键
教师 ——（教师号, 姓名, 职称）    教师号为主键

选修（联系）—— 属性：成绩, 选课时间   ← 挂在菱形上，不挂实体
讲授（联系）—— 本题无属性
```

机考作答小贴士：若绘图工具不顺手，**用文字按"实体+属性+联系+类型"四要素逐条描述**（如"学生与课程通过'选修'联系相连，类型为 m:n，联系属性为成绩、选课时间"），评分点一样能踩全。图不会画≠分拿不到，说清楚才是硬道理。

### 第五步：按规则转换成关系模式——标主键外键

⚠️【必考】三条转换规则（也就是 09 篇口诀的展开）：

| 联系类型 | 转换规则 | 举例（本题） |
| --- | --- | --- |
| **1:1** | 转成两个独立模式，任选一端加入另一端的主键（连同联系属性）作为外键；也可直接合并成一个模式 | （本题无，若"校长—学校"即此类） |
| **1:n** | 转成两个独立模式，**n 端**加入 1 端的主键（连同联系属性）作为外键 | 系(1) — 学生(n)：学生表加"系号" |
| **m:n** | **必须拆成独立关系模式**：属性 = 两端主键 + 联系属性，**主键 = 两端主键的组合** | 学生 — 课程：单独建"选课"模式 |

转换结果（标准作答格式，主键加下划线，外键注明指向）：

```
系(系号, 系名, 电话)                    主键：系号
学生(学号, 姓名, 性别, 系号)            主键：学号；外键：系号 → 系(系号)
教师(教师号, 姓名, 职称)                主键：教师号
课程(课程号, 课程名, 学分, 教师号)       主键：课程号；外键：教师号 → 教师(教师号)
选课(学号, 课程号, 成绩, 选课时间)       组合主键：(学号, 课程号)；
                                        外键：学号 → 学生(学号)、课程号 → 课程(课程号)
```

逐条对账（考场自查就这么对）：

- **系—学生是 1:n**：外键"系号"放进了 n 端的学生模式 ✓
- **教师—课程是 1:n**：外键"教师号"放进了 n 端的课程模式 ✓
- **学生—课程是 m:n**：单独拆出"选课"模式，组合主键（学号, 课程号），联系属性"成绩、选课时间"跟着进了这张表 ✓
- 每个模式的主键都标了，每个外键都写明"指向谁" ✓

为什么 m:n 必须单独建表？一句话说透：如果不拆，学生表就得为每门课重复存一行（学号、姓名、性别、课程号、成绩……），姓名性别跟着成倍冗余，删一门课连人带没了。m:n 拆表是规范化的第一课，[05 规范化与模式分解](05-规范化与模式分解.md) 会从理论角度再讲一遍。

## 三、常见错误清单（8 条）

| # | 错误 | 后果 | 怎么防 |
| --- | --- | --- | --- |
| 1 | **漏标外键**（转换完不写"外键：X → Y"） | 白白丢分，写了就有分 | 每写完一个模式，默念"主键外键都说了吗" |
| 2 | **m:n 不拆**，硬塞进实体表 | 大面积冗余，规则分全丢 | 口诀"多对 n 单独建" |
| 3 | **1:n 方向放反**（把外键加到 1 端） | 如"学生表"外键没加，反而系表塞了学生号 | 外键永远放 n 端 |
| 4 | **属性放错实体** | 如把"学分"挂到学生上 | 属性跟"最小归属单位"走 |
| 5 | **忘记联系属性**（转换时把成绩弄丢） | 组合主键对但内容残缺 | 转换前先把联系属性记在菱形旁 |
| 6 | **主键选不对** | 如学生表用"姓名"当主键 | 主键要"唯一且不空"，编号类字段优先 |
| 7 | **把联系当实体**（建一张"选课"实体） | ER 图层面直接判错 | "某两个实体之间发生的事"是联系 |
| 8 | **把实体当属性**（把"系"画成学生的一个属性） | 当"系"有自己的属性（系名、电话）时必错 | 有自己属性清单的名词，升格为实体 |

## 四、⚠️演练题：图书借阅系统（改编自历年真题风格）

> **题干**：某市公共图书馆拟开发**图书借阅管理系统**，业务规则如下：
>
> (1) 读者凭读者证借书，读者信息包括：读者编号、姓名、联系电话；每名读者可同时借阅多本图书，每本图书可先后被多名读者借阅；每次借阅需登记借出日期和归还日期；
> (2) 图书信息包括：图书编号、书名、定价；每本图书由一家出版社出版，每家出版社可出版多本图书；
> (3) 出版社信息包括：出版社编号、社名、地址。

**问题：**

① 指出该系统中的实体，以及每对实体之间联系的类型，并说明判断依据（特别提示：请说明"借阅"应设计为实体还是联系）。

② 画出该系统的 ER 图（或用文字完整描述），要求标明实体、属性、联系及联系类型。

③ 将 ER 图转换为关系模式，指出每个关系模式的主键和外键。

先别看答案，拿张纸把三问写完再往下翻。

## 五、参考答案与评分点

### 第①问：实体与联系类型

标准作答：

- 实体共 3 个：**读者、图书、出版社**；
- "借阅"不是实体，而是**读者与图书之间的 m:n 联系**——它描述"某读者借了某本书"这一行为，借出日期、归还日期是该联系的属性；
- 联系类型与依据：
  - 读者 — 借阅 — 图书：**m:n**。依据：一名读者可借多本图书，一本图书可先后被多名读者借阅；
  - 出版社 — 出版 — 图书：**1:n**。依据：一家出版社可出版多本图书，一本图书只由一家出版社出版。

评分点对照：

| 写到就给分 | 检查自己 |
| --- | --- |
| 读者、图书、出版社三个实体齐全 | 少一个丢一份分 |
| 读者—图书判为 m:n | 判成 1:n 直接这一空没了 |
| 出版社—图书判为 1:n | 方向反了（n:1）通常也给分，但别赌 |
| 明确"借阅是联系不是实体" | 这是本题设的坑，专考有没有理解 |
| 每对联系给出一句话依据 | 光给类型不给依据，依据分丢 |

### 第②问：ER 图

标准作答（文字版画法）：

```
┌────────┐ 1        n ┌──────┐ m        n ┌──────┐
│ 出版社 │───<出版>────│ 图书 │───<借阅>───│ 读者 │
└────────┘            └──────┘            └──────┘
```

- 实体及属性：读者（读者编号、姓名、联系电话），主键读者编号；图书（图书编号、书名、定价），主键图书编号；出版社（出版社编号、社名、地址），主键出版社编号；
- 联系及属性："借阅"为读者与图书之间的 m:n 联系，联系属性为借出日期、归还日期；"出版"为出版社与图书之间的 1:n 联系，无联系属性。

评分点对照：

| 写到就给分 | 检查自己 |
| --- | --- |
| 三个实体 + 各自属性齐全 | 属性漏一个就少一档 |
| 借出日期、归还日期挂在"借阅"联系上 | 挂到读者或图书实体上=属性归位错误 |
| 连线上标了 m:n、1:n | 不标类型等于白画 |
| 主键属性加下划线（或注明） | 主键是必踩点 |

### 第③问：转换为关系模式

标准作答：

```
读者(读者编号, 姓名, 联系电话)                     主键：读者编号
出版社(出版社编号, 社名, 地址)                     主键：出版社编号
图书(图书编号, 书名, 定价, 出版社编号)               主键：图书编号；外键：出版社编号 → 出版社(出版社编号)
借阅(读者编号, 图书编号, 借出日期, 归还日期)          组合主键：(读者编号, 图书编号)；
                                                  外键：读者编号 → 读者(读者编号)、图书编号 → 图书(图书编号)
```

逐条对账：

- 出版社—图书 1:n：外键"出版社编号"并入 n 端的图书模式 ✓
- 读者—图书 m:n：拆出独立的"借阅"模式，组合主键 + 两个外键 ✓
- 全部四个模式、题干所有属性一个不落 ✓

加分思考（供理解，答题不必展开）：严格说同一读者可能先后多次借同一本书，实际系统会把借出日期并入主键，或另设"借阅流水号"。考试按题干口径作答即可——评分点认的是"组合主键 + 两个外键"。

评分点对照：

| 写到就给分 | 检查自己 |
| --- | --- |
| 四个关系模式齐全 | 少"借阅"模式 = m:n 没拆，大分 |
| 图书模式含"出版社编号"并注明是外键 | 1:n 转换落没落地全看这列 |
| 借阅模式的组合主键（读者编号, 图书编号） | 组合主键是必踩点 |
| 借阅模式的两个外键及指向 | 外键写清"指向谁"才稳 |
| 借出日期、归还日期进了借阅模式 | 联系属性没丢 |

## 六、检查三步法：交卷前最后扫一遍

1. **数联系**：题干里出现了几对联系，转换结果里就应有对应痕迹——1:n 体现为"n 端多出的那一列外键"，m:n 体现为"一张独立的联系模式"。联系一个都不能少；
2. **数主键外键**：逐个模式问三句——主键是谁？外键是谁？外键指向谁？三问有答不出的，立刻补；
3. **数属性**：拿题干给的属性清单逐个打勾，防漏；再查联系属性有没有错躺在实体里。

口诀：**"数联系、数键、数属性，三遍数完再交卷。"**

## 七、考前速记卡

- 实体 = 有自己属性清单的"人/物"；联系 = 实体之间"发生的事"；联系属性 = 离开联系就活不下去的名词（成绩、借出日期）
- 判类型土办法：逐对问"一个 X 对几个 Y"
- 转换三规则：**1:1 并一边，1:n 进 n 端，m:n 单独建（组合主键 + 两外键）**
- m:n 拆出来的表：主键=两端主键组合，联系属性全跟过来
- 外键永远放 n 端；主外键必须注明指向
- 检查三步法：数联系、数主外键、数属性
