# 01 数据库基本概念与体系结构（先把名词和三级模式搞明白）

## 一、人话开场：数据库就是一座有管理制度的仓库

想象你去快递驿站取件：

- 仓库里**堆着的快递**（数据本身）→ 这就是 **DB（数据库）**；
- 驿站的**管理制度**——登记、找件、防丢、谁有权限取谁的件 → 这就是 **DBMS（数据库管理系统）**，比如 MySQL 就是干这个的软件；
- **整个体系**——快递 + 管理制度 + 驿站 + 取件的客户 + 驿站站长 → 这就是 **DBS（数据库系统）**；
- 站长，天天管库、管权限、管坏件处理 → 这就是 **DBA（数据库管理员）**。

一句话总结：**数据=DB，仓管制度=DBMS，整个体系=DBS，站长=DBA。**

正式定义对照：

| 名词 | 正式定义 | 人话版本 | 考试出现形式 |
| --- | --- | --- | --- |
| DB（数据库） | 长期存储在计算机内、有组织、可共享的大量数据的集合 | 按规矩存放的一堆数据 | 选择题辨析 |
| DBMS（数据库管理系统） | 位于用户与操作系统之间的数据管理软件，是管理数据库的系统软件 | 管数据的"操作系统" | 选择题辨析 |
| DBS（数据库系统） | 引入数据库后的整个计算机系统，包括 DB、DBMS（及其开发工具）、应用程序、DBA 和用户 | 一整套人+软件+数据 | 选择题辨析 |
| DBA（数据库管理员） | 负责数据库的建立、使用和维护的专门人员 | 数据库的"大管家" | 职责类选择题 |

❗【易错】考试爱在名词上"偷换"：说"数据库系统就是数据库管理系统"——错！**DBS ⊃ DBMS**，数据库系统还包括硬件、软件、人员和数据本身。判断题遇到"DBMS 就是 DBS"直接打叉。

## 二、DBMS 的六大功能（背熟，选择题送分）

| 功能 | 干什么 | 人话 |
| --- | --- | --- |
| 数据定义 | 定义表、视图、索引、约束等结构 | 画仓库图纸（DDL） |
| 数据操纵 | 插入、删除、修改数据 | 往货架放/取快递（DML） |
| 数据查询 | 检索数据 | 查找快递（DQL/DML） |
| 数据库运行管理 | 并发控制、安全性检查、完整性约束、事务管理 | 门口保安 + 流程管控 |
| 数据库保护 | 数据库的备份、恢复、重做 | 快递丢了的应急预案 |
| 数据库建立和维护 + 通信 | 装载数据、转储、重组织、性能监测；与其他软件通信 | 开业上架 + 对外接口 |

口诀：**"定操查运保维通"**——定义、操纵、查询、运行管理、保护、维护（通信）。

## 三、⚠️【必考】三级模式结构与两级映像（本篇最重要考点）

### 3.1 先讲人话：一个仓库的三种"账本"

还是那个快递驿站：

- **老板看的经营报表**——老板只关心"今天进出多少件、哪个区域件最多"，这是**按用户需要裁剪出来的视图** → **外模式**；
- **店长的总账本**——全店统一的快递登记规则，每一件怎么记、记哪些字段，全店只有一套 → **模式**（也叫概念模式/逻辑模式）；
- **仓库里的实际摆法**——哪个货架、几层格子、怎么码放，物理上怎么放 → **内模式**。

于是有了那句核心口诀：**外模式管"每人看到的"，模式管"全局定义的"，内模式管"物理上存的"。**

### 3.2 正式定义与结构表

| 层级 | 名称 | 别名 | 面向对象 | 描述 | 个数 |
| --- | --- | --- | --- | --- | --- |
| 1 | 外模式 | 子模式、用户模式 | 用户/应用 | 一个或多个用户看到的局部数据视图 | 可有多个 |
| 2 | 模式 | 概念模式、逻辑模式 | 全体用户 | 数据库的全局逻辑结构，全体用户的公共数据视图 | 只有一个 |
| 3 | 内模式 | 存储模式、物理模式 | 系统/存储 | 数据物理结构和存储方式，数据在磁盘上怎么放 | 只有一个 |

记忆锚点：**外多个、内一个、中间模式唯一定全局。**

### 3.3 两级映像：题目真正的"钩子"在独立性上

| 映像 | 位于哪两层之间 | 定义 | 保证的独立性 |
| --- | --- | --- | --- |
| 外模式/模式映像 | 外模式 ↔ 模式 | 模式改变时改映像，外模式不变，应用程序不用改 | **逻辑数据独立性** |
| 模式/内模式映像 | 模式 ↔ 内模式 | 存储结构改变时改映像，模式不变 | **物理数据独立性** |

口诀：**外映逻辑、内映物理。**（外模式那层映像 → 逻辑独立性；内模式那层映像 → 物理独立性）

❗【易错】这是选择题错误率最高的一处，命题人最爱把两条线**交叉对调**来迷惑你。破解办法：记住"**就近原则**"——物理存储相关的一切（换磁盘组织方式、换文件结构、加索引改存取路径）走**内模式**那条线，保证的是**物理**独立性；而"表怎么定义、逻辑结构怎么改"（比如一张表拆成两张表，但通过视图让用户照样用）走**外模式**那条线，保证的是**逻辑**独立性。

### 3.4 对比示例题（改编自历年真题风格）

> 某公司的数据库中，把学生表 Student(Sno, Sname, Sdept) 中的 Sdept 列移出，单独建成 Department 表，Student 表只留 DeptNo 外键，并修改了相应视图的定义，使用户照旧能查到学生所在系名。与此同时，数据库管理员把数据文件从单分区迁移到了多分区，底层存储结构大变。
>
> 【问题】上述改动中，哪一步体现逻辑数据独立性？哪一步体现物理数据独立性？
>
> 【解答】
> - 表结构重组 + 视图同步修改，应用程序无需改动 → 模式变了、外模式靠**外模式/模式映像**顶住 → 体现**逻辑数据独立性**。
> - 数据文件迁移分区、存储结构大变，模式不变 → 靠**模式/内模式映像**顶住 → 体现**物理数据独立性**。
> - 一句话：**用户无感的就是独立性；"哪一层挡住了变化"，就先记那层。**

## 四、数据模型三要素与模型分类

### 4.1 数据模型三要素（必背）

| 要素 | 含义 | 人话 |
| --- | --- | --- |
| 数据结构 | 描述系统的静态特性：对象类型、内容、联系 | 长什么样 |
| 数据操作 | 描述系统的动态特性：检索、插入、删除、修改 | 能干什么 |
| 完整性约束 | 一组规则，保证数据的正确、有效、相容 | 什么算合规 |

口诀：**"结构、操作、约束"——长什么样、能干啥、啥算对。**

### 4.2 概念模型 vs 逻辑模型

| 对比项 | 概念模型 | 逻辑模型 |
| --- | --- | --- |
| 代表 | **ER模型（实体联系模型）** | 层次模型、网状模型、关系模型 |
| 面向 | 用户（人） | 机器（DBMS） |
| 与具体 DBMS 的关系 | **无关** | 相关，按 DBMS 落地 |
| 用途 | 需求分析阶段的沟通工具 | 数据库逻辑设计阶段的实现蓝本 |
| 人话 | 和甲方聊天的草图 | 给施工队看的图纸 |

❗【易错】"ER 图与具体的 DBMS 无关"——正确，这正是概念模型的意义；命题人常把它改成"ER 图与具体 DBMS 有关，所以换数据库要重画 ER 图"来坑你。

## 五、数据库系统的组成与 DBA 职责

### 5.1 DBS 组成

| 组成部分 | 内容 |
| --- | --- |
| 硬件 | 服务器、磁盘、网络设备等 |
| 软件 | DBMS、操作系统、开发工具、应用程序 |
| 数据 | 数据库中存储的数据本身 |
| 人员 | DBA、系统分析员/设计员、应用程序员、最终用户 |

### 5.2 DBA 职责

| 职责 | 说明 |
| --- | --- |
| 参与数据库设计 | 决定信息内容、结构与存储 |
| 定义安全性与完整性要求 | 授权、建约束 |
| 监控数据库使用与运行 | 性能监测、调优 |
| 备份与恢复 | 制定转储策略、组织故障恢复 |
| 数据库重组重构 | 空间整理、系统升级 |

口诀：**"设、安、监、备、组"——参与设计、定安全、盯运行、管备份、做重组。**

## 六、⚠️【必考】送分概念速览（新技术选择题每年必来）

以下都是"认脸题"——能给一句人话 + 认出代表产品就够。

### 6.1 大数据 4V

| 特征 | 含义 | 人话 |
| --- | --- | --- |
| Volume（体量大） | 数据规模巨大（TB/PB/EB 级） | 量大 |
| Variety（种类多） | 结构化、半结构化、非结构化 | 花样多 |
| Velocity（速度快） | 产生与处理速度快 | 来得快 |
| Value（价值密度低） | 单位数据价值低，需挖掘 | 沙里淘金 |

### 6.2 NoSQL 四类

| 类型 | 典型产品 | 人话 |
| --- | --- | --- |
| 键值（Key-Value） | **Redis** | 一把钥匙开一个抽屉 |
| 文档型 | **MongoDB** | 一格一坨 JSON |
| 列族 | **HBase** | 按列抱团存 |
| 图型 | **Neo4j** | 存人脉网、关系网 |

口诀：**"键值Redis、文档Mongo、列族HBase、图Neo4j。"**

### 6.3 数据仓库四特点

| 特点 | 含义 | 人话 |
| --- | --- | --- |
| 面向主题 | 围绕分析主题组织（如"销售""客户"） | 不按业务流程按话题存 |
| 数据集成 | 多源数据统一口径汇总 | 各地数据搬一起 |
| 相对稳定 | 一般不修改，只查询分析 | 进来就别动 |
| 反映历史变化 | 保存历史快照 | 专看过去 |

口诀：**"主集稳变"——面向主题、集成、稳定、历史。**

### 6.4 OLTP vs OLAP

| 对比项 | OLTP（联机事务处理） | OLAP（联机分析处理） |
| --- | --- | --- |
| 用途 | 日常业务交易 | 决策分析 |
| 数据 | 当前的、详细的 | 历史的、汇总的 |
| 操作 | 频繁增删改查、单条处理 | 多为大范围扫描、聚合 |
| 用户 | 柜员、前台业务系统 | 管理层、分析师 |
| 人话 | 收银台 | 作战会议室 |

### 6.5 星型模型与雪花模型

| 对比项 | 星型模型 | 雪花模型 |
| --- | --- | --- |
| 结构 | 一个事实表 + 周围一圈维表 | 维表再进一步规范化展开成多级 |
| 复杂度 | 简单，冗余多 | 复杂，冗余少 |
| 查询性能 | JOIN 少、查询快 | JOIN 多、查询慢些 |
| 形象 | 一颗星放射 | 雪花带杈 |

### 6.6 数据挖掘、云数据库（认脸级）

| 概念 | 人话 | 关键词 |
| --- | --- | --- |
| 数据挖掘 | 从海量数据里挖出规律（分类、聚类、关联规则） | "沙里淘金"、啤酒尿布 |
| 云数据库 | 部署在云上、按需弹性伸缩的数据库服务 | 弹性、按需付费、托管 |

## 八、自测 5 题（改编自历年真题风格）

**1.** 数据库管理系统（DBMS）是（　）。
A. 位于用户与操作系统之间的数据管理软件
B. 数据库中所有数据的集合
C. 包括硬件、软件和人员的整个系统
D. 专门负责数据录入的人员

**答案：A**。B 是 DB，C 是 DBS，D 是数据库操作员/用户。

**2.** 数据库三级模式结构中，"模式"指的是（　）。
A. 用户看到的局部数据视图
B. 数据库的全局逻辑结构
C. 数据的物理存储方式
D. 用户自定义的存储过程

**答案：B**。A 是外模式，C 是内模式；模式=全局逻辑，全库仅一个。

**3.** 当数据库的存储结构发生改变时，通过修改模式/内模式映像，使模式保持不变，从而应用程序不必修改。这保证的是（　）。
A. 逻辑数据独立性
B. 物理数据独立性
C. 参照完整性
D. 数据安全性

**答案：B**。存储结构属于内模式层面，模式/内模式映像保证物理独立性——"内映物理"。

**4.** 关于数据模型三要素，下列说法错误的是（　）。
A. 数据结构描述系统的静态特性
B. 数据操作描述系统的动态特性
C. 完整性约束是一组保证数据正确有效的规则
D. 数据模型三要素包括数据结构、数据操作和并发控制

**答案：D**。三要素是结构、操作、完整性约束；并发控制属于 DBMS 运行管理功能，不是模型三要素。

**5.** 下列技术与其类型的对应关系，错误的是（　）。
A. Redis —— 键值数据库
B. MongoDB —— 文档数据库
C. HBase —— 列族数据库
D. Neo4j —— 文档数据库

**答案：D**。Neo4j 是**图**数据库。NoSQL 四类对应关系是高频送分题，直接背口诀。
