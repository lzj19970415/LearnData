# 路由器·高级

## 1. OSPF 多区域与特殊区域

### 1.1 为什么要分区域

单区域在大规模网络中 LSA 洪泛严重、SPF 计算频繁。分区域后：**区域内路由细节（1/2 类 LSA）只在本区域洪泛**，跨区域只通告汇总信息（3 类 LSA），大幅减小 LSDB。

**核心角色**：
- **ABR（区域边界路由器）**：连接 Area 0 与非骨干区域的设备，负责区域间路由汇总。
- **ASBR（自治系统边界路由器）**：把外部路由（如静态/直连/RIP/BGP）引入 OSPF 的路由器。
- 所有非骨干区域必须与 **Area 0（骨干区域）** 相连，否则区域间路由不通（虚链路 Virtual Link 可以解决，生产环境尽量避免）。

### 1.2 多区域配置（eNSP 拓扑）

**拓扑**：R1 -- R2(ABR) -- R3，R1/R2 在 Area 0，R2/R3 在 Area 1，R3 下挂外部网络。

**R2（ABR）配置：**

```bash
[R2]ospf 1 router-id 2.2.2.2
[R2-ospf-1]area 0
[R2-ospf-1-area-0.0.0.0]network 10.0.12.0 0.0.0.255
[R2-ospf-1-area-0.0.0.0]quit
[R2-ospf-1]area 1
[R2-ospf-1-area-0.0.0.1]network 10.0.23.0 0.0.0.255
```

**R1（Area 0 内）：**

```bash
[R1]ospf 1 router-id 1.1.1.1
[R1-ospf-1]area 0
[R1-ospf-1-area-0.0.0.0]network 10.0.0.0 0.0.0.255
[R1-ospf-1-area-0.0.0.0]network 192.168.10.0 0.0.0.255
```

**R3（Area 1 内）：**

```bash
[R3]ospf 1 router-id 3.3.3.3
[R3-ospf-1]area 1
[R3-ospf-1-area-0.0.0.1]network 10.0.23.0 0.0.0.255
[R3-ospf-1-area-0.0.0.1]network 192.168.30.0 0.0.0.255
```

验证：`display ospf routing`、`display ospf abr-asbr`、`display ospf peer`。

### 1.3 特殊区域（stub / totally stub / NSSA）

| 区域类型 | 行为 | 能否引入外部路由（5/7 类 LSA） |
| --- | --- | --- |
| Stub | 不接收 5 类 LSA，生成默认路由 | 不能 |
| Totally Stub | 不接收 3/4/5 类，只留默认路由 | 不能 |
| NSSA | 可引入外部路由（7 类转 5 类） | 能 |

**① Stub（末梢区域）**：

```bash
[R3-ospf-1]area 1
[R3-ospf-1-area-0.0.0.1]stub          # R3 声明
```

R2（ABR）也要在 Area 1 下执行 `stub`，两端必须一致：

```bash
[R2-ospf-1]area 1
[R2-ospf-1-area-0.0.0.1]stub
```

**② Totally Stub**：ABR 上多一条命令，把 3 类也挡掉：

```bash
[R2-ospf-1-area-0.0.0.1]stub no-summary     # 华为写法；华三同款
```

> 华三 Comware：区域类型配置为 `area 1` + `stub` / `stub no-summary`（H3C 用 `nssa` 命令差异不大）。

**③ NSSA（区域内容许 ASBR 引入外部路由）**：

```bash
[R3-ospf-1-area-0.0.0.1]nssa
[R2-ospf-1-area-0.0.0.1]nssa
```

> 自测点：Stub 区域不能是 Area 0，且区域内不能有 ASBR；NSSA 的 7 类 LSA 在 ABR 上转成 5 类发布到 Area 0。

## 2. 路由策略与过滤

### 2.1 前缀列表 ip-prefix

精确匹配路由前缀，比 ACL 更适合用于路由过滤（只匹配 IP 前缀+掩码长度）：

```text
[R1]ip ip-prefix FILTER index 10 permit 10.1.0.0 16 greater-equal 16 less-equal 24
```

- 含义：允许 10.1.0.0/16，且掩码长度在 16~24 之间。
- `deny` 匹配中即停止；末尾隐式拒绝所有，注意放行需要最后一条 `permit 0.0.0.0 0 less-equal 32`。
- 华三 Comware：`ip ip-prefix FILTER index 10 permit 10.1.0.0 16 greater-equal 16 less-equal 24`（命令基本一致）。

### 2.2 route-policy 基础

route-policy 由节点（Node）组成，每个节点可含多个 if-match 与 apply 子句，按节点序号从低到高匹配：

```text
[R1]route-policy RT1 permit node 10
[R1-route-policy]if-match ip-prefix FILTER
[R1-route-policy]apply cost 50
```

- 节点允许/拒绝：`permit`（匹配后执行 apply 并终止）/ `deny`（匹配后直接拒绝，不再匹配后续节点）。
- 没有匹配任何节点的路由默认被拒绝，使用时注意。

### 2.3 路由引入（import）与路由过滤

**例：把静态路由引入 OSPF（R1 作为 ASBR）：**

```bash
[R1]ospf 1 router-id 1.1.1.1
[R1-ospf-1]import-route static cost 20 type 1
[R1-ospf-1]import-route rip route-policy RP-1
```

**路由过滤常用手法**：

```text
# 方式一：在 OSPF 引入时用 prefix-list 过滤
[R1]ip ip-prefix P-INTERNAL permit 10.1.0.0 16
[R1]ospf 1
[R1-ospf-1]import-route static route-policy POL-INTERNAL

# 方式二：filter-policy 在 OSPF 计算路由时过滤
[R2-ospf-1]filter-policy ip-prefix P-BLOCK import

# 方式三：路由引入时 route-policy 修改度量/标记
[R3]route-policy SET-MED permit 10
[R3-route-policy]if-match ip-prefix P-CORE
[R3-route-policy]apply cost 30
[R3-route-policy]apply tag 100
```

> 华三 Comware：`import-route static route-policy xxx`（在 BGP 视图下）、`import-route` 语法与华为基本一致；filter-policy 写法 `filter-policy ip-prefix xxx import`。

## 3. BGP 基础配置

### 3.1 概念

- **AS（自治系统）**：同一管理机构下的网络，用 AS 号标识（公有 1-64511，私有 64512-65534）。
- **EBGP**：不同 AS 之间的邻居（如与运营商）。
- **IBGP**：同一 AS 内部（全网状，或路由反射器）。

### 3.2 IBGP 配置（eNSP 实验）

**拓扑**：R1(RouterID 1.1.1.1, AS 65001) -- R2(RouterID 2.2.2.2, AS 65001)，直连地址 10.0.12.0/24。

**R1：**

```bash
[R1]bgp 65001
[R1-bgp]router-id 1.1.1.1
[R1-bgp]peer 10.0.12.2 as-number 65001
[R1-bgp]network 10.1.1.0 255.255.255.0     # 通告本地直连网段
```

**R2：**

```bash
[R2]bgp 65001
[R2-bgp]router-id 2.2.2.2
[R2-bgp]peer 10.0.12.1 as-number 65001
```

> 华三 Comware：命令基本相同（`peer 10.0.12.2 as-number 65001`、`network 10.1.1.0 24`）。

### 3.3 网络与路由通告

- BGP 的 `network` 命令**不是把接口加入 BGP**，而是通告"路由表里已存在的路由"（必须先在 OSPF/静态中精确匹配）。
- 通告方式：
  - `network 10.1.1.0 255.255.255.0`：通告精确网段。
  - `network 10.1.1.0 255.255.255.0 route-policy xxx`：通告并修改属性。
  - `import-route ospf`：把 OSPF 路由全部引入 BGP（更常用）。

### 3.4 验证与实验注意

```bash
[R1]display bgp peer            # BGP 邻居状态（Established / Connect / Active）
[R1]display bgp routing-table   # BGP 路由表
[R1]display bgp path 10.1.1.0   # 查看某条 BGP 路径属性
[R1]reset bgp all               # 重置邻居会话（排障后重新协商）
```

- **IBGP 下一跳问题**：EBGP 学来的路由通告给 IBGP 时，默认不修改 next-hop，需在 R1 上：

```bash
[R1-bgp]peer 10.0.12.2 next-hop-local     # IBGP 邻居间修改下一跳为自己
```

- eNSP 实验步骤（3 台路由器 + 1 台交换机二层）：

```
AR1 --(AS 65001)-- AR2 --(AS 65002)-- AR3
先配接口 IP 与 loopback，再配 EBGP 邻居（AR1-AR2 为 EBGP 需直连），
AR1 network 通告内网网段，AR3 上 display bgp routing-table 应看到该前缀与 AS 路径。
```

> 注意 EBGP 默认禁止 multipath；BGP 的 PrefVal/Local_Pref/AS 路径长短 等属性决定选路，实验常用 `apply local-preference 200` 验证路由策略。

## 4. VPN 技术

### 4.1 GRE 隧道

GRE（通用路由封装）把任意三层协议报文封装在 IP 隧道里穿越公网，最简单的 VPN 方式（无加密）。

**拓扑**：R1(公网 100.1.1.1) 与 R2(公网 200.1.1.1) 之间建 GRE，R1 下私网 192.168.10.0/24，R2 下私网 192.168.20.0/24。

**R1：**

```bash
[R1] interface Tunnel0/0/0
[R1-Tunnel0/0/0] tunnel-protocol gre    # 指定隧道协议为 GRE
[R1-Tunnel0/0/0] ip address 10.0.0.1 255.255.255.0   # 隧道虚拟接口 IP（私网互联）
[R1-Tunnel0/0/0] tunnel source 100.1.1.1   # 源为公网接口 IP
[R1-Tunnel0/0/0] tunnel destination 200.1.1.1
[R1-Tunnel0/0/0] quit
[R1] ip route-static 192.168.20.0 255.255.255.0 10.0.0.2   # 私网路由指向隧道口
```

**R2 对称配置**（Tunnel0/0/0: 10.0.0.2/24，源 200.1.1.1，目 100.1.1.1，静态路由指向 10.0.0.1）。

验证：

```bash
display interface Tunnel0/0/0     # 协议 Up
ping 192.168.20.2                  # 源为 192.168.10.x，跨越公网通
```

> 华三 Comware 接口名为 `interface Tunnel0`，其余命令基本一致（`tunnel-protocol gre`）。

### 4.2 IPsec VPN 原理与配置思路

- **原理**：IKE 阶段一协商安全参数并生成密钥（AH/ESP 加密/认证），阶段二建立数据面安全联盟（SA）。
- **核心组成**：IKE 提议（加密算法 DES/3DES/AES、认证 MD5/SHA、DH 组）、IPsec 安全策略（反重放窗口）、认证方式（预共享密钥 PSK）。
- 生产环境几乎都用 **IPsec over GRE**（GRE 先封装私网路由，IPsec 保护 GRE 隧道）。

**基础配置思路（两台出口路由器 IKE 模式）：**

```bash
# R1（先定义触发加密的流量：ACL 3000 = 源 192.168.10.0/24 → 目的 192.168.20.0/24）
[R1]acl 3000
[R1-acl-adv-3000]rule 5 permit ip source 192.168.10.0 0.0.0.255 destination 192.168.20.0 0.0.0.255
[R1-acl-adv-3000]quit
[R1]ipsec proposal PRO1
[R1-ipsec-proposal-PRO1]esp authentication-algorithm sha1
[R1-ipsec-proposal-PRO1]esp encryption-algorithm aes-256
[R1-ipsec-proposal-PRO1]quit
[R1]ike proposal 1
[R1-ike-proposal-1]authentication-method pre-share
[R1-ike-proposal-1]authentication-algorithm sha1
[R1-ike-proposal-1]dh group2
[R1-ike-proposal-1]quit
[R1]ike peer HUAWEI1
[R1-ike-peer-HUAWEI1]undo version 2          # 使用 IKEv1（eNSP/VRP5 默认即为 v1）
[R1-ike-peer-HUAWEI1]pre-shared-key cipher Huawei@VPN
[R1-ike-peer-HUAWEI1]remote-address 200.1.1.1
[R1-ike-peer-HUAWEI1]quit
[R1]ipsec policy POL_1 10 isakmp
[R1-ipsec-policy-isakmp-POL_1]security acl 3000
[R1-ipsec-policy-isakmp-POL_1]proposal PRO1
[R1-ipsec-policy-isakmp-POL_1]tunnel local 100.1.1.1
[R1-ipsec-policy-isakmp-POL_1]tunnel remote 200.1.1.1
[R1-ipsec-policy-isakmp-POL_1]quit
[R1]interface GigabitEthernet0/0/1
[R1-GigabitEthernet0/0/1]ipsec policy POL_1
```

> 华三 Comware 命名差异：IPsec 提议为 `ipsec transform-set`，安全框架 `ipsec policy` 下用 `security acl 3000` + `ike-profile`，隧道本地/远端同为 `tunnel local` / `tunnel remote`。原理一致：**数据进隧道=通过 ACL 定义哪些流量进加密**。

验证：

```bash
display ipsec proposal
display ike sa     # 阶段一 SA（ISAKMP SA 状态 Active）
display ipsec sa   # 阶段二 SA（计数看加解包数量）
```

### 4.3 L2TP VPN 简述

- L2TP 是二层隧道协议，典型场景：**远程拨号（LAC=客户端，LNS=服务端）**，适合远程办公/移动办公。
- 华为路由器作 LNS 核心配置：

```bash
[R]interface Virtual-Template1
[R-Virtual-Template1]ppp authentication-mode pap
[R-Virtual-Template1]quit
[R]l2tp-group 1
[R-l2tp-group-1]tunnel name LNS
[R-l2tp-group-1]allow l2tp virtual-template 1 remote lns1
```

- 与 IPsec 不同：L2TP 本身不加密，实际部署常"L2TP over IPsec"（先建立 IPsec 隧道，再跑 L2TP）。

## 5. MPLS 基础

### 5.1 标签转发原理

- 传统 IP 转发：每跳查最长前缀匹配路由表，转发慢、无法做流量工程。
- **MPLS**：入口 LER（PE）为报文打上标签（如 1000），LSR（P 设备）只查标签转发，出口弹出标签还原 IP，转发效率高且支持 VPN/流量工程。

```
报文: [IP]           → [Label 1000][IP] → [Label 2000][IP] → [IP]
       PE1 (入)          P (中转)             P (中转)          PE2 (出)
```

### 5.2 L3VPN 原理简述（运营商场景）

- 运营商 PE 设备用 **VRF（VPN 路由转发表）** 隔离不同客户路由，MP-BGP 在 PE 之间通告 VPNv4 路由（携带 RD 防止路由重叠、RT 控制收发）。
- 客户 CE（客户路由器）通过静态/OSPF/BGP 与 PE 交互，两端"看似直连"实际上穿越运营商骨干。

**命令体验（运营商 PE 侧，配置骨架）：**

```text
[R-PE]ip vpn-instance CUSTOMER_A        # 创建 VRF
[R-PE-vpn-instance-CUSTOMER_A]ipv4-family
[R-PE-vpn-instance-CUSTOMER_A-af-ipv4]route-distinguisher 65001:100   # RD
[R-PE]interface GigabitEthernet0/0/0
[R-PE-GigabitEthernet0/0/0]ip binding vpn-instance CUSTOMER_A     # 接口绑定 VRF
[R-PE]bgp 65000
[R-PE-bgp]ipv4-family vpnv4
[R-PE-bgp-af-vpnv4]peer 10.0.0.2 as-number 65000
[R-PE-bgp-af-vpnv4]peer 10.0.0.2 enable   # 建立 VPNv4 邻居
```

> 华三 Comware：VRF 创建 `ip vpn-instance CUSTOMER_A`，接口绑定 `ip binding vpn-instance`，MP-BGP 视图 `bgp 65000` + `ipv4-family vpn-instance`（命令细节略有差异）。

生产组网中，L3VPN 需要底层先跑 MPLS 域（`mpls lsr-id`、`mpls ldp`），再叠加 VPNv4。eNSP 实验可搭建 PE1-P-PE2 三台路由器体验完整流程。

## 6. 路由器排障与运维

### 6.1 基础排障命令

```bash
ping 10.0.1.1                        # 连通性
tracert 10.0.1.1                     # 路径追踪，查哪一跳不通
display ip interface brief           # 接口状态、IP 是否配置
display ip routing-table             # 路由是否存在
display arp                          # 二层映射
display logbuffer                    # 看系统日志（接口翻动/认证失败）
```

华为 ping 参数：`ping -a 源 -c 次数 -t 超时(毫秒) 目标`。华三 `tracert` 相同。

### 6.2 OSPF 邻居建立失败排查步骤

1. `display ospf peer` → 看停留在哪个状态。
2. 查接口协议状态：`display interface`、`undo shutdown`。
3. 核对区域、掩码、反掩码：`display ospf interface` 确认接口在正确区域。
4. Router-ID 冲突 → 查看两边 `display ospf brief`。
5. 认证不一致：`display ospf interface GigabitEthernet0/0/0`（是否要求认证）。
6. 确认 Hello/Dead 定时器一致（广播网默认 10s/40s，`ospf timer hello` 可改，两端必须一致）。
7. `debugging ospf packet` 抓包看报错（`undo debugging all` 关闭）。

### 6.3 NAT 不生效排查

- 步骤：① `display ip interface brief` 公网口已配置 IP 且 Up；② `display acl 2000` 计数是否增长；③ `display nat session all` 有无会话；④ `ping` 通公网；⑤ 检查应用方向（出接口 outbound）。
- 常见错误：ACL 写反、静态 NAT 绑定错误、出口没有指定 NAT、内网口路由缺失。

### 6.4 接口自环测试

```bash
[R1]ping 1.1.1.1                # ping 本机 LoopBack 地址（验证三层正常）
[R1]ping -a 10.0.0.1 10.0.0.2   # 指定源地址 ping（华三：ping -a 10.0.0.1 10.0.0.2）
```

- ping 通本接口 IP 但 ping 不通对端：查链路状态、对端配置。
- `display interface` 看 CRC 错误、输入/输出丢弃等。

## 7. 企业典型组网设计

### 7.1 出口组网：双机热备 + NAT + 防火墙

```
                        ┌──── 运营商 A ────┐
                GE0/0/0 ┤                    ├ GE0/0/0
             ┌─────── R1(主) ────────┐
             │                       │
         内网核心/汇聚 ──────── R2(备) ──────── 运营商 B
             │                       │
         └── 防火墙（安全区）── DMZ/服务器区
```

**设计要点**：
- 两台出口路由器通过 **VRRP（虚拟路由冗余协议）** 提供网关高可用，内网网关指向虚拟 IP。
- 出口路由器做 NAT（easy-ip），防火墙做安全过滤；现代企业也流行"防火墙直接出口"，但双路由 + 负载均衡仍是主流。

### 7.2 VRRP 配置示例

**需求**：内网网关 192.168.1.254 虚拟，主备 R1/R2 各自物理 IP 192.168.1.1/192.168.1.2。

**R1（主）：**

```bash
[R1]interface GigabitEthernet0/0/0
[R1-GigabitEthernet0/0/0]ip address 192.168.1.1 255.255.255.0
[R1-GigabitEthernet0/0/0]vrrp vrid 1 virtual-ip 192.168.1.254
[R1-GigabitEthernet0/0/0]vrrp vrid 1 priority 120        # 比 R2 高，R1 为 Master
[R1-GigabitEthernet0/0/0]vrrp vrid 1 preempt-mode timer delay 20
```

**R2（备份）：**

```bash
[R2]interface GigabitEthernet0/0/0
[R2-GigabitEthernet0/0/0]ip address 192.168.1.2 255.255.255.0
[R2-GigabitEthernet0/0/0]vrrp vrid 1 virtual-ip 192.168.1.254
[R2-GigabitEthernet0/0/0]vrrp vrid 1 priority 50
```

**验证：**

```bash
display vrrp verbose 0.0.0.1
# State 显示 Master / Backup
```

> 华三 Comware：`vrrp vrid 1 virtual-ip 192.168.1.254` 相同；优先级命令同为 `vrrp vrid 1 priority 120`；查看 `display vrrp`。

**链路冗余进阶**：出口两条运营商线路，可用 **NQA + 浮动静态路由**（见中级篇）或 **BGP（EBGP 双上联）** 实现选路与自动切换。

### 7.3 安全与运维建议

- 出口路由器关闭 Telnet，启用 SSH 与 AAA。
- 设备时钟同步：`ntp-service unicast-server 203.107.6.88`。
- 定期备份配置：`display current-configuration` 导出到 FTP/SCP，或 `FTP` 到网管。
- 防火墙与路由器解耦：路由器只做三层与 NAT，安全策略全部在防火墙实现（谁过滤、谁拒绝要职责清晰）。
- 上线检查清单：路由表、ACL 命中、NAT 会话、VRRP 状态、双链路 Failover 演练。
