## 一、IPsec VPN 高级

### 1.1 核心概念

IPsec（Internet Protocol Security）是在 IP 层做加密和认证的协议族，隧道两端设备（本笔记为防火墙）为流量加解密，业务主机完全无感知。

| 术语 | 含义 |
|------|------|
| **IKE** | Internet 密钥交换协议，负责协商加密参数和交换密钥（UDP 500/4500） |
| **SA** | 安全联盟，一条 SA = 一套协商好的"加密+认证+密钥+生命周期"参数 |
| **ESP** | 封装安全载荷，提供加密+完整性认证（隧道模式加密整个 IP 包） |
| **AH** | 认证头，只做完整性校验不加密（现在基本不用） |
| **IKEv1 / IKEv2** | IKE 两个版本：v2 简化协商流程、报文更少、抗 DDoS，新项目优先 |

### 1.2 IKE 协商过程（v1 主模式）

```
阶段一（IKE SA，加密协商通道本身）：
  1. 双方交换 SA 提议（认证/加密/哈希/DH 组）
  2. 交换 DH 公钥（双方各自算出相同密钥）
  3. 身份认证（预共享密钥 PSK 或证书）
阶段二（IPsec SA，为业务流量协商）：
  4. 协商 ESP 的加密/认证算法，生成数据加密密钥
```

### 1.3 站点到站点 IPsec 完整配置（华为 USG）

场景：北京总部 `202.1.1.1` ↔ 上海分支 `202.1.2.1`，打通内网 `192.168.1.0/24` 与 `192.168.2.0/24`。

```
            ┌──────────┐                    ┌──────────┐
 总部内网   │ FW-A     │   Internet   │ FW-B     │   分支内网
.168.1.0/24│ 202.1.1.1│───隧道─────│202.1.2.1│ 192.168.2.0/24
            └──────────┘                    └──────────┘
```

**总部侧（FW-A）完整配置：**

```bash
system-view
sysname HQ-FW

# 接口与路由（略，见初级篇）
interface GigabitEthernet1/0/0
 ip address 202.1.1.1 255.255.255.0
quit

# 1. 定义被保护流量（ACL：总部内网 → 分支内网）
acl number 3000
 rule 5 permit ip source 192.168.1.0 0.0.0.255 destination 192.168.2.0 0.0.0.255
quit

# 2. IKE 参数（IKE proposal + peer）
ike proposal 1
 encryption-algorithm aes-256
 dh group14
 authentication-algorithm sha1
 authentication-method pre-share
quit
ike peer 1
 pre-shared-key simple Huawei@2026      # 两端必须一致
 remote-address 202.1.2.1                # 对端公网 IP
quit

# 3. IPsec 变换集（隧道加密参数）
ipsec transform-set 1
 esp encryption-algorithm aes-256
 esp authentication-algorithm sha1
quit

# 4. IPsec 策略绑定
ipsec policy hq-policy 1 isakmp
 security acl 3000                       # 绑定被保护流量
 transform-set 1                         # 绑定变换集
 ike-peer 1                              # 绑定 IKE
quit

# 5. 绑定到公网接口
interface GigabitEthernet1/0/1
 ipsec policy hq-policy 1
quit

# 6. 放行 IKE 与 IPsec 流量（防火墙特性，必须放行）
security-policy
 rule name allow_ike_ipsec
  source-zone untrust
  destination-zone local
  service udp destination-port 500 4500  protocol udp
  action permit
 quit
 rule name allow_esp
  source-zone untrust
  destination-zone local
  service protocol 50                            # ESP
  action permit
 quit
quit

# 7. 放行两端内网互访（也可不放行，靠 IPsec 封装后处理）
security-policy
 rule name ipsec_branch
  source-zone trust
  destination-zone untrust
  source-address 192.168.1.0 24
  destination-address 192.168.2.0 24
  action permit
 quit
quit

save
```

**分支侧（FW-B）把 IP 和网段对调重复一遍**，两端 ACL 互为镜像：

```
# FW-B 关键差异
acl number 3000
 rule permit ip source 192.168.2.0 0.0.0.255 destination 192.168.1.0 0.0.0.255
ike peer 1
 remote-address 202.1.1.1
```

### 1.4 验证与排障

```bash
# 查看 IKE 协商结果（应显示正常）
[Huawei] display ike sa

# 查看 IPsec SA（应显示 up）
[Huawei] display ipsec sa

# 查看 IPsec 统计（收发报文）
[Huawei] display ipsec statistics

# 在 PC 上 ping 对端内网验证
ping 192.168.2.10
```

| 故障现象 | 原因 | 处理 |
|----------|------|------|
| `display ike sa` 为空 | ACL 没匹配流量 / 预共享密钥不一致 | 检查 ACL、两端 PSK |
| IKE 协商成功但 IPsec SA 失败 | 变换集算法不一致 | 两端对齐 `transform-set` |
| 隧道建立但 ping 不通 | 安全策略/NAT 干扰了隧道流量 | 检查是否做了 NAT（应绕过）、策略是否放行 |
| NAT 设备在后面 | 对端 NAT 之后要开 NAT-T（端口 4500） | 两端都开 NAT 穿越 |

> 华三 Comware 对应配置：`ike proposal`、`ike peer`、`ipsec transform-set`、`ipsec policy`、接口 `ipsec apply policy`；命令风格与华为高度相似，差异在细节（如 `pre-shared-key ciphertext` 输入方式不同）。

## 二、SSL VPN 简述

### 2.1 是什么

SSL VPN 基于 HTTPS（443 端口）提供远程接入：用户浏览器访问网关，**免装客户端**（或装轻量插件）即可接入内网，对移动办公、临时用户特别友好。

### 2.2 使用场景

- 移动办公：员工用笔记本/手机访问内网 OA、ERP
- 合作伙伴临时接入：只给某个网页/应用开权限
- 分支少量用户接入：不开昂贵的 IPsec 线路

### 2.3 与 IPsec 对比

| 维度 | IPsec VPN | SSL VPN |
|------|-----------|---------|
| 客户端 | 需装软件或终端自带 | 浏览器即可（免装） |
| 访问范围 | 整段内网 | 可精确到单个应用 |
| 适用终端 | 电脑为主 | 电脑+手机全终端 |
| 部署复杂度 | 较高 | 低 |
| 典型场景 | 站点到站点 | 远程接入 |

### 2.4 华为 SSL VPN（EasyConnect）配置要点

华为 USR 内置 SSL VPN 网关，启用步骤：

```bash
# 开启 SSL VPN 功能（Web 界面或命令行）
[Huawei] ssl-vpn enable

# Web 界面配置：用户/用户组、虚拟网关、资源（应用/IP 段）、策略
```

运维要点：SSL VPN 的证书、用户账号、资源策略都要在 Web 界面维护，命令行只能查看状态：

```
display ssl-vpn user     # 在线用户
display ssl-vpn session  # 会话
```

## 三、深度防御（内容检测）

### 3.1 为什么需要深度检测

策略只能挡"不符合规则的流量"，挡不住"看起来正常的恶意流量"（SQL 注入、恶意附件、钓鱼网站）。NGFW 的深度检测在**放行流量内部再扫描一遍**。

### 3.2 五大检测功能总览

| 功能 | 检测对象 | 典型动作 |
|------|----------|----------|
| IPS 入侵防御 | 攻击特征（漏洞利用、扫描、渗透） | 阻断+告警 |
| AV 防病毒 | 文件/邮件中的病毒木马 | 阻断+清除 |
| URL 过滤 | 访问的网站类别（赌博、色情、广告） | 阻断/告警 |
| 文件过滤 | 文件类型（限制 exe、压缩包） | 阻断 |
| 反垃圾邮件 | 邮件内容/附件 | 阻断/隔离 |

### 3.3 IPS 配置（华为 USR）

```bash
# 创建 IPS 配置文件
[Huawei] profile type ips name ips_default
[Huawei-ips-ips_default] ?
[Huawei-ips-ips_default] quit

# 在安全策略中调用
[Huawei] security-policy
[Huawei-policy-security] rule name in_web
[Huawei-policy-security-rule-in_web] source-zone untrust
[Huawei-policy-security-rule-in_web] destination-zone dmz
[Huawei-policy-security-rule-in_web] service tcp destination-port 80 443
[Huawei-policy-security-rule-in_web] profile ips
[Huawei-policy-security-rule-in_web] action permit
```

### 3.4 AV 防病毒

```bash
[Huawei] profile type av name av_default
[Huawei-av-av_default] quit

[Huawei-policy-security] rule name internet_protect
[Huawei-policy-security-rule-internet_protect] source-zone trust
[Huawei-policy-security-rule-internet_protect] destination-zone untrust
[Huawei-policy-security-rule-internet_protect] profile av
[Huawei-policy-security-rule-internet_protect] action permit
```

### 3.5 URL 过滤

```bash
# 定义一个 URL 过滤 profile：阻断高危类别
[Huawei] profile type url-filter name url_policy
[Huawei-url-url_policy] quit

# 策略里对 Trust → Untrust 应用 URL 过滤
[Huawei-policy-security-rule-x] profile url-filter url_policy
```

### 3.6 文件过滤

```bash
# 阻止内网下载 exe 文件
[Huawei] profile type file-block name block_exe
[Huawei-file-block] quit
[Huawei-policy-security-rule-x] profile file-block filter_exe
```

### 3.7 策略与 Profile 的组合原则（重点）

- **深度检测会显著消耗 CPU/吞吐**：只在关键策略上开启，别全开
- 检测顺序：策略 →（过 NAT）→ profile 内容检测 → 放行/阻断
- 告警与阻断的区别：profile 里 `alarm`（仅告警）vs `block`（阻断），先上线观察再升级阻断

> 华三 SecPath（Comware V7）同类功能用 `security-policy` 里 `profile` + `app-profile` 组织，命令风格类似（如 `[H3C-security-policy-1] ips-profile`、`av-profile`）。

## 四、虚拟系统（vsys）

### 4.1 什么是 vsys

**vsys（virtual system，虚拟系统）** 把一台物理防火墙逻辑分割成多台"逻辑防火墙"，每台拥有独立的接口、区域、策略、NAT、用户，互不干扰。多租户/部门隔离首选。

```
  ┌────────── 一台 USR 防火墙 ──────────┐
  │  vsys1（部门A）：GE1/0/1, 独立策略  │
  │  vsys2（部门B）：GE1/0/2, 独立策略  │
  │  管理面（admin）                    │
  └──────────────────────────────────────┘
```

### 4.2 使用场景

- 运营商多客户共用的接入防火墙
- 大企业内部按部门/楼层切分隔离
- IDC 多租户边界防护

### 4.3 基本配置命令（华为）

```bash
# 创建 vsys
[Huawei] vsys name v1
[Huawei-vsys-name-v1] resource-class resource 1          # 分配资源
[Huawei-vsys-name-v1] assign interface GigabitEthernet1/0/1   # 分配接口
[Huawei-vsys-name-v1] quit

# 进入 vsys 配置
[Huawei] switch vsys v1
[Huawei-vsys-v1] security-policy
# ...在 v1 里独立配置
```

> 华三 Comware 对应 `context`（虚拟设备）技术（`[H3C] context name c1` + `allocate interface`），原理相同。

## 五、DDoS 防护

### 5.1 常见攻击类型

| 攻击 | 原理 | 危害 |
|------|------|------|
| **SYN Flood** | 发大量 SYN 不完成三次握手，占满连接表 | 正常用户连不上服务器 |
| **UDP Flood** | 高流量 UDP 冲击带宽 | 带宽耗尽 |
| **ICMP Flood** | 海量 ping | 带宽/CPU 耗尽 |
| **DNS 反射放大** | 伪造源地址打 DNS 递归 | 带宽耗尽 |

### 5.2 华为防攻击配置

```bash
# 开启 SYN Flood 防护
[Huawei] firewall defend syn-flood enable
[Huawei] firewall defend syn-flood threshold 2000        # 每秒 2000 个 SYN 触发

# UDP 洪泛
[Huawei] firewall defend udp-flood enable
[Huawei] firewall defend udp-flood threshold 5000

# ICMP 洪泛
[Huawei] firewall defend icmp-flood enable
[Huawei] firewall defend icmp-flood threshold 1000

# 查看防护统计
[Huawei] display firewall defend statistics
```

> 华三 Comware：`[H3C] attack-defense policy 1` → `syn-flood enable`、`udp-flood enable` 等，最后接口下 `apply attack-defense-policy`。

### 5.3 连接限制（会话限制）

限制单个源 IP 最大并发连接/每秒新建连接，防单点拖垮全网络：

```bash
# 限制每个源 IP 的并发连接数（华为）
[Huawei] firewall session-limit per-session 3000
```

### 5.4 黑名单/白名单

```bash
# 黑名单：直接封掉恶意源
[Huawei] firewall blacklist ip 1.2.3.4 32
# 白名单：保证重要源不受防攻击限制
[Huawei] firewall whitelist ip 10.168.0.0 16
# 查看
[Huawei] display firewall blacklist
[Huawei] display firewall whitelist
```

| 手段 | 适用 |
|------|------|
| 白名单 | 重要客户源、监控源、VPN 对端 |
| 黑名单 | 已确认的攻击源 IP |

> 运维提醒：先告警观察再拉黑，误封整网段的代价很大；黑名单有老化时间（可选 `timeout`）。

## 六、防火墙排障与运维

### 6.1 排障总思路（五元组检查法）

流量不通时按顺序检查：

```
1. 接口与路由          → display ip routing-table
2. 区域归属            → display firewall-zone
3. 安全策略            → 查看命中规则与命中次数
4. NAT                 → display nat-policy / display nat server
5. 会话表              → display firewall session table
```

### 6.2 常用验证命令一览

```
display interface brief                    # 接口 UP/DOWN
display ip routing-table                   # 路由
display firewall-zone                      # 区域与接口
display security-policy rule all           # 策略（部分版本带命中计数）
display nat session                        # NAT 会话
display firewall session table             # 会话（关键！）
display firewall session table | include 192.168.1.10   # 过滤某个 IP
display session statistics                 # 会话统计
display firewall detect-result             # 攻击检测结果
display ike sa / display ipsec sa          # VPN
display hrp state                          # 双机状态
display logbuffer | include SEC            # 安全日志
```

### 6.3 常见故障场景与处理

| 故障 | 典型原因 | 处置 |
|------|----------|------|
| 策略放行了还是不通 | 接口区域归属错 / 会话表被老策略占 | `display firewall-zone` 验证；`reset firewall session` 清会话 |
| NAT 不生效 | nat-policy 顺序不对 / 区域不匹配 | `display nat session` 看有无转换 |
| 丢包 | 策略匹配到 deny / 连接超速触发 DDoS 防护 / MTU 分片 | 查黑名单、防护统计、会话表 |
| MTU 分片问题 | 大包 ping 不通小包通 | `ping -s 1400` 测试；调整 MTU 或开启分片重组 |
| 会话被秒清 | 老化时间太短 / 会话数超限 | 调整 `session aging-time` / session-limit |
| 双机切换后业务断 | 会话未同步 / 心跳中断 | `display hrp state` 查心跳、会话同步数 |

### 6.4 策略命中审计

排查"到底哪条规则在放行/拦截"：通过会话表反查 + `display security-policy rule all` 看规则命中统计，必要时打开调试：

```bash
[Huawei] debugging firewall packet-filter ...        # 生产环境慎用
[Huawei] undo debugging all
```

生产环境**严禁开 debug**，优先用会话表与统计完成定位。

### 6.5 健康运维习惯（企业实战）

- 每周导出配置与日志备份（含时间戳命名）
- 每季度做配置变更评审（谁、何时、改了什么）
- 定期检查安全策略"僵尸规则"（长期零命中）并清理
- 升级签名库（IPS/AV 特征库）并测试后上线

## 七、企业安全体系与等保合规

### 7.1 纵深防御（Defense in Depth）

**单靠防火墙救不了整个网络**，安全靠多层防线叠加：

```
  [互联网]
      ↓ 边界防火墙（NAT + 攻击防护 + VPN 入口）
      ↓ 入侵检测/IPS（旁路或串联）
      ↓ 服务器区防火墙（东西向隔离）
      ↓ Web 防火墙（WAF，应用层防护）
      ↓ 主机防护（补丁 + 主机防火墙）
      ↓ 数据层（备份 + 加密）
```

防火墙承担的角色：**边界隔离 + 访问控制 + 安全检测 + VPN 接入 + 审计记录**。

### 7.2 等保 2.0 中防火墙的角色

| 等保控制点 | 防火墙承担的能力 | 二级要求 | 三级要求 |
|-----------|------------------|----------|----------|
| 安全边界-访问控制 | 安全策略/ACL | 按区域/用户控制 | 粒度到端口级+双向控制 |
| 安全边界-边界防护 | 区域隔离、NAT | 边界隔离 | 白名单制、接口与区域映射 |
| 安全边界-入侵防范 | IPS/检测 | 有入侵检测 | 需**实时检测+响应** |
| 安全审计 | 日志 syslog 外送 | 审计记录留存 | 审计日志集中 + 保护性 |
| 网络运维管控 | 双机热备、统一监控 | 基本保障 | 主备切换+链路冗余 |

等保 2.0 三级比二级严的地方，在防火墙上主要体现在：**策略白名单化、日志集中留存、双机冗余、入侵防护（IPS 必须）、关键链路带宽限制**。政企网评重点检查：安全策略是否最小化、是否默认拒绝、日志是否留存 6 个月、是否有双机/备份。

### 7.3 云环境下的防火墙角色

- **NFV 云防火墙**：云平台租户边界（如电信云、政务云的多租户安全域）
- 与物理防火墙的差异：虚拟化资源分配、多租户 vsys 实例、API 自动化下发策略
- 核心职责不变：**隔离 + 控制 + 检测 + 审计**
