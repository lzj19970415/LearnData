# 网络基础·中级

本篇面向已掌握二层交换配置的运维同学，重点解决"**不同 VLAN 怎么互通、网络间怎么路由、地址怎么自动分配、安全怎么控制、故障怎么排**"五大问题。全程华为 VRP 命令（华三 Comware 差异处用括号标注），建议配合 eNSP 逐步敲命令验证。

## 1. 链路聚合（Eth-Trunk）

### 1.1 为什么需要链路聚合

交换机之间一根线带宽不够（如 1G 瓶颈）、或单根链路断了就全断（无冗余），于是把**多根物理链路捆绑成一条逻辑链路**，这个技术叫链路聚合。

**作用**：

| 作用 | 说明 |
| --- | --- |
| 提升带宽 | N 根 1G 捆绑 ≈ 逻辑 N G（华为默认按负载分担） |
| 链路冗余 | 一根线断，流量自动切换到其他成员链路 |
| 简化配置 | 上层把捆绑口当成一个接口管理 |

> 华三称链路聚合为 **Link Aggregation（链路聚合）**，华为叫 **Eth-Trunk**，概念完全一样。

### 1.2 华为配置示例（手工/静态聚合）

华为 Eth-Trunk 支持两种模式：**manual（手工，静态）** 和 **lacp-static（LACP 协议协商）**。对手工模式，两端都要把相同物理接口加入同编号的 Eth-Trunk。

```vrp
<Huawei> system-view
[Huawei] sysname SW1
[SW1] interface Eth-Trunk 1                     # 创建逻辑接口
[SW1-Eth-Trunk1] mode manual load-balance       # 手工聚合模式（默认即手工）
[SW1-Eth-Trunk1] quit

[SW1] interface GigabitEthernet0/0/1
[SW1-GigabitEthernet0/0/1] eth-trunk 1          # 把物理口加入 Eth-Trunk 1
[SW1-GigabitEthernet0/0/1] quit

[SW1] interface GigabitEthernet0/0/2
[SW1-GigabitEthernet0/0/2] eth-trunk 1
[SW1-GigabitEthernet0/0/2] quit

[SW1] interface Eth-Trunk 1
[SW1-Eth-Trunk1] port link-type trunk           # Eth-Trunk 口也要配端口类型
[SW1-Eth-Trunk1] port trunk allow-pass vlan 10 20 100
[SW1-Eth-Trunk1] quit
```

对端交换机同样配置 Eth-Trunk 1 并加入对应物理口。验证：

```vrp
[SW1] display eth-trunk 1
[SW1] display trunkmembership eth-trunk 1
```

> 华三 Comware 对应命令：
> ```vrp
> [H3C] interface Bridge-Aggregation 1
> [H3C-Bridge-Aggregation1] link-aggregation mode dynamic   # LACP 动态；静态对手工模式默认即可
> [H3C] interface GigabitEthernet1/0/1
> [H3C-GigabitEthernet1/0/1] port link-aggregation group 1
> ```
> 华为 `eth-trunk 1` 等价华三 `port link-aggregation group 1`。

### 1.3 注意事项

1. 加入 Eth-Trunk 的物理口必须**类型一致、速率一致**；
2. 加入前接口上有配置会失败（提示先清配置）；
3. 成员口加入后不能再单独配 VLAN，需在 Eth-Trunk 逻辑口统一配。

### 1.4 LACP 动态聚合与负载均衡

生产环境更推荐 **LACP 动态聚合**（两端自动协商、自动增减成员、检测链路状态更可靠）：

```vrp
[SW1] interface Eth-Trunk 1
[SW1-Eth-Trunk1] mode lacp-static          # LACP 静态聚合模式
[SW1-Eth-Trunk1] load-balance dst-ip      # 负载分担方式（按目的 IP，可选 src-ip/src-dst-ip）
[SW1-Eth-Trunk1] quit

[SW1] interface GigabitEthernet0/0/1
[SW1-GigabitEthernet0/0/1] eth-trunk 1
[SW1-GigabitEthernet0/0/1] quit

[SW1] display eth-trunk 1                # 查看成员链路状态（Selected/Standby）
[SW1] display lacp statistics          # LACP 报文统计
```

> 华三 Comware 对应：`interface Bridge-Aggregation 1` + `link-aggregation mode dynamic`；查看 `display link-aggregation verbose`。

> **负载均衡概念**：Eth-Trunk 不是"一根线用满再用下一根"，而是按**报文字段（源/目的 MAC 或 IP）**哈希到成员链路。不同流分布到不同链路，所以`"带宽翻倍"是逻辑叠加，单一大流仍走一条链路。

## 2. VLAN 间路由

初级篇验证过"不同 VLAN 二层隔离"，那部门之间要互访怎么办？答案是**三层路由**，两种主流方案：单臂路由、三层交换机（VLANIF）。

### 2.1 方案一：单臂路由（路由器子接口）

交换机把 trunk 口接路由器，路由器用**子接口**（带 VLAN Tag）终结各 VLAN：

```text
PC1(VLAN10 192.168.10.10) → SW1 trunk 口 → R1 子接口 G0/0/0.10 / .20
PC3(VLAN20 192.168.20.10) → SW1 trunk 口 → R1 子接口 G0/0/0.20
```

**交换机侧配置**（trunk 口透传 10、20）：

```vrp
<H3C> system
[H3C] interface GigabitEthernet0/0/24
[H3C-GigabitEthernet0/0/24] port link-type trunk
[H3C-GigabitEthernet0/0/24] port trunk allow-pass vlan 10 20
```

**路由器侧配置**（AR2220，创建子接口并封装 802.1Q）：

```vrp
<Huawei> system
[Huawei] interface GigabitEthernet0/0/0.10
[Huawei-GigabitEthernet0/0/0.10] dot1q termination vid 10     # 封装 VLAN 10 标签
[Huawei-GigabitEthernet0/0/0.10] ip address 192.168.1.1 255.255.255.0   # VLAN10 的网关
[Huawei-GigabitEthernet0/0/0.10] arp broadcast enable          # 开启子接口 ARP 广播
[Huawei-GigabitEthernet0/0/0.10] quit

[Huawei] interface GigabitEthernet0/0/0.20
[Huawei-GigabitEthernet0/0/0.20] dot1q termination vid 20
[Huawei-GigabitEthernet0/0/0.20] ip address 192.168.20.1 255.255.255.0
[Huawei-GigabitEthernet0/0/0.20] arp broadcast enable
```

> 关键点：PC 的**网关指向子接口 IP**。华三子接口命令为 `vlan-type dot1q vid 10`（替代华为 `dot1q termination vid 10`），其余相同。

### 2.2 方案二：三层交换（VLANIF）

用三层交换机，给每个 VLAN 建一个 **VLANIF 虚拟三层接口**，VLANIF 的 IP 就是该 VLAN 的网关，交换机内部直接路由转发（硬件转发，性能高），是目前主流做法：

```vrp
<Huawei> system
[Huawei] vlan batch 10 20
[Huawei] interface Vlanif 10
[Huawei-Vlanif10] ip address 192.168.1.1 255.255.255.0      # VLAN10 网关
[Huawei-Vlanif10] quit
[Huawei] interface Vlanif 20
[Huawei-Vlanif20] ip address 192.168.20.1 255.255.255.0     # VLAN20 网关
[Huawei-Vlanif20] quit
```

**验证**：

```vrp
[Huawei] display ip interface brief
[Huawei] display ip routing-table          # 应看到两条直连路由
```

PC1（192.168.1.10，网关 192.168.1.1）ping PC3（192.168.20.10，网关 192.168.20.1）→ 通。

> 华三命令完全一致（`interface Vlan-interface 10`，华为为 `interface Vlanif 10`，注意华三是 `Vlan-interface`）。

## 3. 静态路由与默认路由

### 3.1 路由表基础

路由器（三层交换机）转发数据依据**路由表**，每条路由由"**目标网段 + 掩码 + 下一跳（或出接口）**"组成。查看路由表：

```vrp
[Huawei] display ip routing-table
[Huawei] display ip routing-table | include 192.168.30.0
```

路由来源优先级（数值越小越优先）：**直连 > 静态 > OSPF（内部 10）> RIP（120）**。

### 3.2 静态路由配置示例

拓扑：R1 连接网段 `192.168.1.0/24` 和 `192.168.10.0/24`；R2 连接 `192.168.10.0/24` 和 `192.168.2.0/24`，两网段通过 10.0.0.0/24 互连。要让 192.168.1.0 访问 192.168.2.0，需要**在 R1 上写去往 192.168.2.0 的静态路由，下一跳指向 R2 的接口地址**。

```vrp
# R1 配置
<Huawei> system
[Huawei] sysname R1
[R1] interface GigabitEthernet0/0/0
[R1-GigabitEthernet0/0/0] ip address 192.168.1.1 255.255.255.0
[R1-GigabitEthernet0/0/0] quit
[R1] interface GigabitEthernet0/0/1
[R1-GigabitEthernet0/0/1] ip address 10.0.0.1 255.255.255.0
[R1-GigabitEthernet0/0/1] quit

[R1] ip route-static 192.168.2.0 255.255.255.0 10.0.0.2
# 语法：ip route-static 目的网段 目的掩码 下一跳地址

# R2 配置（回程路由）
[R2] ip route-static 192.168.1.0 255.255.255.0 10.0.0.1
```

> **双向都要写路由！** 只配去程、不回程，数据包有去无回，这是运维最常踩的坑。

### 3.3 默认路由

默认路由是"兜底路由"，匹配所有目的地址（0.0.0.0/0），通常指向出口网关/运营商：

```vrp
[R1] ip route-static 0.0.0.0 0.0.0.0 10.0.0.2    # 所有未知网段走 10.0.0.2
```

华三命令 `ip route-static 0.0.0.0 0.0.0.0 10.0.0.2` 完全一致。

### 3.4 浮动静态路由（备份链路）

给同一条目的路由配两条静态路由，设置不同优先级（华为默认 60，越小越优先），主链路失效自动切换备份：

```vrp
# 主用链路：默认优先级 60，走 10.0.0.2
[R1] ip route-static 192.168.2.0 255.255.255.0 10.0.0.2
# 备用链路：优先级 100，走 10.100.0.2（备线）
[R1] ip route-static 192.168.2.0 255.255.255.0 10.100.0.2 preference 100
```

验证：`display ip routing-table` 中只有主路由存在；拔掉主链路后（eNSP 中 shutdown 接口），备用路由自动生效。

> 华三 Comware：`ip route-static 192.168.2.0 24 10.100.0.2 preference 100`，同样支持优先级。这是小型出口"主备链路"最朴素的冗余方案。

## 4. 动态路由 OSPF 基础

### 4.1 为什么用动态路由

静态路由手工逐条配置，网络大、拓扑变化时维护量巨大。OSPF（开放式最短路径优先）**自动学习路由、自动收敛**，通过链路状态算法（SPF）计算最短路径，是企业网标准动态路由协议。

### 4.2 区域概念

OSPF 用**区域（Area）**管理：**Area 0 是骨干区域**，其他区域必须与 0 相连。单区域配置最常见（把所有路由器都放 Area 0）。

### 4.3 单区域 OSPF 配置

拓扑：R1（192.168.1.0/24）— 10.0.0.0/24 — R2（192.168.2.0/24）

```vrp
# R1
<R1> system
[R1] ospf 1 router-id 1.1.1.1                 # 进程号 1，router-id 手工指定（推荐）
[R1-ospf-1] area 0                            # 进入区域 0
[R1-ospf-1-area-0.0.0.0] network 192.168.1.0 0.0.0.255   # 宣告网段（反掩码）
[R1-ospf-1-area-0.0.0.0] network 10.0.0.0 0.0.0.255
[R1-ospf-1-area-0.0.0.0] quit

# R2
[R2] ospf 1 router-id 2.2.2.2
[R2-ospf-1] area 0
[R2-ospf-1-area-0.0.0.0] network 192.168.2.0 0.0.0.255
[R2-ospf-1-area-0.0.0.0] network 10.0.0.0 0.0.0.255
```

**反掩码速记**：255.255.255.0 → 反码 0.0.0.255；255.255.255.128 → 0.0.0.127；不连续（如 255.255.255.192 只允许特定网段时）可用反码精确匹配。

> 华三 Comware 的 OSPF 命令与华为几乎一样：`ospf 1` / `area 0` / `network 192.168.1.0 0.0.0.255`。

### 4.4 邻居与验证

```bash
[R1] display ospf peer                   # 查看 OSPF 邻居
[R1] display ospf peer brief
[R1] display ospf routing                # OSPF 学习到的路由
[R1] display routing-table
```

邻居状态：**2-Way → ExStart → Loading → Full**。`Full` 表示邻接建立成功。如果邻居卡在 `Init` 或 `ExStart`，优先检查：网段是否一致、子网掩码是否一致、`network` 宣告是否覆盖、区域是否相同、MTU 是否不一致。

### 4.5 OSPF 排障要点

- 邻居建立失败 → 检查 network 宣告网段、掩码、区域 ID；
- 路由学不到 → 检查对方是否宣告、区域是否连通；
- 华为 `display ospf error` 看协议错误计数。

### 4.6 OSPF 报文与邻居状态机（进阶必知）

OSPF 依靠 5 类报文交互完成邻居建立与数据库同步：

| 报文 | 全称 | 作用 |
| --- | --- | --- |
| Hello | 你好报文 | 发现邻居、选举 DR/BDR，默认 10s 一次 |
| DD | 数据库描述 | 描述本地 LSDB 摘要 |
| LSR | 链路状态请求 | 请求缺失的 LSA |
| LSU | 链路状态更新 | 传送完整 LSA |
| LSAck | 链路状态确认 | 确认收到 |

邻居状态机（重点背）：**Down → Init → 2-Way → ExStart → Exchange → Loading → Full**。

- **2-Way**：双向邻居确认，DR/BDR 在此时选举；
- **Full**：LSDB 同步完成，可以交换路由。

> 排障实战：邻居一直停在 Down/Init → 对端没收到 Hello（VLAN 不通、接口 down）；停在 ExStart/Exchange → 两端 MTU 或掩码不一致。

## 5. DHCP 服务

### 5.1 DHCP 原理

DHCP（Dynamic Host Configuration Protocol）自动给终端分配 IP、掩码、网关、DNS，免去逐台手工配置。流程：**Discover（发现）→ Offer（提供）→ Request（请求）→ Ack（确认）**，被称为 DORA 过程。

### 5.2 华为设备配置 DHCP 服务（全局地址池）

```vrp
[Huawei] dhcp enable                          # 全局开启 DHCP 功能
[Huawei] ip pool office                      # 创建地址池 office
[Huawei-ip-pool-office] network 192.168.10.0 mask 255.255.255.0   # 地址池网段
[Huawei-ip-pool-office] gateway-list 192.168.10.1                # 下发的网关
[Huawei-ip-pool-office] dns-list 223.5.5.5 114.114.114.114      # 下发 DNS
[Huawei-ip-pool-office] excluded-ip-address 192.168.10.1 192.168.10.10   # 排除地址（服务器、打印机预留）
[Huawei-ip-pool-office] lease day 0 hour 8      # 租约 8 小时
[Huawei-ip-pool-office] quit

# 接口下发 DHCP（接口下开启 global 全局池）
[Huawei] interface Vlanif 10
[Huawei-Vlanif10] ip address 192.168.10.1 255.255.255.0
[Huawei-Vlanif10] dhcp select global          # 使用全局地址池
```

> 华三 Comware 对应：地址池为 `dhcp server ip-pool office`，其余 `network 192.168.10.0 mask 255.255.255.0`、`gateway-list`、`dns-list` 相同；接口下 `dhcp select global` 一致。

**验证**：

```bash
[Huawei] display dhcp select interface               # 接口上的 DHCP 状态
[Huawei] display ip pool name office             # 查看地址池分配情况
```

### 5.3 DHCP 中继概念

客户 PC 与 DHCP 服务器不在同一网段时，交换机/路由器上配置 **DHCP 中继（Relay）**，把客户端的 DHCP 广播请求以单播方式转发给远端的 DHCP 服务器：

```vrp
[Huawei-Vlanif20] ip address 192.168.20.1 255.255.255.0
[Huawei-Vlanif20] dhcp select relay               # 接口启用中继
[Huawei-Vlanif20] dhcp relay server-ip 192.168.100.10   # 指向 DHCP 服务器
```

> 运维场景：云资源池、办公终端量大时用 DHCP 批量下发；排除地址段留给静态 IP 的服务器、打印机，避免冲突。

### 5.4 DHCP 常见故障排查

| 现象 | 排查方向 |
| --- | --- |
| 拿不到地址 | `dhcp select global` 是否启用、地址池是否耗尽（`display ip pool`）、交换机端口是否正常 |
| 拿到错误网段 | 中继配置错误、地址池网段写错、客户端跨网段无中继 |
| IP 冲突 | 排查 excluded-ip-address 是否覆盖服务器、租期是否合理 |
| 时好时坏 | 地址池剩余不足、交换机连接 DHCP 服务器的链路丢包 |

### 5.5 DHCP Snooping（安全加固，了解）

交换机上开启 DHCP Snooping 可防止非法 DHCP 服务器（仿冒网关下发错误 IP）：

```vrp
[Huawei] dhcp snooping enable        # 全局使能
[Huawei-Vlanif10] dhcp snooping enable
[Huawei-GigabitEthernet0/0/1] dhcp snooping trust    # 连接真实 DHCP 服务器的上联口设为信任口
```

> 华三对应 `dhcp snooping enable` 与接口 `dhcp snooping trust`。这是政务/金融内网合规审计常检项。

## 6. ACL 访问控制基础

### 6.1 什么是 ACL

ACL（Access Control List，访问控制列表）是一组"匹配规则"，按报文的**源/目的 IP、端口、协议**等特征进行过滤，用于**安全控制、流量限速、NAT、路由策略**等。运维最常用的是**基本 ACL** 和**高级 ACL**。

### 6.2 华为 ACL 编号规则

| 类型 | 编号范围 | 匹配依据 | 用途 |
| --- | --- | --- | --- |
| 基本 ACL | 2000~2999 | 仅源 IP | 按来源限制访问 |
| 高级 ACL | 3000~3999 | 源/目的 IP、协议、端口 | 精细化控制 |
| 二层 ACL | 4000~4999 | MAC、VLAN | 二层过滤 |

### 6.3 基本 ACL 配置与应用（traffic-filter）

需求：**禁止 VLAN 20 的 PC（192.168.20.0/24）访问服务器 VLAN 10（192.168.10.0/24）**，其他放行。

```bash
# 定义 ACL 2000（基本 ACL），拒绝源网段 192.168.20.0/24，其余允许
[Huawei] acl number 2000
[Huawei-acl-basic-2000] rule 5 deny source 192.168.20.0 0.0.0.255
[Huawei-acl-basic-2000] rule 10 permit source any
[Huawei-acl-basic-2000] quit

# 应用到接口（traffic-filter 方向：inbound 进入 / outbound 出）
[Huawei] interface Vlanif 10
[Huawei-Vlanif10] traffic-filter inbound acl 2000
```

> 华三对应为 `packet-filter inbound acl 2000`（在接口下应用），ACL 定义 `acl number 2000` 与 `rule 5 deny source 192.168.20.0 0` 一致。

**ACL 规则匹配顺序**：华为按**规则编号从小到大**依次匹配，匹配到即停止。**隐含规则**：默认末尾有 `permit any`（华为）或 `deny any`（需显式放行），配置时务必写全。

**inbound / outbound 方向选择**：

- **inbound**：在报文**进入接口时**过滤——适合"不让某网段进来"（如 VLANIF 口禁止财务段访问）；
- **outbound**：在报文**离开接口时**过滤——适合"限制本网段出去"。

> 经验：通常把 ACL 应用在**离攻击源最近**或**离保护对象最近**的接口。写反方向会造成"明明配了却不生效"，这是 ACL 排障第一检查项。

### 6.4 高级 ACL 示例（限制 Telnet 端口）

```bash
[Huawei] acl number 3000
```

## 7. 网络排障基础命令与思路

### 7.1 核心排障命令

| 命令 | 作用 |
| --- | --- |
| `ping <IP>` | 测 IP 连通性与丢包/时延 |
| `tracert <IP>` | 逐跳追踪路径，定位断点（华三：`tracert` 相同） |
| `display interface brief` | 接口状态：Up/Down、速率、光口收发光 |
| `display ip interface brief` | 三层接口 IP 与状态 |
| `display vlan` | VLAN 列表与端口成员 |
| `display mac-address` | MAC 表（排查环路、学习异常） |
| `display arp` | ARP 表（排查 IP 冲突、网关问题） |
| `display logbuffer` | 设备日志缓冲区 |
| `display cpu-usage` / `display memory-usage` | 设备负载 |

### 7.2 常见故障场景排查

**场景一：同一交换机不同 VLAN 之间不通**

```text
1. 确认两边网关配置（VLANIF 是否存在、IP 是否冲突）；
2. display ip interface brief 查看 VLANIF 状态；
3. 确认 PC 网关指对；不同 VLAN 二层天然隔离，必须走三层路由。
```

**场景二：外网不通**

```text
1. 先 ping 网关 —— 不通则查本机 IP/掩码、交换机端口 VLAN；
2. 网关通 → ping 外网 —— 不通则查默认路由（display ip routing-table 是否有 0.0.0.0/0）；
3. 路由有 → ping 外网域名 —— 域名不通查 DNS；IP 通域名不通 = DNS 问题；
4. 都通但网页打不开 → 检查出口防火墙/代理/HTTP 端口。
```

**场景三：网络时好时坏、丢包**

```text
1. ping 目标看丢包率；
2. 检查是否有环路（广播风暴）→ display mac-address 看异常刷新；
3. 看 CPU 是否过高（广播攻击）；
4. 查物理链路（光衰、双工不匹配：display interface）。
```

### 7.3 排障方法论（自上而下/自下而上）

- **自下而上**：物理 → 链路 → 网络 → 传输 → 应用（适合"完全不通"）；
- **自上而下**：先查应用再查底层（适合"应用卡但网络通"）；
- **中间突破口**：从"离故障点最近的网关"开始 ping，二分法快速缩小范围。

### 7.4 综合排障案例演练

**案例**：政务外网某部门反馈"能登录内网 OA，但打不开互联网"。

```text
第 1 步  ping 网关 192.168.10.1         → 通（本机到网关正常）
第 2 步  ping 8.8.8.8 / 114.114.114.114 → 不通（说明出口或路由问题）
第 3 步  display ip routing-table        → 无默认路由 0.0.0.0/0
第 4 步  结论：出口默认路由缺失，或出口设备 ACL 阻断；补配
         ip route-static 0.0.0.0 0.0.0.0 10.0.0.2
```

**问题**：两台 PC 同 VLAN 但互 ping 不通。

```text
第 1 步  ipconfig 检查 IP/掩码/网关是否同网段；
第 2 步  display port vlan 确认端口划分到同一 VLAN；
第 3 步  display mac-address 看能否学习到对端 MAC；
第 4 步  学不到 → 查网线/端口物理状态（display interface brief）。
```

> 运维口诀：**先物理、后链路、再路由、终应用**；`ping` 通 ≠ 网络通（防火墙策略仍可能拦端口）。

## 8. 本篇小结

| 主题 | 核心配置 |
| --- | --- |
| 链路聚合 | `interface Eth-Trunk 1` + 接口 `eth-trunk 1` |
| VLAN 间路由 | VLANIF 接口配 IP（三层交换）或子接口单臂路由 |
| 静态路由 | `ip route-static 目的网段 掩码 下一跳` |
| OSPF | `ospf 1` → `area 0` → `network x.x.x.x 反掩码` |
| DHCP | 地址池 + 接口 `dhcp select global`，跨网段用中继 |
| ACL | 基本 2000~2999，`traffic-filter` 应用到接口 |
| 排障 | 按层二分：接口 → 路由 → 转发 → 应用 |
