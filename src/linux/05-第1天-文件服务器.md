# 文件服务器（Samba/FTP/NFS 等）

Linux 下常用的文件共享服务有三类：**FTP**（跨平台文件传输）、**NFS**（Linux 之间的文件级共享，性能最好）、**Samba**（Linux 与 Windows 之间的共享）。本篇以 Vsftpd 为主线，兼顾 NFS 与 Samba，最后补充 NAS/SAN 存储概念。

## FTP 文件传输协议

### FTP 基本概念

- FTP（File Transfer Protocol）基于 **TCP** 协议，实现文件的上传、下载、删除与共享。
- 采用 **C/S（客户端/服务器）** 模式：服务端提供共享，客户端上传下载；一个服务端可同时服务多人。
- FTP 会建立两条 TCP 连接：
  - **控制连接**：传输命令信息（固定 21 端口）；
  - **数据连接**：实际传输文件数据。
- 主流 FTP 服务端软件：**Vsftpd**（Linux 最主流）、ProFTPD、PureFTPd、Server-U、FileZilla Server 等。

### 主动模式与被动模式

两种模式均以 **FTP 服务器端** 为参照（易错点：别站在客户端视角记忆）：

| 模式 | 过程 | 数据端口 |
| --- | --- | --- |
| **主动模式（PORT）** | 客户端用任意端口 N（N>1024）连服务器 21 命令端口 → 客户端监听 N+1 并发 `PORT N+1` 命令 → **服务器用 20 端口主动连客户端的 N+1** | 服务端固定 20 |
| **被动模式（PASV）** | 客户端连服务器 21 → 客户端发 `PASV` 命令 → **服务器开一个任意高位端口 P（>1024）** → 客户端主动连 P 传数据 | 服务端随机高位 |

> **企业实践**：若客户端与服务端都开防火墙，FTP 建议用**主动模式**，服务端防火墙只需放行 **20、21** 两个端口即可；被动模式因数据端口随机，防火墙配置麻烦。

### Vsftpd 简介

- 全称 Very Secure FTP daemon，"非常安全的 FTP 服务进程"。
- 特点：小巧轻快、安全易用、稳定高效，可满足企业 1000 用户级别的跨部门使用。
- 基于 GPL 开源；支持**虚拟用户**方式验证（更安全），还可结合 MySQL 做多重验证。

### 三种登录类型

| 类型 | 说明 |
| --- | --- |
| **匿名用户** | 无需密码，映射为系统用户 `ftp`，默认根目录 `/var/ftp/` |
| **本地（系统）用户** | 用 Linux 系统账号密码登录，默认进入该用户家目录 |
| **虚拟用户** | 只存在于 FTP 专属数据库中，统一映射成一个系统用户，最安全 |

详细配置可通过 `man vsftpd.conf` 查看。

## Vsftpd 安装与配置

### 安装步骤

```bash
# 安装 epel 源
yum -y install epel-release.noarch
# 安装 vsftpd 及依赖：pam 认证模块、db4 文件数据库支持
yum -y install vsftpd* pam* db4*
```

### 配置文件清单

| 文件/目录 | 作用 |
| --- | --- |
| `/etc/vsftpd/vsftpd.conf` | 核心配置文件 |
| `/etc/vsftpd/ftpusers` | 指定**禁止**访问 FTP 的用户（PAM 拦截） |
| `/etc/vsftpd/user_list` | 用户列表，允许/拒绝由 `userlist_deny` 决定 |
| `/etc/vsftpd/vsftpd_conf_migrate.sh` | 变量与设置脚本 |
| `/var/ftp/` | 匿名用户默认根目录 |

### 修改前先备份

```bash
cd /etc/vsftpd/
cp vsftpd.conf{,.bak}   # 生成 vsftpd.conf.bak
```

### 核心配置参数

```text
anonymous_enable=YES          # 是否允许匿名登录
local_enable=YES              # 是否允许本地系统用户登录
write_enable=YES              # 是否开启写入（上传）的总开关
local_umask=022               # 本地用户上传文件的权限掩码（注释默认 077，常设 022）
anon_upload_enable=YES        # 匿名上传（需先开 write_enable，且目录有写权限）
anon_mkdir_write_enable=YES   # 匿名创建目录
anon_other_write_enable=YES   # 匿名其他写权限（改名/删除/覆盖）
anon_umask=022                # 匿名上传掩码
anon_root=/var/ftp            # 匿名用户 FTP 根目录
anon_max_rate=0               # 匿名最大传输速率（字节/秒），0 不限
local_root=/var/ftp           # 本地用户登录后的根目录
local_max_rate=0              # 本地用户速率限制
xferlog_enable=YES            # 开启上传/下载日志
xferlog_file=/var/log/xferlog # 日志路径
xferlog_std_format=YES        # 标准日志格式
idle_session_timeout=600      # 空闲会话超时（秒）
data_connection_timeout=120   # 数据传输超时（秒），与上一项同一时间只有一个生效
connect_from_port_20=YES      # 主动模式使用 20 端口
listen=YES                    # 独立模式监听 IPv4（不能与 listen_ipv6 同用）
pam_service_name=vsftpd       # PAM 认证文件（/etc/pam.d/vsftpd）
userlist_enable=YES           # 启用 user_list 控制
userlist_deny=YES             # YES=拒绝列表内用户；NO=仅允许列表内用户
max_clients=0                 # 最大并发连接数
max_per_ip=0                  # 同一 IP 最大连接数
chroot_local_user=YES         # 是否把所有用户锁在家目录
allow_writeable_chroot=YES    # 允许 chroot 根目录有写权限（新版必须，否则登录报错）
ftpd_banner=Welcome to FTP    # 登录标语
```

> **易错点**：`anon_upload_enable` 即使设为 YES，若没开 `write_enable=YES`，或共享目录属主不对，都无法上传。

### chroot 组合逻辑（易混点）

| chroot_local_user | chroot_list_enable | 效果 |
| --- | --- | --- |
| YES | YES | 全部用户锁家目录；`chroot_list` 中的用户是**例外（不锁）** |
| YES | NO | 全部锁，无例外 |
| NO | YES | 全部不锁；`chroot_list` 中的用户是**例外（被锁）** |
| NO | NO | 全部不锁，无例外 |

记忆口诀：**两个都开 = 名单是例外**；只开 local_user = 全锁，只开 list_enable = 只锁名单内。

### 匿名用户配置示例

```bash
vim /etc/vsftpd/vsftpd.conf
```

```text
anonymous_enable=YES
anon_root=/var/ftp
anon_upload_enable=YES
anon_mkdir_write_enable=YES
anon_other_write_enable=YES
anon_umask=022
write_enable=YES
```

开启服务并验证：

```bash
systemctl start vsftpd
netstat -lnpt | grep vsftpd   # 应看到 0.0.0.0:21 LISTEN
```

**实现匿名上传的关键一步——改目录属主**：

```bash
cd /var/ftp/
chown -R ftp.ftp pub/
ll   # pub 属主属组从 root 改为 ftp
```

> **重点**：匿名访问的身份是 `ftp` 用户，`pub` 默认属主是 root，不改属主就只能浏览不能上传。

> **注意**：改完配置必须 `systemctl restart vsftpd` 才生效；客户端要**重新登录**，否则看不到新配置效果。

### 本地（系统）用户配置示例

```bash
# 1. 创建测试用户
useradd zhangsan
useradd lisi
echo "123456" | passwd --stdin zhangsan
echo "123456" | passwd --stdin lisi
```

```text
# 2. 修改 /etc/vsftpd/vsftpd.conf
local_enable=YES
local_umask=077
chroot_local_user=YES
allow_writeable_chroot=YES
write_enable=YES
pam_service_name=vsftpd
userlist_enable=YES
userlist_deny=NO        # 只允许 user_list 中的用户登录（白名单模式）
```

```bash
# 3. 添加白名单
vim /etc/vsftpd/user_list
# 写入：zhangsan、lisi

# 4. 重启并测试
systemctl restart vsftpd
```

### 虚拟用户配置（重点，完整流程）

虚拟用户即"只有 FTP 概念的账号"，全部映射到一个系统用户，安全性最高。

```bash
# 1. 建立虚拟用户映射的系统用户（禁止登录 shell）
useradd -s /sbin/nologin vu

# 2. 创建虚拟用户文件（奇数行用户名，偶数行密码）
cd /etc/vsftpd/
vim user
# wangwu
# 12345
# maliu
# 12345

# 3. 用 db_load 转成 Berkeley DB 数据库
db_load -T -t hash -f user user.db
# -f 指定源文件  -T 允许非 Berkeley 程序使用的文本转换  -t hash 读取方法

# 4. 建立支持虚拟用户的 PAM 认证文件
vim /etc/pam.d/vsftpd.vu
# auth    required  /lib64/security/pam_userdb.so db=/etc/vsftpd/user
# account required  /lib64/security/pam_userdb.so db=/etc/vsftpd/user

# 5. 修改主配置文件
vim vsftpd.conf
```

```text
guest_enable=YES              # 启用虚拟用户功能
guest_username=vu             # 指定虚拟用户映射的宿主用户
pam_service_name=vsftpd.vu    # 使用第 4 步的 PAM 文件
virtual_use_local_privs=YES   # 虚拟用户权限与宿主用户（本地用户）一致
user_config_dir=/etc/vsftpd/user_dir   # 每个用户的独立配置目录
allow_writeable_chroot=YES
local_enable=YES
local_umask=077
chroot_local_user=YES
write_enable=YES
```

```bash
# 6. 为用户建立独立配置（目录名=用户名）
mkdir /etc/vsftpd/user_dir
vim /etc/vsftpd/user_dir/wangwu
# local_root=/etc/vsftpd/data    # 该虚拟用户的数据存放路径

# 7. 建数据目录并给权限
mkdir /etc/vsftpd/data
chmod 777 data/

# 8. 重启并测试
systemctl restart vsftpd
touch /etc/vsftpd/data/wangwu.txt   # 登录后验证可见
```

> **重点易错**：**本地用户和虚拟用户不能同时登录**——认证方式只有一种：本地用户用 `pam_service_name=vsftpd`，虚拟用户用 `pam_service_name=vsftpd.vu`，二者互斥。

## FTP 客户端 lftp

### 特点与语法

- lftp 支持 **ftp、FTPS、HTTP、SFTP** 等多种协议，支持 Tab 补全（双击 Tab 查看候选）。
- 语法：`lftp 用户名:密码@ftp地址:传送端口（默认21）`
- 常用选项：`-f 指定脚本文件`、`-c 执行命令后退出`。

### 常用操作

```bash
lftp zhangsan@192.168.1.10          # 登录（或不带用户名登录后用 login 命令）
ls / cd                             # 查看文件、切换目录
get file                            # 下载单个文件
mget -c *.pdf                       # 批量下载（-c 支持断点续传）
mirror aaa/                         # 整目录下载（含子目录）
put file / mput *.txt               # 上传
mirror -R 本地目录                   # 本地目录迭代反向上传
pget -c -n 10 file.dat              # 最多 10 线程断点续传下载
set ftp:charset gbk                 # 远程编码 gbk 时设置，乱码必用
set file:charset utf8               # 本地编码
```

### 书签与配置文件

```bash
# lftp 提示符下收藏书签
bookmark add ustc
bookmark edit        # 手动编辑书签（明文文本文件）

# /etc/lftp.conf 常用配置，免去每次敲命令
set ftp:charset gbk
set file:charset utf8
set pget:default-n 5
```

## NAS 与 SAN 存储

### 概念对比

| 对比项 | NAS（Network Attached Storage） | SAN（Storage Area Network） |
| --- | --- | --- |
| 共享级别 | **文件级**共享 | **块级**共享 |
| 网络 | 依赖 TCP/IP 以太网（局域网） | 专用高速网络（FC 光纤或 IP-SAN），模拟 SCSI 总线 |
| 协议 | NFS、SMB/CIFS、HTTP | SCSI（经 FCP/TCP-IP 封装） |
| 系统识别 | 共享文件夹（一个文件系统） | 本地块设备（需专门锁管理软件支持并发） |
| 性能 | 相对较低（文件系统层开销），高速局域网可弥补 | 高 IOPS、低延迟，适合数据库/高交易环境 |
| 依赖 | 局域网故障则 NAS 中断 | 不依赖局域网，减轻 LAN 压力 |
| 管理/成本 | 即插即用、管理简单、成本低 | 部署复杂、需专人管理、维护费高 |

### 使用场景

- **NAS**：文件存储共享整合、活动档案存档、大数据（横向扩展 NAS）、中小虚拟化环境、VDI。
- **SAN**：数据库与高流量电商网站、快速备份（备份流量不走 LAN）、大规模虚拟化、视频编辑。

> **性能排序（FTP/NFS/Samba）**：**NFS > FTP > Samba**。

## NFS 服务

### NFS 原理与 RPC

- NFS（Network File System）在 **Linux 内核**实现，服务端监听 **TCP/UDP 2049** 端口；难以与 Windows 兼容。
- 依赖 **RPC（远程过程调用）** 机制：其他基于 RPC 的服务启动时先向 RPC 注册，由 RPC 分配随机端口；客户端先问 RPC（**111 端口**，CentOS 6.5 后进程名为 portmapper/rpcbind）再发起真正请求。
- 配套用户态工具由 `nfs-utils` 软件包提供；NFS 仅支持基于 IP 的访问控制。

### 服务端配置

```bash
# 1. 添加 hosts 解析（可选）
vim /etc/hosts
# 192.168.122.59  nfs.qfedu.com
# 192.168.122.85  client.qfedu.com

# 2. 安装
yum install -y nfs-utils

# 3. 创建共享目录
mkdir /data

# 4. 配置共享
vim /etc/exports
# /data  192.168.122.0/24(rw,sync,no_root_squash)
# 含义：该网段主机可把 NFS 服务器的 /data 挂到自己的文件系统

# 5. 设置开机启动并启动（先 rpcbind 后 nfs）
systemctl enable rpcbind.service
systemctl enable nfs-server.service
systemctl start rpcbind.service
systemctl start nfs-server.service

# 6. 确认
exportfs -v      # 查看导出详情
exportfs -r      # 重新载入配置使其生效
rpcinfo -p       # 查看向 RPC 注册的端口
```

### exports 常用参数

| 参数 | 含义 |
| --- | --- |
| `ro` / `rw` | 只读 / 读写（**缺省只读**） |
| `sync` | 同步写入 |
| `secure`（默认） | 仅用 1024 以下端口连接；`insecure` 反之 |
| `async` | 异步提高性能，但未正常关守护进程就重启可能丢数据 |
| `no_wdelay` | 关闭写延时（设了 async 会被忽略） |
| `no_subtree_check` | 关闭子树检查 |
| `root_squash`（默认） | root 被映射为匿名用户，**不允许 root 身份访问** |
| `no_root_squash` | **允许 root** 以 root 身份访问挂载卷 |
| `all_squash` | 所有 UID/GID 一律映射为匿名用户（公共卷常用），默认 no_all_squash |
| `anonuid` / `anongid` | 指定匿名用户的 UID/GID |

### 客户端配置与挂载

```bash
# 1. 客户端只装工具、只起 rpcbind，不需要启动 nfs 服务（易错点）
yum -y install nfs-utils
systemctl enable rpcbind.service
systemctl start rpcbind.service

# 2. 查看服务端共享列表
showmount -e nas
# Export list for nas:
# /data 192.168.122.0/24

# 3. 手动挂载
mkdir /data
mount -t nfs nas:/data /data
umount /data

# 4. 开机自动挂载
vim /etc/fstab
# nas:/data  /data  nfs  defaults  0 0
mount -a && df    # 验证
```

> **服务端改配置不重启**：有客户端在使用时不要重启 NFS，用 `exportfs` 重新载入：
> - `exportfs -ar` 重新导出所有；`exportfs -au` 关闭所有导出；`exportfs -u FS` 关闭指定导出。

## Samba 服务

### 原理简介

- Samba 是在 Linux/UNIX 上实现 **SMB 协议**的免费软件，最大功能是 **Linux 与 Windows 之间文件/打印共享**，也可用于 Linux 之间。
- SMB（Server Messages Block）是局域网共享文件、打印机的 C/S 协议；配合 NetBIOS over TCP/IP 可跨网段共享。

### 两个核心守护进程

| 进程 | 职责 | 端口 |
| --- | --- | --- |
| **smbd** | 建立 SMB 对话、验证身份、提供**文件和打印**访问（核心服务，不启动就没有共享） | **139/TCP** |
| **nmbd** | **名称解析**（工作组名 ↔ IP，类似 DNS 的作用）；不启动则只能用 IP 访问 | **137、138/UDP** |

- 两进程的全部配置保存在 `/etc/samba/smb.conf`。
- Windows 访问方式：`\\192.168.122.15\共享目录名` 或 `\\MYWORKGROUP\共享目录名`。
- Samba 提供四类服务：文件和打印服务、授权与被授权（smbd）；名称解析、浏览服务（nmbd）。

## 本篇要点小结

1. FTP 有主动/被动两种模式，参照物是**服务器端**；双防火墙环境选主动模式只放行 20/21。
2. Vsftpd 三种登录类型：匿名（ftp 用户）、本地（系统用户）、虚拟（映射系统用户 + PAM userdb），认证方式互斥。
3. 匿名上传三要素：`write_enable` + `anon_upload_enable` + 目录属主（ftp）。
4. NFS 依赖 RPC（111），数据端口 2049；客户端只起 rpcbind；root 权限由 `no_root_squash` 控制。
5. Samba 的 smbd（139/TCP）管文件、nmbd（137/138/UDP）管名字。
6. 性能：NFS > FTP > Samba；文件共享选 NAS，数据库/高 I/O 选 SAN。
