# 路由与日志管理

> 本篇覆盖：直连/静态/默认/动态路由概念、Linux 路由查看与增删（ip route/route）、端口概念与常见服务端口、systemctl 服务管理、rsyslog 日志类型与优先级、常见系统日志文件、自定义日志、logrotate 日志轮转与日志安全。

## 一、路由基础

### 1. 路由的三种来源

路由器转发数据时，需要在**路由表**中查找相应路由。路由表中的路由有三种途径：

1. **直连路由**：路由器自动添加和自己直连的网段路由；
2. **静态路由**：管理员手动添加的路由；
3. **动态路由**：由路由协议（如 OSPF、RIP、BGP）动态建立的路由。

### 2. 静态路由

| 优缺点 | 说明 |
|--------|------|
| 优点 | 不占用路由器太多 CPU 和 RAM 资源，不占用太多带宽；出于安全考虑可隐藏网络的某些部分；管理员可控制数据转发路径；小网络配置静态路由更便捷 |
| 缺点 | **不能动态反映网络拓扑**，网络发生变化时管理员必须手动修改路由 |

### 3. 默认路由

- 默认路由是一种**特殊的静态路由**：当路由表中与包的目的地址**没有匹配表项**时，路由器按默认路由做出选择；
- 如果没有默认路由，目的地址在路由表中无匹配表项的包将被**丢弃**；
- 默认路由为 `0.0.0.0`：匹配 IP 时，0 表示 wildcard（通配），与任何目的地址都匹配成功——这就是默认路由的效果。

### 4. 动态路由

- 指路由器之间交换特定路由信息，**自动建立自己的路由表**，并能根据链路和节点变化自动调整；
- 当网络节点或链路故障、存在其他可用路由时，动态路由可自行选择**最佳可用路由**继续转发报文。

## 二、Linux 路由操作

### 1. 查看路由表（ip r）

```bash
ip r            # ip route，RHEL7 推荐
```

输出示例：

```text
default via 10.18.44.1 dev enp0s25                       ← 默认路由（网关）
10.18.40.100 via 10.18.44.1 dev enp0s25 proto dhcp metric 100
10.18.44.0/24 dev enp0s25 proto kernel scope link src 10.18.44.196 metric 100
10.18.45.0/24 via 10.18.44.1 dev enp0s25                 ← 静态路由
192.168.122.0/24 dev virbr0 proto kernel scope link src 192.168.122.1
```

字段解读：

- `default via 10.18.44.1`：默认路由，下一跳网关 10.18.44.1；
- `via`：下一跳地址；`dev`：出接口；
- `src`：该路由使用的本机源地址；
- `metric`：路由开销值，越小越优先（DHCP 下发的路由常带 metric 100）。

### 2. 添加/删除路由

```bash
# 添加默认网关
ip r add default via 10.18.44.1 dev enp0s25

# 删除默认网关
ip r d default            # ip route delete default

# 添加静态路由：访问 10.18.45.0/24 网段走 10.18.44.1
ip r add 10.18.45.0/24 via 10.18.44.1 dev enp0s25

# 删除静态路由
ip r del 10.18.45.0/24
```

> **易错点**：`ip r add` 配置的路由是**临时生效**的，重启网络/主机后消失。

### 3. 旧版 route 命令（了解）

```bash
route -n                          # 查看路由表（-n 数字显示不做解析）
route add default gw 10.18.44.1   # 添加默认网关
route del default gw 10.18.44.1   # 删除默认网关
route add -net 10.18.45.0/24 gw 10.18.44.1 dev enp0s25   # 添加静态路由
```

### 4. 路由持久化配置

```bash
# 方法一：写进网卡配置文件（RHEL7）
vim /etc/sysconfig/network-scripts/ifcfg-eth0
GATEWAY=10.18.44.1                       # 默认网关

# 静态路由文件（一条一行）
vim /etc/sysconfig/network-scripts/route-eth0
10.18.45.0/24 via 10.18.44.1 dev eth0

systemctl restart network

# 方法二：nmcli（RHEL8+）
nmcli con mod eth0 ipv4.gateway "10.18.44.1"
nmcli con mod eth0 +ipv4.routes "10.18.45.0/24 10.18.44.1"
nmcli con up eth0
```

### 5. 路由排障组合

```bash
ping -c3 10.18.45.10        # 测连通
traceroute -n 10.18.45.10   # 逐跳追踪路径
ip r get 10.18.45.10        # 查看去往该目的地址实际选中的路由
```

## 三、端口与服务

### 1. 网络端口概念

- 这里的端口指 **TCP/IP 协议中的逻辑端口**，不是集线器/交换机/路由器上的物理接口（RJ-45、Serial 等）；
- 如果把 IP 地址比作一间房子，**端口就是出入这间房子的门**；一个 IP 的端口可以有 **65536（2^16）** 个，端口号范围 **0 ~ 65535**（2^16-1）；
- 端口机制的目的：操作系统支持多进程同时运行，数据包到达主机后，根据报文首部的**目的端口号**把数据交给对应进程；
- 端口本质是**队列**：操作系统为进程分配队列，数据包按目的端口推入相应队列等待进程取用；队列可溢出，进程可调整自己队列大小；
- 接收方进程要开启端口，**发送方进程也要开启端口**（数据包带源端口，便于对方回传）。

### 2. 常见端口号（运维必背）

| 端口 | 服务 | 说明 |
|------|------|------|
| 22 | SSH | 远程登录 |
| 80 | HTTP | Web |
| 443 | HTTPS | Web 加密 |
| 3306 | MySQL | 数据库 |
| 9000 | php-fpm | FastCGI |
| 21 / 20 | FTP 控制链路 | 文件传输 |
| 25 | SMTP | 发邮件 |
| 110 / 143 | POP3 / IMAP | 收邮件 |
| 53 | DNS | 域名解析（TCP/UDP） |
| 139 / 445 | NetBIOS / SMB | Windows 共享 |
| 3389 | RDP | 远程桌面 |

### 3. 常见服务管理操作（systemctl）

```bash
systemctl list-units                # 查看当前已加载的服务单元
systemctl list-unit-files           # 查看所有服务的开机自启状态
systemctl start vsftpd              # 启动服务
systemctl status vsftpd             # 查看服务状态
systemctl status vsftpd -l          # 查看状态（完整输出，不截断）
systemctl stop vsftpd               # 停止
systemctl restart vsftpd            # 重启
systemctl reload vsftpd             # 重载配置（不中断服务）
systemctl enable vsftpd             # 设置开机自启
systemctl disable vsftpd            # 取消开机自启
ss -anput | grep 3306               # 检查端口监听
```

## 四、日志系统（rsyslog）

### 1. 日志的重要性

- Linux 系统日志是管理员**了解系统运行的主要途径**；
- 内核和许多程序会产生错误信息、告警信息和其他提示信息，这些信息都应记录到日志文件中；
- 完成这个过程的程序是 **rsyslog**，它可以根据日志的**类别和优先级**将日志保存到不同的文件中。

### 2. 常见系统日志文件

| 日志文件 | 记录内容 |
|---------|---------|
| `/var/log/messages` | 系统和服务常见错误信息（最常用） |
| `/var/log/boot.log` | 系统引导过程中发生的事件（开机自检信息） |
| `/var/log/lastlog` | 最后一次用户成功登录的时间、登录 IP 等（用 `lastlog` 命令查看） |
| `/var/log/secure` | 系统安全日志：用户和组变化、用户登录认证情况（SSH 排障必看） |
| `/var/log/btmp` | 登录失败的记录（用户、时间、远程 IP；`lastb` 查看，文件可能很大） |
| `/var/log/wtmp` | 永久记录每个用户登录、注销及系统启动、停机事件（`last` 命令查看） |
| `/var/log/cron` | 计划任务执行记录 |
| `/var/log/maillog` | 邮件相关记录 |

### 3. 日志类型（facility，设备/对象）

rsyslog 按日志来源分类：

| 类型 | 含义 |
|------|------|
| auth | PAM 产生的日志 |
| authpriv | SSH、FTP 等登录信息的验证信息 |
| cron | 时间任务（计划任务）相关 |
| kern | 内核 |
| lpr | 打印 |
| mail | 邮件 |
| mark(syslog) | rsyslog 服务内部信息，时间标识 |
| news | 新闻组 |
| user | 用户程序产生的相关信息 |
| `*` | 所有类型 |

### 4. 日志优先级（level）

日志级别 0~7，**级别越低信息越多**（debug 信息最多，emerg 最严重）：

| 代号 | 级别 | 含义 |
|------|------|------|
| 0 | debug | 调试信息，日志信息最多 |
| 1 | info | 一般信息，最常用 |
| 2 | notice | 具有重要性的普通条件信息 |
| 3 | warning | 警告级别 |
| 4 | err | 错误级别，阻止某功能/模块正常工作 |
| 5 | crit | 严重级别，阻止整个系统或整个软件不能工作 |
| 6 | alert | 需要立刻修改的信息 |
| 7 | emerg | 内核崩溃等严重信息 |
| — | none | 什么都不记录 |

### 5. 自定义日志

```bash
vim /etc/rsyslog.conf
```

配置格式：

```text
日志对象.日志级别    日志文件
```

匹配符号：

- `.`：记录**大于或等于**后面指定级别的日志；
- `.=`：只记录**等于**指定级别的日志；
- `.!`：非（排除指定级别）。

示例：

```text
*.*                    /var/log/mylog         # 所有类型所有级别
kern.err               /var/log/kernel.log    # 内核 err 及更严重
*.info;mail.none       /var/log/big.log       # 所有 info 级，排除 mail
mail.info              /var/log/mail.log
cron.info;cron.!err    /var/log/newcron       # cron 的 info~warning
```

```bash
systemctl restart rsyslog       # 修改后重启日志服务生效
# 测试写入
logger -p kern.err "test kern error log"
tail /var/log/kernel.log
```

## 五、logrotate 日志轮转

### 1. 为什么要轮转

日志持续增长会占满磁盘、检索变慢。logrotate 按**周期/大小**把旧日志改名归档并新建日志文件，控制日志占用。

### 2. 全局配置 /etc/logrotate.conf

```bash
vim /etc/logrotate.conf
```

```text
weekly                          # 轮转周期，默认一周轮转一次
rotate 4                        # 轮转次数，保留最近 4 份归档
create                          # 轮转后创建新文件
dateext                         # 以轮转时刻的时间作为归档文件后缀

include /etc/logrotate.d        # 局部配置目录
missingok                       # 文件不存在时不报错
create 0644 root utmp           # 建新文件时指定权限/属主/属组
```

### 3. 轮转实例 1：普通日志

```bash
vim /etc/logrotate.d/yum
```

```text
/var/log/yum.log {
        missingok
        daily                   # 每天轮转
        rotate 3                # 保留 3 份
        create 0777 root root
}
```

手动测试：

```bash
logrotate /etc/logrotate.conf                   # 手动执行一次轮转
ls /var/log/yum*
# /var/log/yum.log  /var/log/yum.log-20170331
grep 'yum' /var/lib/logrotate/logrotate.status  # 查看各文件最近轮转时间
```

配合改系统时间验证周期：

```bash
date 09011000                                               # 改系统时间
logrotate -s /var/lib/logrotate/logrotate.status /etc/logrotate.conf
```

- `-s`：指定轮转状态记录文件（记录所有日志文件最近轮转的时间）。

### 4. 轮转实例 2：日志安全（chattr 隐藏权限）

```bash
vim /etc/logrotate.d/messages
```

```text
/var/log/messages {
    prerotate
        chattr -a /var/log/messages        # 轮转前去掉追加属性
    endscript

    daily
    create 0600 root root
    missingok
    rotate 5

    postrotate
        chattr +a /var/log/messages        # 轮转后加回追加属性
    endscript
}
```

- `chattr +a`：只能追加不能删除/修改，防篡改（日志安全）；
- `chattr -a`：解除，否则 logrotate 无法改名；
- 注意：测试时若与 `/etc/logrotate.d/syslog` 中的 messages 规则重复，先把 syslog 里的 messages 段删除，避免冲突。

### 5. 轮转实例 3：多个日志共用一份配置

```bash
vim /etc/logrotate.d/syslog
```

```text
/var/log/cron
/var/log/maillog
/var/log/secure
/var/log/spooler
{
    missingok
    sharedscripts                          # 多个文件只执行一次脚本
    postrotate
        /bin/kill -HUP `cat /var/run/syslogd.pid 2> /dev/null` 2> /dev/null || true
    endscript
}
```

### 6. 轮转后重启服务的重要性（原理）

- 轮转只是把旧日志文件**改名**，文件的 **INODE 并没有变**；
- 而日志程序（rsyslogd）是按**文件的 inode 号**识别文件的，改了名字它仍往旧 inode 写；
- 所以轮转配置里的 postrotate 脚本要**重启/通知日志服务**（`kill -HUP` 或 `systemctl restart rsyslog`），让它重新打开新文件，新的日志内容才能写入新日志文件。

### 7. journalctl（systemd 日志补充）

```bash
journalctl -xe                 # 最近日志+解释，排障常用
journalctl -u nginx            # 指定服务的日志
journalctl -u nginx -f         # 实时跟踪
journalctl --since today       # 按时间过滤
```

## 六、实战清单

1. 添加默认路由，配置静态路由并测试连通（`ip r add` + `ping` + `traceroute`）。
2. 使用 rsyslog 自定义日志（配置 facility.level → 文件，`logger` 测试，重启 rsyslog 验证）。
3. 使用 logrotate 对日志进行轮转（daily/rotate/create 配置，手动轮转并检查归档文件与 status 文件）。
4. 用 `last`、`lastb`、`lastlog` 检查登录痕迹。

## 七、易错点汇总

- `ip r add` 的路由临时生效，重启消失；持久化要写 ifcfg/route-eth0 或用 nmcli。
- 默认路由 `0.0.0.0` 能匹配一切目的地址；无默认路由时无匹配包直接丢弃。
- rsyslog 日志级别数字越小信息越多（0=debug 最多，7=emerg 最严重）；`.` 是"大于等于"而不是"等于"。
- 改 rsyslog.conf 后必须 `systemctl restart rsyslog` 才生效。
- logrotate 的 `prerotate` 里 `chattr -a`、`postrotate` 里 `chattr +a`，顺序颠倒轮转会失败。
- 轮转只改名不改 inode，**不重启日志服务会导致日志继续写进旧文件**——这是轮转配置里 postrotate 脚本存在的意义。
- 多个日志文件共用配置时用 `sharedscripts`，避免脚本重复执行。
