# IP详解及配置

> 本篇覆盖：IP 地址组成与分类、子网掩码运算、私有地址、VLSM/CIDR、MAC 与 ARP、Linux 网卡配置（临时+永久）、ping/traceroute 网络测试。

## 一、IP 地址组成

### 1. 点分十进制

- IP 地址由 **4 部分数字**组成，每部分对应 **8 位二进制**，各部分之间用点分开。
- 二进制形式称为"点分二进制"，换算为十进制后称为"点分十进制"。

```text
11000000.10101000.00000001.00000001  →  192.168.1.1
```

### 2. 网络位与主机位

- 每个 IP 地址由两部分组成：
  - **网络地址（NetID）**：表示属于互联网中的哪一个网络；
  - **主机地址（HostID）**：表示属于该网络中的哪一台主机。
- 判断两台主机是否"同网段"，本质是比较两者按子网掩码计算出的**网络号是否相同**——所以结论依赖子网掩码的设置，而不是只看 IP 前几段。

## 二、IP 地址分类（A/B/C/D/E）

### 1. 分类总览

| 类别 | 第一段范围 | 网络位/主机位 | 默认掩码 | 用途 |
|------|-----------|--------------|----------|------|
| A | 1~126 | 1 字节网络 + 3 字节主机 | 255.0.0.0 | 大型网络 |
| B | 128~191 | 2 字节网络 + 2 字节主机 | 255.255.0.0 | 中型网络 |
| C | 192~223 | 3 字节网络 + 1 字节主机 | 255.255.255.0 | 小型网络 |
| D | 224~239 | — | — | 组播（Multicast） |
| E | 240~254 | — | — | 保留实验 |

### 2. A 类地址

- 范围 `1.0.0.0` ~ `126.0.0.0`（0 和 127 保留）。
- 网络地址最高位必须是 **"0"**。
- 例：`10.0.0.1`，第一段是网络号，后三段是主机号。
- 可用 A 类网络 126 个，每个网络可容纳约 **2^24 - 2 ≈ 1677 万**台主机。

### 3. B 类地址

- 范围 `128.0.0.0` ~ `191.255.255.255`。
- 网络地址最高位必须是 **"10"**。
- 例：`172.168.1.1`，前两段网络号，后两段主机号。
- 可用 B 类网络 16382 个，每个网络可容纳 **2^16 - 2 = 65534** 台主机。

### 4. C 类地址

- 范围 `192.0.0.0` ~ `223.255.255.255`。
- 网络地址最高位必须是 **"110"**。
- 例：`192.168.1.1`，前三段网络号，最后一段主机号。
- C 类网络可达 209 万余个，每个网络可容纳 **2^8 - 2 = 254** 台主机。

### 5. D 类与 E 类

- **D 类**：`224.0.0.0` ~ `239.255.255.255`，以 "1110" 开头，专门用于**组播**，一次寻址一组计算机，不指向特定网络。
- **E 类**：`240.0.0.0` ~ `254.255.255.254`，以 "11110" 开头，为将来使用保留。

### 6. 特殊地址（易错点）

| 地址 | 含义 |
|------|------|
| `0.0.0.0` | 当前主机（未指定地址） |
| `255.255.255.255` | 当前子网的受限广播地址 |
| `127.0.0.1` ~ `127.255.255.255` | 环回测试（loopback），不代表真实网络 |
| `169.254.0.0/16` | DHCP 获取失败时的自动私有地址（APIPA） |

> **易错点**：主机位全 0 是网络地址（如 `192.168.1.0`），全 1 是广播地址（如 `192.168.1.255`），二者都不能配给主机，这就是"-2"的由来。

## 三、子网掩码

### 1. 作用

子网掩码用于**区分 IP 地址中的网络号和主机号**：掩码为 1 的位对应网络号，为 0 的位对应主机号。

### 2. 例 1：标准 C 类掩码求网络号和主机号

- IP：`202.197.119.110`，掩码：`255.255.255.0`

```text
IP 二进制       1100 1010.1100 0101.0111 0111.0110 1110
掩码二进制      1111 1111.1111 1111.1111 1111.0000 0000
IP AND 掩码  →  1100 1010.1100 0101.0111 0111.0000 0000   网络号 = 202.197.119.0

掩码取反        0000 0000.0000 0000.0000 0000.1111 1111
IP AND 反掩码→  0000 0000.0000 0000.0000 0000.0110 1110   主机号 = 0.0.0.110
```

### 3. 例 2：变长掩码 255.255.128.0

- IP：`202.197.119.110`，掩码：`255.255.128.0`

```text
IP 二进制       1100 1010.1100 0101.0111 0111.0110 1110
掩码二进制      1111 1111.1111 1111.1000 0000.0000 0000
网络号      →  1100 1010.1100 0101.0000 0000.0000 0000   = 202.197.0.0
主机号      →  0000 0000.0000 0000.0111 0111.0110 1110
```

- 再取 `202.197.118.110` 按同一掩码计算，网络号为 `202.197.64.0`（第三段 118 = 0111 0110，最高位 0，AND 后得 0111 0110？注意 118 的最高位是 0，掩码后落回 0 段/128 段需要按位判断）。
- **结论：两个 IP 是否同一网段，必须按同一掩码分别求网络号比较**，不能凭感觉看前两段。

> **易错点**：变长掩码下"第三段相同"不代表同网段。例如掩码 `255.255.128.0` 时，`119`（0111 0111）和 `118`（0111 0110）的最高位都是 0，实际同属 `202.197.0.0/17` 网段；而若一方第三段 ≥128 则不同段。判断永远以按位 AND 结果为准。

## 四、私有地址

私有地址只在**局域网内部**使用，不会在公网上路由：

| 类别 | 私有地址范围 |
|------|-------------|
| A 类 | `10.0.0.0` ~ `10.255.255.255`（10.0.0.0/8） |
| B 类 | `172.16.0.0` ~ `172.31.255.255`（172.16.0.0/12） |
| C 类 | `192.168.0.0` ~ `192.168.255.255`（192.168.0.0/16） |

## 五、VLSM、超网与 CIDR

### 1. VLSM（可变长子网掩码）

- **子网划分**：通过**增加**掩码中 "1" 的位数实现，把大网切小。

### 2. 超网

- **超网划分**：通过**减少**掩码中 "1" 的位数实现，把多个小网合并。
- 求超网地址的方法同样是把超网掩码与 IP 地址做**按位与**运算。

### 3. CIDR（无类别域间路由）

- 1996 年因特网组织机构发布 **CIDR（Classless Interdomain Routing）**。
- 去掉了 A/B/C 类的概念，采用**无类地址**：不再由地址前几个比特预先定义类别，每个地址只包含网络号部分和主机号部分。
- 表示法：`192.168.1.0/24`，斜线后的数字是掩码中 "1" 的位数（前缀长度）。

## 六、MAC 地址与 ARP

### 1. 查看 MAC 地址

```bash
ifconfig            # 查看所有网卡，含 MAC
ip a                # 同上，推荐
ifconfig eth0       # 单独查看 eth0
```

### 2. 查询 MAC 与 IP 的对应关系（ARP 表）

```bash
arp -a                       # 查看本机 ARP 缓存表
```

### 3. arping 探测

```bash
arping 172.16.70.250                    # 向目标 IP 发 ARP 请求
arping -I enp0s25 10.18.44.208          # 指定网卡探测
```

输出示例：

```text
ARPING 10.18.44.208 from 10.18.44.196 enp0s25
Unicast reply from 10.18.44.208 [00:21:CC:C1:42:4B]  1.113ms
Unicast reply from 10.18.44.208 [00:21:CC:C1:42:4B]  0.975ms
```

- arping 可用于：检测 IP 冲突（同一 IP 出现两个不同 MAC）、查看局域网内 IP 对应的 MAC。

## 七、Linux 网络管理

### 1. 查看 IP 地址

```bash
ifconfig            # 查看所有网卡
ifconfig eth0       # 单独查看 eth0
ip a                # 查看所有网卡（ip addr）
ip a s eth0         # 单独查看 eth0（ip addr show）
ip a l eth0         # 同上（list 是 show 的别名）
```

### 2. 临时配置 IP（ifconfig）

```bash
ifconfig eth0 192.168.2.250/24      # 设置 IP，会覆盖旧 IP
ifconfig eth0:0 192.168.2.251/24    # 设置子接口（一块网卡多个 IP）
```

> **注意**：ifconfig 方式子网掩码可以不写（默认按 A/B/C 类），但**重启网络/系统后失效**。

### 3. 临时增删 IP（ip addr，推荐）

```bash
ip addr add 192.168.2.250/24 dev eth0    # 添加 IP（简写 ip a a）
ip a d 192.168.2.8/24 dev enp0s25        # 删除 IP（del 简写 d）
```

> **易错点**：`ip addr` 方式子网掩码**必须写**；且 `add` 是叠加不会覆盖旧 IP，与 ifconfig 行为不同。

### 4. 启动/关闭网卡

```bash
ifconfig eth0 up        # 启用
ifup eth0               # 启用（读配置文件）
ifconfig eth0 down      # 关闭
ifdown eth0             # 关闭
```

### 5. 永久配置：网卡配置文件（静态 IP）

配置文件路径：`/etc/sysconfig/network-scripts/ifcfg-eth0`

```bash
vim /etc/sysconfig/network-scripts/ifcfg-eth0
```

```ini
DEVICE=eth0                    # 设备名
NAME="System eth0"             # 连接名称（可以不存在）
BOOTPROTO=none                 # none/static：静态；dhcp：动态获取
NM_CONTROLLED=no               # 关闭 NetworkManager 接管
ONBOOT=yes                     # 开机启动网卡
TYPE=Ethernet                  # 以太网类型
HWADDR=00:0c:29:8e:a5:d3       # MAC 地址
IPADDR=172.16.80.252           # IP 地址
NETMASK=255.255.0.0            # 子网掩码（写法一）
PREFIX=24                      # 子网掩码（写法二，前缀长度）
NETWORK=172.16.0.0             # 网络地址
GATEWAY=172.16.0.1             # 网关
DNS1=172.16.0.1                # 第 1 台 DNS
DNS2=114.114.114.114           # 第 2 台 DNS
```

### 6. 永久配置：动态 IP（DHCP）

```ini
DEVICE=eth0
NAME="System eth0"
BOOTPROTO=dhcp                 # 动态获取
ONBOOT=yes
TYPE=Ethernet
```

### 7. 重启网络服务（配置文件修改后必须重启）

```bash
systemctl restart network           # RHEL7
/etc/init.d/network restart         # RHEL5/6
service network restart             # RHEL5/6
```

> **易错点**：改了配置文件不重启服务 = 不生效。RHEL8/CentOS8 之后用 `nmcli connection reload && nmcli connection up eth0`。

## 八、网络测试工具

### 1. ping

- 用途：测试主机之间网络的连通性，使用 **ICMP** 协议发出 ECHO 请求并等待回应，可测连通性、速度、稳定性。

```bash
ping 192.168.1.9       # 开始持续 ping；Ctrl + c 停止
ping -c 4 192.168.1.9  # 只 ping 4 次
```

### 2. ping 常用选项

| 选项 | 作用 |
|------|------|
| `-c <次数>` | ping 指定次数后停止 |
| `-i <秒>` | 设定发送间隔，默认 1 秒一次 |
| `-I <网卡>` | 指定网卡接口或源地址 |
| `-n` | 不把 IP 解析成主机名，直接输出数值 |
| `-f` | 极限检测，快速连续 ping（约 100 次/秒） |
| `-q` | 不显示过程，只显示开头结尾统计 |
| `-s <字节>` | 指定发送数据字节数，默认 56 字节 + 28 字节 ICMP 头 = 84 字节 |
| `-t <ttl>` | 设置 TTL 存活数值 |
| `-R` | 记录路由过程（IP 头限制最多 9 个路由） |
| `-W <毫秒>` | 设置超时时间 |
| `-w <秒>` | 设置 deadline，超时自动结束 |
| `-b` | 允许 ping 广播地址 |
| `-M do` | 禁止分片（可用于探测路径 MTU） |

> **知识点**：数据包最大 65507 字节（Linux）/ 65500（Windows），因为包头+内容不能超过 65535。

### 3. traceroute：路由追踪

- 作用：追踪数据包从本机到目标主机走过的路径（Windows 中对应 `tracert`）。
- 每跳默认探测 3 次，输出每跳的设备域名/IP 和三次延迟（ms）。

```bash
traceroute www.qfedu.com          # 基本用法
yum -y install traceroute         # 未安装时先安装
traceroute -m 10 www.baidu.com    # 设置最大跳数 10
traceroute -n www.baidu.com       # 只显示 IP，不做 DNS 解析
traceroute -p 6888 www.baidu.com  # 指定探测包 UDP 端口 6888
traceroute -q 4 www.baidu.com     # 每跳发送 4 个探测包
traceroute -w 3 www.baidu.com     # 等待响应超时设为 3 秒
traceroute -r www.baidu.com       # 绕过正常路由表直连（报网络不可达属正常）
```

### 4. traceroute 工作原理（重点）

1. traceroute 先发送 **TTL=1** 的 IP 数据报（每次 3 个 40 字节包，含源地址、目的地址、时间戳）。
2. 路径上第一个路由器收到后把 TTL 减 1，TTL 变 0，路由器丢弃该包并回送 **ICMP time exceeded** 消息。
3. traceroute 收到消息，得知第一个路由器在路径上；再发 TTL=2 的包发现第二个路由器……逐次 TTL 加 1。
4. 到达目的地时主机不会回 ICMP time exceeded，怎么判断到达？
   - traceroute 发送的 UDP 包目的端口选择 **30000 以上**一般程序不会用的端口；
   - 目的主机收到后回送 **ICMP port unreachable**，traceroute 收到即知到达终点。
5. 所以 traceroute 服务端不需要任何守护进程（Daemon）。

### 5. traceroute 输出解读（易错点）

- 每行三个时间是同一跳三次探测的往返时间。
- 出现 `* * *`：可能是防火墙封了 ICMP/UDP 返回信息，拿不到回应。
- 某一跳延迟大：网关阻塞、设备本身慢，或 DNS 解析慢（可加 `-n` 避免 DNS 解析）。
- 局域网跨网段排障、远程访问服务器异常时，用 traceroute 定位是主机问题还是网关问题，也可把结果提交 IDC 服务商。

## 十、易错点汇总

- 判断同网段必须"同掩码、分别算、比网络号"，只看 IP 前几段会出错。
- `127.0.0.0/8` 和 `169.254.0.0/16` 是保留段，不用于真实组网。
- `ifconfig` 配 IP 会覆盖旧 IP、掩码可省略；`ip addr add` 是叠加、掩码必须写。
- 配置文件修改后必须 `systemctl restart network` 才生效。
- ping 大包上限 65507（Linux），超过会被协议限制拒绝。
- traceroute 到达目的地的标志是 ICMP port unreachable，而非 time exceeded。
