# 计划任务与服务器远程管理

> 千锋 Linux 运维课程第 5 天。两条主线：**计划任务**（at / cron，让系统在指定时间自动干活）与**服务器远程管理**（SSH、scp、lrzsz，以及企业级堡垒机 Jumpserver 的完整部署）。

## 一、计划任务

### 1. 概念解析

在 Linux 中，除了用户即时执行的命令操作外，还可以配置在**指定时间、指定日期**执行预先计划好的系统管理任务，例如：

- 定期备份
- 定期采集监测数据
- 定期清理日志、定期巡检等

RHEL6 系统中默认已安装 **at、cronie** 软件包，通过两个系统服务实现计划任务功能：

| 服务 | 作用 | 设置命令 | 类型 |
| ---- | ---- | -------- | ---- |
| `atd` | 一次性计划任务 | `at` | 到点执行一次 |
| `crond` | 周期性计划任务 | `crontab` | 按规则循环执行 |

### 2. 计划任务分类

- **一次性计划任务**：到点执行一次，用 `at` 设置（atd 服务）
- **循环型计划任务**：按时间规则反复执行，用 `crontab` 设置（crond 服务）
- **系统级计划任务**：管理员维护，写在 `/etc/crontab`、`/etc/cron.d/` 中
- **用户级计划任务**：每个用户自己的任务，用 `crontab -e` 设置，存放在 `/var/spool/cron/用户名`

### 3. crontab 服务管理

```bash
# 安装软件
yum -y install crontabs

# rhel5/6 查看与启动
/etc/init.d/crond status
/etc/init.d/crond start

# rhel5/6 开机启动
chkconfig crond on

# rhel7 及以后（systemd）
systemctl start crond.service
systemctl status crond.service
systemctl enable crond.service
```

### 4. 用户级计划任务：crontab 命令

```bash
# 为指定用户创建计划任务（-u 指定用户，不写默认当前用户）
crontab -u 用户 -e

# 当前用户编辑计划任务（最常用）
crontab -e
```

任务内容分两部分，**用空格分开**：

1. **时间部分**：5 个字段（分 时 日 月 周）
2. **动作部分**：到时间要执行的命令或脚本

### 5. 时间字段与写法

5 个字段依次为：

| 字段 | 分钟 | 小时 | 日 | 月 | 周 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 范围 | 0-59 | 0-23 | 1-31 | 1-12 | 0-7 |

> 周字段 0 和 7 都表示周日；详细取值可查手册：`man 5 crontab`。

特殊符号：

| 符号 | 含义 | 示例 |
| ---- | ---- | ---- |
| `*` | 每……（该字段所有取值） | `* * * * *` 每分钟 |
| `,` | 取不同的时间点 | `1,5,9` 第 1、5、9 分 |
| `-` | 表示范围 | `8-12` 8 到 12 分 |
| `*/n` | 每隔 n（步长） | `*/5` 每 5 分钟 |

典型写法示例：

```bash
5      10 * * *      # 每天 10:05
5      10 8 * *      # 每月 8 号 10:05
1      5  7 * 5      # 每周五 05:01
1,5,9  *  * * *      # 每小时的第 1、5、9 分钟
8-12   *  * * *      # 每小时的 8~12 分
5-20,40 * * * *      # 每小时的 5~20 分和第 40 分
8-12,20-25 * * * *   # 每小时的 8~12 分和 20~25 分
*/5    *  * * *      # 每 5 分钟
```

动作部分要求：把规定时间要执行的命令写在这里（**包括脚本，最常用**），**命令最好写绝对路径**。

### 6. 查看 / 删除计划任务

```bash
# 查看当前用户任务
crontab -l
# 查看指定用户任务
crontab -l -u 用户名
# 方法二：直接看任务文件（root 用户的任务文件）
cat /var/spool/cron/root

# 删除当前用户全部任务（-r 删除）
crontab -r
# 删除指定用户任务
crontab -r -u wing
# 只删某几条：进入编辑界面手动删行
crontab -e -u tom
# 方法二：直接删任务文件
rm -f /var/spool/cron/root
```

> 慎用 `crontab -r`：它删除的是该用户**全部**任务，生产环境建议先 `crontab -l > /root/cron.bak` 备份。

### 7. 计划任务权限控制

```bash
cat /etc/cron.deny    # 黑名单：写入的账户不允许执行 crontab
cat /etc/cron.allow   # 白名单：存在时，只有写入的账户允许执行 crontab
```

规则要点：

- `cron.deny` 存在 → 里面的用户**不能**用 crontab，其他人都可以
- `cron.allow` 存在 → **只有**里面的用户能用，其他人都不行
- **allow 优先**：只要 allow 文件存在，不管 deny 是否存在，都只允许 allow 里的用户

### 8. 一次性计划任务：at（补充）

```bash
yum -y install at
systemctl start atd && systemctl enable atd

at 20:00                     # 指定 20:00 执行
at> reboot                   # 交互输入要执行的命令
at> <EOT>                    # Ctrl+D 结束输入

at now + 10 minutes          # 10 分钟后执行
at -f /root/task.sh 22:00    # 到点执行脚本

atq                          # 查看未执行的任务队列
atrm 3                       # 删除第 3 号任务
```

### 9. 系统级计划任务（补充）

```bash
# /etc/crontab 与用户任务的区别：多一个"执行用户"字段
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
# 分 时 日 月 周  执行用户  命令
0  2  *  *  *   root  /usr/bin/backup.sh
```

- `/etc/cron.d/`：放置独立的任务文件，格式同 `/etc/crontab`
- `/etc/cron.{hourly,daily,weekly,monthly}`：把脚本丢进对应目录，即按小时/天/周/月自动执行

### 10. 计划任务实战与注意事项

常见任务示例：

```bash
# 每天凌晨 2:30 备份数据库
30 2 * * * /usr/bin/mysqldump -uroot -p'密码' --all-databases > /backup/db_$(date +\%F).sql

# 每周日 23:00 清理 7 天前的应用日志
0 23 * * 0 /usr/bin/find /var/log/myapp -mtime +7 -name "*.log" -delete

# 每 5 分钟采集一次系统负载
*/5 * * * * /usr/bin/uptime >> /var/log/load.log
```

注意事项：

- 命令、脚本一律用**绝对路径**；脚本要加执行权限（`chmod +x`）
- `%` 在 crontab 中有特殊含义，需转义为 `\%`
- 任务有输出会发邮件给对应用户，通常重定向丢弃：`>/dev/null 2>&1`
- 修改任务后**不需要重启 crond**，下一分钟即生效
- cron 的环境变量与登录 shell 不同，脚本中需要的变量在脚本内自行 source

## 二、远程管理

### 1. SSH 服务基础

SSH 是 Linux 服务器远程管理的标准方式，默认端口 **22**。

涉及软件包：

- `openssh`：公共组件
- `openssh-server`：提供服务端
- `openssh-clients`：提供客户端

```bash
yum install openssh* -y
```

服务器端启动与验证：

```bash
systemctl start sshd
lsof -i:22            # 确认 22 端口已被 sshd 监听
```

实验环境临时关闭防火墙和 SELinux：

```bash
systemctl stop firewalld
setenforce 0
```

客户端远程登录：

```bash
# -X 开启图形转发；-p 指定端口；用户名@主机
ssh -X tom@10.18.44.208 -p 2222

# 不写用户名时默认使用当前用户，默认端口 22
ssh 10.18.44.208
```

> 注意：如果登录账户没有密码，默认不能登录（`PermitEmptyPasswords no`）。

### 2. 免密登录（SSH 密钥认证）

在 client 上操作：

```bash
# 1. 产生公钥和私钥（一路回车即可）
ssh-keygen
#    生成：~/.ssh/id_rsa（私钥，保密）
#          ~/.ssh/id_rsa.pub（公钥）

# 2. 拷贝公钥给对方服务器
ssh-copy-id -i 10.18.44.208
```

原理：客户端用私钥签名，服务器用 `~/.ssh/authorized_keys` 中保存的公钥验证，配对成功即免密登录。

补充要点（避免免密失效）：

- `~/.ssh` 目录权限 `700`，`authorized_keys` 权限 `600`
- 私钥不能泄露；多人共用的服务器建议每人一对密钥

### 3. 直接执行远程命令

```bash
# 登录后在远端执行一条命令，结果返回本地
ssh 10.18.44.208 "reboot"
```

### 4. 远程拷贝：scp

scp 基于 SSH 协议传输，安全可靠；需要先安装客户端（openssh-clients）。

核心规则：**谁是远程谁加 IP**。

```bash
# 本地文件 → 远程
scp /a.txt 192.168.2.108:/

# 远程文件 → 本地
scp 192.168.2.108:/a.txt ./

# 远程 → 另一台远程
scp 192.168.2.108:/a.txt 192.168.2.109:/

# -P 指定端口（大写 P）；拷贝目录加 -r
scp -P 2222 -r /data/dir 192.168.2.108:/tmp
```

### 5. sshd 服务端常用配置

```bash
vim /etc/ssh/sshd_config
```

关键参数：

```conf
Port 22                      # 监听端口，可改成其他端口提高安全性
ListenAddress 192.168.2.8    # 只监听指定地址
PermitRootLogin yes          # 是否允许 root 直接登录（生产建议 no）
MaxSessions 10               # 最大并发会话数
PermitEmptyPasswords no      # 禁止空密码登录
```

修改后重启生效：

```bash
systemctl restart sshd
```

> 端口修改后登录需 `ssh -p 新端口`，并确认防火墙放行新端口。

### 6. rz / sz 命令（lrzsz）

在支持 ZMODEM 的终端工具（Xshell、SecureCRT 等）中实现本地与服务器之间的文件传输，root 登录后安装：

```bash
yum install -y lrzsz
```

使用：

```bash
sz filename    # 服务器发送文件到本地（本地弹出保存框）
rz             # 本地上传文件到服务器（弹出选择框选择要上传的文件）
```

### 7. 远程桌面管理

- 图形界面远程可用 VNC、Xmanager 等工具
- 生产运维以 SSH 字符终端为主，桌面方式仅特殊场景使用

## 三、Jumpserver 堡垒机

Jumpserver 是开源堡垒机（跳板机），用于**集中管控服务器登录入口**，提供：身份认证、资产授权、会话审计、命令记录、录像回放。

整体组件（1.5.x 版本）：

| 组件 | 作用 | 端口 |
| ---- | ---- | ---- |
| jumpserver 核心（jms） | 主程序、API、Web | 8080 |
| koko | SSH/Web 终端（替代旧版 coco） | 2222 / 5000 |
| guacamole | RDP/VNC 远程桌面（HTML5） | 8081 |
| luna | Web Terminal 前端页面 | 静态资源 |
| nginx | 统一入口反向代理 | 80 |
| Redis / MariaDB | 缓存 / 数据库 | 6379 / 3306 |

### 1. 环境配置

```bash
getenforce                       # 确认 SELinux 为 Disabled
systemctl stop firewalld.service

# 修改字符集：否则日志打印中文可能报 input/output error
localedef -c -f UTF-8 -i zh_CN zh_CN.UTF-8
export LC_ALL=zh_CN.UTF-8
echo 'LANG="zh_CN.UTF-8"' > /etc/locale.conf

# 安装基础依赖
yum -y install wget sqlite-devel xz gcc automake zlib-devel openssl-devel epel-release git
```

### 2. 编译安装 Python 并创建虚拟环境

```bash
# 注意：必须编译安装，否则安装 Python 库依赖时会有麻烦
```

### 6. 配置 config.yml

```bash
cd /opt/jumpserver
cp config_example.yml config.yml

# 生成随机 SECRET_KEY（50 位）
SECRET_KEY=`cat /dev/urandom | tr -dc A-Za-z0-9 | head -c 50`
echo "SECRET_KEY=$SECRET_KEY" >> ~/.bashrc

# 生成随机 BOOTSTRAP_TOKEN（16 位）
BOOTSTRAP_TOKEN=`cat /dev/urandom | tr -dc A-Za-z0-9 | head -c 16`
echo "BOOTSTRAP_TOKEN=$BOOTSTRAP_TOKEN" >> ~/.bashrc
```

用 sed 批量写入配置：

```bash
sed -i "s/SECRET_KEY:/SECRET_KEY: $SECRET_KEY/g" /opt/jumpserver/config.yml
sed -i "s/BOOTSTRAP_TOKEN:/BOOTSTRAP_TOKEN: $BOOTSTRAP_TOKEN/g" /opt/jumpserver/config.yml
sed -i "s/# DEBUG: true/DEBUG: false/g" /opt/jumpserver/config.yml
sed -i "s/# LOG_LEVEL: DEBUG/LOG_LEVEL: ERROR/g" /opt/jumpserver/config.yml
sed -i "s/# SESSION_EXPIRE_AT_BROWSER_CLOSE: false/SESSION_EXPIRE_AT_BROWSER_CLOSE: true/g" /opt/jumpserver/config.yml
```

确认数据库配置项（`sed -n '/^DB_/p' config.yml`）：

```yaml
DB_ENGINE: mysql
DB_HOST: 127.0.0.1
DB_PORT: 3306
DB_USER: jumpserveradmin
DB_PASSWORD: jumpserverpwd
DB_NAME: jumpserver
```

### 9. 部署 guacamole（远程桌面组件）

guacamole 是基于 HTML5 和 JavaScript 的 VNC 查看器，用于连接 Windows/RDP/VNC 资产。

Docker 方式：

```bash
docker run --name jms_guacamole -d -p 8081:8081 \
  -e JUMPSERVER_SERVER=http://$Server_IP:8080 \
  -e BOOTSTRAP_TOKEN=$BOOTSTRAP_TOKEN \
  jumpserver/jms_guacamole:1.5.5
```

手工部署核心步骤：

```bash
cd /opt
git clone --depth=1 https://github.com/jumpserver/docker-guacamole.git
cd /opt/docker-guacamole && tar xf guacamole-server-1.0.0.tar.gz
cd guacamole-server-1.0.0

autoreconf -fi

ln -sf /opt/docker-guacamole/guacamole-auth-jumpserver-1.0.0.jar /config/guacamole/extensions/
ln -sf /opt/docker-guacamole/root/app/guacamole/guacamole.properties /config/guacamole/

# guacamole 环境变量（建议同时写入 ~/.bashrc）
export JUMPSERVER_SERVER=http://127.0.0.1:8080   # jumpserver 访问地址
export BOOTSTRAP_TOKEN=******                    # 与 config.yml 一致
export JUMPSERVER_KEY_DIR=/config/guacamole/keys
export GUACAMOLE_HOME=/config/guacamole

/etc/init.d/guacd start
sh /config/tomcat9/bin/startup.sh
```

### 11. 配置 nginx 统一入口

```bash
mkdir /usr/local/nginx/conf/conf.d
vim /usr/local/nginx/conf/conf.d/jumpserver.conf
```

核心配置（精简自课件）：

```nginx
server {
    listen 80;
    server_name bastion.qf.com;
    client_max_body_size 100m;          # 录像及文件上传大小限制

    location /luna/ {
        try_files $uri / /index.html;
        alias /opt/luna/;               # luna 安装路径，改目录需同步修改
    }
    location /media/ {
        add_header Content-Encoding gzip;
        root /opt/jumpserver/data/;     # 录像位置
    }
    location /static/ {
        root /opt/jumpserver/data/;     # 静态资源
    }
    location /koko/ {
        proxy_pass       http://localhost:5000;
        proxy_buffering off;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    location /guacamole/ {
        proxy_pass       http://localhost:8081/;
        proxy_buffering off;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $http_connection;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Host $host;
    }
    location /ws/ {
        proxy_pass http://localhost:8070;
        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Host $host;
    }
    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

主配置加载子配置并检查语法：


### 13. 排错经验

- **koko 不在线 / guacamole 注册失败**：多数为**版本不匹配**，镜像 tag 必须与 Jumpserver 版本一致（如都用 1.5.5）；按相同 tag 重建容器即可注册成功
- 生产建议容器绑定本机回环 + 开机自启：

```bash
docker run --name jms_koko -d -p 2222:2222 -p 127.0.0.1:5000:5000 \
  -e CORE_HOST=http://$Server_IP:8080 -e BOOTSTRAP_TOKEN=$BOOTSTRAP_TOKEN \
  --restart=always jumpserver/jms_koko:1.5.5

docker run --name jms_guacamole -d -p 127.0.0.1:8081:8080 \
  -e JUMPSERVER_SERVER=http://$Server_IP:8080 -e BOOTSTRAP_TOKEN=$BOOTSTRAP_TOKEN \
  --restart=always jumpserver/jms_guacamole:1.5.5
```

- 自动获取本机真实 IP 的实用命令：

```bash
Server_IP=`ip addr | grep 'state UP' -A2 | grep inet | egrep -v '(127.0.0.1|inet6|docker)' | awk '{print $2}' | tr -d "addr:" | head -n 1 | cut -d / -f1`
```

- 用 `docker ps` 确认两个容器均为 Up 状态、端口映射正确
- 排错参考：<https://docs.jumpserver.org/zh/docs/faq.html>

## 五、要点速记

- 计划任务两套体系：`at`（一次性）与 `crontab`（周期性），对应 `atd`、`crond` 服务
- crontab 时间五字段：**分 时 日 月 周**；符号 `*`、`,`、`-`、`*/n`
- 权限控制：`cron.allow` 优先于 `cron.deny`
- 任务文件位置：`/var/spool/cron/用户名`；`crontab -r` 删全部任务，操作前先备份
- SSH 免密：`ssh-keygen` 生成密钥 → `ssh-copy-id` 推公钥
- scp 规则：**谁是远程谁加 IP**；`-P` 端口、`-r` 目录
- Jumpserver 组件：core + koko + guacamole + luna，nginx 80 统一入口，各组件 `BOOTSTRAP_TOKEN` 必须一致
