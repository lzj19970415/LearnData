# 11 智能体安全入门（能"动手干活"的 AI 怎么管）

> 前面的 AI 是"聊天"的。这一章的 AI 是**"会动手干活"的**（智能体 Agent）——能查数据、能调工具、能执行动作。能动手，就更危险，更要管。

## 一、先说人话：智能体和普通 AI 差在哪

- **普通 AI**：只会"说"，出问题最多是"说错话"。
- **智能体（Agent）**：会"做"——能调 API、查数据库、发邮件、执行命令。出问题就是"**做错事**"（删错数据、把机密发出去了）。

> 一句话：**因为智能体"能动手"，它的安全就不再是"管住嘴"，而是"管住手"——它到底被允许干什么、干得对不对、干过什么。**

## 二、管智能体的"三把锁"（核心框架）

```
① 权限：它能干什么（管住能力范围）
② 行为：它做得对不对（管住动作别越界）
③ 日志：它做过什么（管住留痕）
```

**人话**：就像给一个"实习生"交代工作——**先告诉他只能做什么（权限），干活时盯着别越界（行为控制），干完要留记录（日志）。**

### 锁1：权限（最小权限）

- **默认拒绝**：没明确允许的，一律不让做。
- **最小权限**：只给"完成当前任务"所需的最小范围，**别给万能账号**。
- **权限随会话**：这次任务的权限，做完就收回，别一直留着。

**人话**：**"能查数据库就只给查询权限，别连删改权限一起给；一次任务干完权限就收回。"**

### 锁2：行为控制（护栏钩子 + 沙箱）

- **护栏钩子（Hook）**：在智能体"要动手前"**插一道检查**：

```
 输入护栏（看它要做啥）→ 工具调用前护栏（这操作危险吗？删库？外发？）→ 执行 → 输出护栏（带敏感数据了吗）
```

- **沙箱（Sandbox）**：高风险动作（执行代码、开附件）**丢进隔离环境跑**，出事也只影响沙箱，不影响真系统。

**人话**：**它想做高风险动作时，先问一道、再隔离着做。**

### 锁3：日志审计

- 记录**全链路**：谁让它做的、它输出了什么、它调了哪个工具、结果如何。
- 目的：事后能追"它到底有没有把敏感数据发出去"。

**人话**：**给智能体的每一步都"记账"，出问题能翻旧账。**

## 三、FinBot 四关（理解"智能体怎么被攻击/怎么防"）

用个小实验理解：一个智能体助理，攻击者连闯四关。

```
① 侦察：骗它说出"你有什么工具、权限、系统指令"
     → 防：提示词不外泄、工具/权限不对外暴露
② 策略绕过：骗它违反自身规则（角色扮演/伪指令）
     → 防：模型层语义护栏
③ 数据外渗：诱导它把机密通过 URL/邮件带出去
     → 防：外发域名白名单、输出内容检测
④ 护栏防御：把前三关全拦下，并留审计日志
```

**人话**：前三关是"攻击者怎么骗智能体"，第四关是"你怎么把它骗的拦下来"。**会防第四关，就掌握前面所有思路了。**

## 小结（人话速记）

1. 智能体"会动手"→ 比聊天 AI 更危险，**要管它"能做什么、做对没、做过啥"**。
2. 三把锁：**最小权限 + 行为护栏（钩子/沙箱）+ 日志审计**。
3. 钩子位置：**输入前、动手前、输出后** 三个卡点。
4. FinBot 四关：**侦察 → 绕过 → 外渗 → 防御**。
5. 高风险动作**先确认、再沙箱隔离跑**。

> 动手建议：用任何智能体平台（或开源框架）搭个能查库的 Agent，试一下"让它读一个文件后把内容写成 URL 参数"，看它会不会真干——再想想"最小权限+白名单"怎么挡住它。
