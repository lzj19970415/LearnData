# 02 日志分析入门（看懂"案发现场的录像"）

> 上一章我们知道了"要查日志"。这一章就讲：**日志到底是什么、长什么样、怎么从里面发现坏蛋。**

## 一、先说人话：日志是什么

日志就是**服务器自己记的流水账**。你访问一个网站、登录一台服务器、数据库查了条数据，服务器都会"记一笔"，存成日志。

- 日志 = 案发现场的**监控录像**：谁（IP）、什么时候（时间）、干了什么（干了什么）都被录下来了。
- 攻击者就算破坏得再彻底，**日志往往也留着**（或者"清空日志"这个动作本身就是最大的破绽）。
- 所以做安全，**先学会看日志**，就像破案先学会看录像。

> ⚠️ 重要提醒：日志分析**第一件事是先做副本**，`cp access.log /backup/`，然后**在副本上分析**，别动原文件。原文件是证据。

## 二、先认识几种日志（记一下它们在哪个文件）

| 类型 | 在哪 | 记什么 |
| --- | --- | --- |
| 系统日志（Windows） | 事件查看器 | 登录、账户、服务 |
| 系统日志（Linux） | /var/log/secure、/var/log/messages | SSH 登录、系统事件 |
| Web 访问日志（Nginx） | /var/log/nginx/access.log | 谁访问了网站、访问了什么 |
| Web 访问日志（Apache） | /var/log/httpd/access_log | 同上 |
| 数据库日志（MySQL） | general_log（默认关） | 所有 SQL 语句 |

**人话**：攻击者打网站 → 留下访问日志；打 SSH → 留下 secure；从数据库拖数据 → 留下 general_log（前提是开了）。

## 二、学会看懂一行 Web 日志（重点）

Nginx/Apache 的访问日志一行通常是这个格式（拆开看）：

```
IP - 用户 [时间] "方法 路径 协议" 状态码 大小 "从哪来" "用什么工具(UA)"
```

例：
```
192.168.1.10 - - [19/Oct/2026:10:30:22] "GET /admin/login.php HTTP/1.1" 200 1234 "http://x.com" "Mozilla/5.0"
```

**这几个字段是什么意思（人话）**：

- **IP**：谁发起的
- **方法**：GET（看页面）/ POST（提交数据，比如登录、上传）
- **路径**：访问了哪个页面
- **状态码**：200=成功、404=没有、**500=服务器报错**、403=被拒绝
- **UA**：用的什么浏览器/工具

**怎么看异常（人话）**：

1. **状态码 404 一大堆** → 有人在**扫你的目录**（找漏洞）。
2. **状态码 500 + 路径里带 `'` `union` `sleep`** → 在**试 SQL 注入**（因为他的坏代码让服务器报错了）。
3. **同一个 URL 频繁 POST + 页面很冷门（比如 /uploads/x.php）** → 大概率是**后门在偷偷执行**（Webshell）。
4. **UA 是 sqlmap / sqlmap/1.x 之类** → 用自动化工具在注入。

## 三、分析的三要素（记住这个就好上手）

```
时间 + IP + 特征（payload/UA）
```

- **先按时间**看：攻击往往是"突然开始、密集一阵"。
- **再按 IP 聚**：把同一个 IP 的所有请求列出来（awk / Excel 透视都行），看它的行为全貌。
- **最后看特征**：url 里的特殊字符、UA、状态码。

**例**：`awk '{print $1}' access.log | sort | uniq -c | sort -rn | head` → 就能列出"访问最多的 IP 是哪些"，攻击者的 IP 往往排前面。

## 六、数据库日志（一般怎么用）

- MySQL 的 **general_log** 默认是**关**的。排查 Web 攻击时，打开它就能看到**完整 SQL**，一眼看出有没有注入/拖库。
- 打开方式（了解即可，上线别乱开，会拖慢性能）：
  ```sql
  SET GLOBAL general_log = ON;
  ```

## 七、小结（人话速记）

1. 日志=录像，**先备份再分析**。
2. Web 日志三件套：**时间 + IP + 特征**。
3. 状态码 **404/500** 和 **POST 冷门路径 200** 是最值得看的。
4. 带 `'`、`union`、`sleep` 的 URL = 注入尝试。
5. SQL 拖库看 **general_log**。

> 动手建议：把你自己网站的 access.log 打开，按上面拆字段看懂一行，再 `awk` 数一下哪些 IP 最频繁——你就入门了。
