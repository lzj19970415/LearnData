# 02 日志分析基础（系统/中间件/数据库）

> 对应 10月19日上午后半：系统、中间件、数据库日志分析。

## 一、日志分析总思路【背】

```
看什么日志 → 按时间线串起来 → 找攻击特征 → 还原攻击链
```

四步：**定位日志源 → 缩小时间范围（应急开始前后）→ 搜特征关键词 → 关联多源日志交叉验证。**

## 二、系统日志

### Windows（详见 01 篇事件 ID 表）【背】

- 位置：`C:\Windows\System32\winevt\Logs\`（Security.evtx、System.evtx）
- 入口：`eventvwr.msc`
- 重点：4625 大量出现=爆破；4720+7045 组合=入侵后建后门；1102=抹日志。
- 4624 里看 **LogonType**：**10=远程桌面**、3=网络登录、2=本地交互（考过）。

### Linux【背】

| 文件 | 内容 |
| --- | --- |
| /var/log/secure（auth.log） | SSH 认证成功/失败 |
| /var/log/messages | 系统事件 |
| /var/log/cron | 计划任务执行记录 |
| /var/log/lastlog、wtmp、btmp | 登录记录（用 last/lastb 看） |

- SSH 爆破特征：`Failed password for ... from x.x.x.x` 大量重复。

## 三、中间件日志（重点）【背】

### Nginx

- 访问日志：`/var/log/nginx/access.log`（默认格式 combined）
- 错误日志：`/var/log/nginx/error.log`

### Apache

- 访问日志：`/var/log/httpd/access_log`（RHEL 系）/ `/var/log/apache2/access.log`（Debian 系）
- 错误日志：`error_log` / `error.log`

### 访问日志字段（combined 格式）【背】

```
IP - 用户 [时间] "请求方法 路径 协议" 状态码 响应大小 "Referer" "UA"
```

**状态码含义**：200 成功、302 跳转、403 禁止、404 不存在、**500 服务器错误（报错注入常伴随）**。

## 四、数据库日志【背】

| 日志 | 用途 |
| --- | --- |
| MySQL general_log | 通用查询日志（**开关型**，排查 Web 攻击时打开，能看到完整 SQL） |
| MySQL slow_log | 慢查询日志 |
| MySQL binlog | 增量操作日志（恢复/取证用） |
| MySQL error log | 错误日志 |

排查口诀：**Web 攻击看 general_log**（记完整 SQL，搜 `select ... from ... union`、`information_schema`、`load_file`）。

## 五、攻击特征关键词清单【背，必考】

### SQL 注入特征

```
' 、 and 1=1 、 or 1=1 、 union select 、 information_schema 、
load_file 、 into outfile 、 sleep( 、 benchmark( 、 updatexml( 、 extractvalue(
```

### 扫描器/工具特征

- sqlmap UA：`sqlmap/1.x` 或大量变形 UA
- 菜刀/蚁剑/冰蝎：POST 请求**body 加密大段字符**（base64/hex），页面为固定脚本名

### Webshell 行为特征

- 同一 URL **POST 频繁**且响应 200
- 访问**冷门路径**（如 `/uploads/x.php`、`/static/x.jsp`）返回 200
- URL 带命令执行函数：`cmd=`、`pass=`、`whoami`

### 文件上传攻击

- access.log 里出现**上传目录下新文件被访问**且 UA 是工具（如 `AntSword`）

## 六、高频考点提示

1. **三个必背位置**：Nginx `/var/log/nginx/access.log`、Apache `/var/log/httpd/access_log`、SSH 爆破在 `secure`。
2. **general_log** 是数据库排查核心：默认关，开启后记全量 SQL。
3. 状态码 200+POST+冷门路径 = Webshell 三特征。
4. 分析顺序：**先看时间、再串 IP、最后看 payload**——三要素（时间、IP、payload）齐了才算证据链。
5. 日志要做**副本取证**：`cp access.log /backup/` 再分析，别在原文件上操作。
