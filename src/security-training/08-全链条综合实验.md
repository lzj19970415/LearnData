# 08 综合实战（把前面学的串起来打一遍）

> 前面你是"拆开"学的（查日志、看漏洞、加固、溯源）。这一章把它们**串成一条完整的流程**——这也是你将来"真正做安全"时的整套动作。

## 一、人话：一套完整的安全处置是什么样

把整个流程想成一次"体检 + 治病"：

```
发现身体有异常（体检发现指标不对）
   ↓
先搞清病在哪（排查：进程/账户/日志）
   ↓
把病灶清掉（清理后门）
   ↓
把环境治好（加固）
   ↓
查是不是还有别的问题、往后怎么预防（溯源 + 复测）
```

对一台服务器/网站，就对应下面这套**五段式**（背下来，做事照这个来）：

```
① 攻击利用（先确认是漏洞攻击的）→ ② 修复（堵上）→ ③ 加固（加锁）
→ ④ 应急排查（查还有没有别的后门）→ ⑤ 溯源（还原过程 + 留证）
```

## 二、五段式每段到底干什么（人话）

| 阶段 | 干什么 | 用什么（对应章节） |
| --- | --- | --- |
| ① 攻击利用 | 复现/确认是哪个漏洞被打 | 03 Web漏洞 |
| ② 修复 | 把那个漏洞堵上 | 07 加固（参数化、白名单…） |
| ③ 加固 | 顺手把同类隐患一起堵 | 07 三处加固 |
| ④ 排查 | 看有没有留下 webshell/后门/账户 | 01 应急响应 |
| ⑤ 溯源 | 还原怎么进来的、留证据 | 06 溯源 |

**人话**：这不是五个独立步骤，是一个"**发现→堵→查→防→留证**"的闭环。做完 ⑤，才算整件事处理完。

## 三、怎么做才"算处理完"（关键）

每完成一段，**要留证据**（截图/命令/结果），尤其是：

```
 ① 漏洞：留 payload 和攻击效果截图
 ② 修复：留"原攻击打不进来"的截图
 ④ 排查：列出发现的可疑项 + 删除动作
 ⑤ 溯源：输出"时间 + IP + 动作"时间线
```

**为什么留证**：一是证明你做了，二是别人复核/考核能看到，三是出事有据可查。

## 四、实战中容易踩的坑（先打预防针）

1. **只发现不修**：找到漏洞就算了 → 等于没做。
2. **只修不复测**：改了配置没验证 → 很可能没堵住。
3. **一上来就杀后门**：没先排查/没留证，容易漏掉更多或破坏证据。
4. **忘了留证**：做完啥也没留，白做。
5. **顺序乱了**：急着"堵漏"却把"排查"省了。

## 小结（人话速记）

1. 完整流程是**闭环**：发现 → 修复 → 加固 → 排查 → 溯源。
2. 每一段都要**留证据**（截图/命令/时间线）。
3. 修完要**复测**；做完要**留证**。
4. 别贪快乱顺序——**先排查再清理**。
