09 案例答题总纲与评分套路（先学会拿分，再谈学懂）

学之前先记一句大实话：下午题不是作文比赛，是踩点给分的"填空题"。 阅卷老师在你的答案上停留的时间以秒计，他不是在欣赏文采，而是在找关键词——扫到"参照完整性"给一分，扫到"传递函数依赖"再给一分。你写了三行没有关键词，不如写一行全踩在点上的。

所以这一篇不教知识点，只教一件事：怎么把"会的东西"变成"卷面上的分"。 知识本身请回去翻 01~08 篇，案例四大件的实战演练见 10 案例-ER图与关系模式设计、11 案例-SQL建表与查询、12 案例-候选键与范式分解、13 案例-事务与并发调度。

一、先认清对手：下午卷长什么样

项目内容
科目名称应用技术（大家习惯叫"下午题"或"案例分析"）
题型问答题 + 设计题：写 SQL、画 ER 图、求候选键、判范式、设计备份方案……
满分与及格线满分 75 分，45 分及格；必须与上午"基础知识"同一次同时过线，一科挂全作废
考试形式机考，全部在电脑上打字作答（设计题可用绘图工具或文字描述）
大题数量近年多为 4~5 道必答大题（每道大题再拆成若干小问；具体以当次试卷为准）
大题分值感觉通常每道大题 15 分上下（5 道题）或 15~20 分（4 道题）

机考连考机制：下午的时间是从上午"省"出来的

⚠️【必考认知】现在的考试是两科连考、分批进行，这直接决定了你的时间策略：

  • 基础知识与应用技术连考，两科总作答时长 240 分钟；
  • 基础知识最短 90 分钟、最长 120 分钟，交卷后自动进入应用技术；
  • 所以应用技术实际能分到 120~150 分钟：上午 90 分钟就交卷，下午有 150 分钟；上午磨满 120 分钟，下午就只剩 120 分钟；
  • 具体规则以当次考试通知为准，但备考时请按最坏情况（120 分钟也能做完）练，按最好情况（150 分钟）规划。

❗【易错】很多同学以为“下午写满 120 分钟就够用”——错。连考机制下，你上午浪费的每一分钟都是从下午扣的。上午卷的目标很明确：90~100 分钟内保质保量交卷，把省下来的时间全部“搬运”到下午。

本套笔记的下午时间策略，一律按 150 分钟这个上限来设计。平时练习就直接在电脑记事本里限时写——手写很顺的 SQL，打字时括号引号照样翻车。

分值策略顺带说一句：①~④四大件是大盘，⑤⑥是嵌在各大题里的"零钱"——大题先保结构分（骨架对、格式对），小问再抢关键词分。两边都要抓，一边都别弃。

三、评分真相：老师手里有一张"关键词表"

下午题的评分方式就四个字：踩点给分。每道题背后是一张评分点清单，你答案里命中一个点，就得一个点的分，写多不扣分（跑题除外）。由此推出两条铁律：

铁律一：名词解释要凑齐"三件套"——定义 + 作用 +（举例）

以"什么是视图"为例，看三个版本的差距：

你的答案预估得分点评
"视图就是虚的表"0~1 分纯大白话，一个关键词没有
"视图是由查询语句定义的虚表，数据库中不实际存储数据"约一半分有了"虚表、只存定义"关键词，但缺作用
"视图是从一个或多个基本表（或视图）上通过 SELECT 查询定义的虚表，数据库中只保存其定义而不保存数据；作用是简化用户操作、提供一定的逻辑数据独立性，并能作安全性保护手段（对不同用户开放不同视图）；例如为财务部建立只包含工资字段的员工视图并只授权给该部门"满分定义+作用+例子，三件套齐了

铁律二：判断题必须"结论 + 理由"，理由要指认"是哪种依赖 / 违反了什么"

以"判断某关系模式是否满足 3NF"为例：

你的答案预估得分点评
"不满足 3NF"1 分只有结论，理由分全丢
"不满足 3NF，因为存在非主属性对候选键的传递函数依赖"满分结论 + 指认依赖类型
"不满足 3NF：候选键为学号，系名传递函数依赖于学号（学号→系号→系名），而系号、系名均为非主属性"满分且漂亮结论 + 指认依赖 + 写出具体依赖链，阅卷老师想扣都无从下手

一句大白话总结：判卷像法官断案——光喊"有罪"不行，必须指出违反了哪一条。

加餐：题干"设问动词"词典——看清题眼再下笔

题干的动词就是评分点的"说明书"，动词不同，期待的答案形态完全不同：

题干动词期待你干什么下笔姿势
指出 / 找出 / 列出点名即可，不必展开名词 + 半句依据，分条写
说明 / 简述 / 什么是定义 + 作用直接套名词解释三件套
比较 / 区别抓差异两列对照，每列只写差异关键词
画出 / 补全 / 完善图示规范矩形/椭圆/菱形各就各位，连线标 1/n/m
写出 / 补全语句完整 SQL先骨架后填肉，句尾分号
判断 / 分析 / 是否结论 + 理由指认"哪种依赖/违反什么协议"
为什么 / 原因原理 + 后果"因为……，会导致……"

口诀：题眼不对，答案白费；动词怎么说，分数就怎么给。

一道 3 分小问的全流程示范

以一道高频小问为例："什么是实体完整性？它由哪种约束实现？" 完整走一遍流程：

  • 第一步 看动词："什么是"→ 定义+作用，直接套模板一三件套；
  • 第二步 调关键词：主键、唯一、非空；
  • 第三步 组织成答案（2~3 行，关键词前置）：

实体完整性是指基本表中主键的取值必须唯一且不能为空的约束（定义）。它的作用是保证每个元组都能被唯一标识，防止出现无法区分的重复记录（作用）。实体完整性通过 PRIMARY KEY（主键）约束实现（落点）。

  • 第四步 对照评分点自查：主键 √、唯一 √、非空 √、唯一标识元组 √、PRIMARY KEY √——五个关键词全在，3 分落袋。

概念本身在 01 数据库基本概念与体系结构，这里示范的是"怎么把它写成能拿分的答案"——同一套流程可以套到任何名词小问上。

五、⚠️万能答题模板（考前直接背这四段）

模板一：名词解释

「XX 是指……（定义），它的作用是……，例如……」

套用示范（数据独立性）：

数据独立性是指应用程序与数据的物理结构和逻辑结构相互独立、互不影响的特性。它的作用是当数据结构改变时，应用程序不必修改，从而降低维护成本；它分为物理独立性和逻辑独立性，例如数据库更换存储设备时，应用程序无须任何改动。

踩分关键词："应用程序不必修改"——这句是阅卷老师最想看到的，千万别省。

模板二：范式判断

「先求出候选键为……，主属性为……；存在（或不存在）非主属性对候选键的（部分/传递）函数依赖……，所以 R 最高属于 XNF。」

套用示范：

先求出候选键为（学号），主属性为（学号）。存在非主属性系名对候选键学号的传递函数依赖（学号→系号→系名），故不满足 3NF；不存在非主属性对候选键的部分函数依赖，满足 2NF。所以关系模式 R 最高属于 2NF。

配套口诀："候选键打底，2NF 查部分，3NF 查传递，BCNF 看决定方。"（决定方指每个函数依赖的左部是否都包含候选键。）

模板三：ER图转关系模式

三步走，一步都不能省：

  1. 先判断联系类型：对每一对实体各问一句"一个 X 对应几个 Y"；
  2. 再按规则转换：1:1 并入任意一边 ／ 1:n 并入 n 端 ／ m:n 必须拆成独立关系模式；
  3. 最后逐一标主键和外键：每个模式都要交代"主键是谁、外键是谁、指向谁"。

配套口诀："一对一并一边，一对 n 进 n 端，多对 n 单独建，主外键挨个点。"

模板四：SQL 书写规范

三条纪律：关键字大写、一行一子句、先写框架再填条件。 考场上先把六行骨架默出来，再逐层往里填肉：

SELECT   ...        -- ① 要哪些列（含聚合函数结果）
FROM     ...        -- ② 涉及哪几张表
WHERE    ...        -- ③ 行级条件（聚合函数不许进这里！）
GROUP BY ...        -- ④ 按什么分组
HAVING   ...        -- ⑤ 组级条件（聚合条件搬进这里）
ORDER BY ...;       -- ⑥ 排序收尾，别忘了分号

先有骨架再填内容的好处：句子结构分先落袋——阅卷拆分评分点时，FROM 对了、连接条件对了、GROUP BY 对了，即使细节有瑕疵，结构分也稳拿一半以上。

六、❗高频丢分点清单（10 条，考前贴墙版）

#丢分点一句话纠正
1m:n 联系没拆成独立关系模式m:n 必须单独建表：属性=两端主键+联系属性，主键=两端主键的组合

丢分点之外，再送你三个"捡分习惯"：

  • 不会的小问也要写：评分点拆得细，你憋出"外键保证参照完整性"半句话就可能踩到一个点，空着是稳定的 0 分；
  • 关键词前置：先写"黑话"（参照完整性、传递函数依赖），再补大白话解释——阅卷老师扫前半行就能给分；
  • 字数克制：名词解释 2~3 行、判断理由 1~2 行足够。写多不加分，还挤占别题时间。

七、案例复习法：近 5 次真题做 2 遍

真题是这个星球上最接近"考什么"的东西，近 5 次的案例真题至少做两遍：

  • 第一遍：掐时间写。 120 分钟内完整作答，不会也硬写——先逼自己体验"考场上答不完"的真实压力；
  • 第二遍：对照评分点逐条改。 把官方/教辅的答案要点抄在旁边，用红字补上自己漏掉的关键词，感受"我以为我会了"和"评分点要求我写出来"之间的落差；
  • 错题本记原因不记题目。 每道错题归三类：①没背到（回对应笔记篇目重背）②背了不会用（找同类型再演一遍）③粗心（归入上文丢分点清单，考前重读）；
  • 考前一周只翻错题本和各篇速记卡，不再碰新题。

八、案例四大件速查表

先说一句四大件之间的"咬合"关系，复习时就不会把它当四件孤立的事：ER 图转出来的关系模式（①），往往就是求候选键、判范式（③）的原材料；SQL 题（②）里建的表，字段设计得好不好，背后也是①③的功夫；事务调度（④）虽然独立，但表级锁、行级锁的讨论对象就是②里建的表。 所以四大件按 10→11→12→13 的顺序学，是递进不是并列。

大件必背步骤（照着走就行）实战详解
① ER图与关系模式设计名词筛实体 → 属性归位（联系属性单独放）→"一个X对几个Y"定类型 → 按三规则转换（1:1并一边 / 1:n进n端 / m:n单独建）→ 主键外键逐个标10 案例-ER图与关系模式设计
② SQL 建表与查询六约束建表 → SELECT 六行骨架 → 连接条件 / 分组 / 子查询按题填 → 视图、授权、索引套模板11 案例-SQL建表与查询
③ 候选键与范式分解只出现在依赖左部的属性先进候选 → 闭包验证 → 定主/非主属性 → 查部分依赖（2NF）→ 查传递依赖（3NF）→ 查决定方（BCNF）→ 结论带理由12 案例-候选键与范式分解
④ 事务与并发调度找出冲突操作对 → 画优先图（有环=不可串行化）→ 按 2PL 判断封锁协议 → 死锁、隔离级别按题作答13 案例-事务与并发调度

九、考前速记卡

把这张卡片截图存手机，考前最后一晚只看它：

  • 下午题 = 踩点填空：关键词就是分，答不到点上写再多也是白干
  • 名词解释三件套：定义、作用、带例子
  • 判断题公式：结论 + 理由（指认是哪种依赖/违反了什么）
  • 时间地图：150 分钟 → 3 分钟通读标记 + 每大题 25~28 分钟 + 留 10 分钟检查；单问卡 3 分钟就跳
  • 四句模板：名词解释"XX是指……作用是……例如……"｜范式"先求候选键……存在……依赖，所以最高属于 XNF"｜ER 转换"一对一并一边、一对 n 进 n 端、多对 n 单独建、主外键挨个点"｜SQL"大写关键字、一行一子句、先写骨架再填条件"
