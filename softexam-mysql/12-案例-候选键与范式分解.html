12 案例实战三：候选键与范式分解（下午必出的推理题）

12.1 先说人话：这是一场"纸面侦探游戏"

下午卷的规范化题，本质是一场纸面侦探游戏：题目给你的函数依赖集 F 就是一沓线索，你要顺着线索一步步排查，找出那个"唯一能定人"的证据组合——候选键；再据此判断这个关系模式的"身份清白程度"——范式等级。

  • 四步法的原理在 03 关系代数与候选键求解、范式判断套路和表格法在 05 规范化与模式分解 都讲过，本篇不重复；
  • 本篇只干一件事：把"标准作答"一步一步写给你看，每步推理都摆在明面上，照着练两遍，考场上就是默写。

12.2 示范一：四步法求候选键（闭包全程展开）

题面：设关系模式 R(A, B, C, D, E)，函数依赖集 F = {A→B, B→C, C→D, D→E}，求 R 的候选键。

第 ① 步：把每个属性按"左部 / 右部"归类

属性当过左部吗？当过右部吗？归类对候选键的影响
A✓（A→B）✗只在左部（L类）必在候选键中
B✓（B→C）✓（A→B）左右都在（LR类）待验证
C✓（C→D）✓（B→C）左右都在（LR类）待验证
D✓（D→E）✓（C→D）左右都在（LR类）待验证
E✗✓（D→E）只在右部（R类）一定不在候选键中

❗【易错】别看到 B、C、D 出现在箭头右边就急着排除——判据是"在所有依赖里是否从未当过左部"。这条链式依赖里 B、C、D 都当过左部，所以它们只是"待验证"，不能直接排除。

第 ② 步：锁定候选键的"底座"

  • 只在左部（必进候选键）：{A}
  • 只在右部（必不进）：{E}
  • 候选键的底座 = {A}

第 ③ 步：检查"左右都没出现"的属性

  • 本题没有这类属性（若存在，同样必须进候选键，并入底座）。

第 ④ 步：从底座出发求属性闭包（一轮一轮推，全部写在答题纸上）

轮次当前闭包本轮应用的依赖新增属性
初始{A}————
第1轮{A, B}A→BB
第2轮{A, B, C}B→CC
第3轮{A, B, C, D}C→DD
第4轮{A, B, C, D, E}D→EE

第4轮推完全部属性：A⁺ = {A, B, C, D, E} = U（U 为全属性集）。

结论

A 能唯一决定全部属性 ⇒ 候选键 = A。

LR 类的 B、C、D 不必再单独验证：A 单独已能定全局，任何包含 A 的更大组合（如 (A,B)）都不再"极小"，不能算候选键。

12.3 示范二：组合候选键（一题两个候选键）

题面：设 R(A, B, C, D)，F = {A→B, B→A, AC→D}，求 R 的候选键。

第 ① 步：属性归类

属性当过左部当过右部归类影响
A✓（A→B、AC→D）✓（B→A）LR类待验证
B✓（B→A）✓（A→B）LR类待验证
C✓（AC→D）✗L类必在候选键中
D✗✓（AC→D）R类一定不在

第 ② 步：先试底座的闭包，不够就拉人

  • 底座 = {C}
  • C⁺ = {C}，推不出任何新属性 ⇒ 单靠 C 不够，必须从 LR 类（A、B）里补人。

第 ③ 步：LR 类属性逐个补进来求闭包（❗每个都要试，不能试一个就收工）

组合闭包推演（"→应用"表示应用一条依赖）结果
(A, C){A, C} →应用 A→B→ {A, B, C} →应用 B→A→（A 已在，无新增） →应用 AC→D→ {A, B, C, D}= U ⇒ 是候选键
(B, C){B, C} →应用 B→A→ {A, B, C} →应用 A→B→（B 已在，无新增） →应用 AC→D→ {A, B, C, D}= U ⇒ 也是候选键

结论

候选键有两个：(A, C) 与 (B, C)。 主属性：A、B、C（凡是出现在任一候选键里的属性都算）；非主属性：D。

❗【易错】只答 (A,C) 漏掉 (B,C)，是这类题最典型的丢分点。口诀：L 类打底，LR 类个个都要试。反过来 (A,B,C) 别写进去——它能推出全属性但"不极小"，不算候选键。

12.4 示范三：范式判断的标准作答语言

题面：沿用示范一的关系 R(A,B,C,D,E)，F={A→B, B→C, C→D, D→E}，判断 R 最高属于第几范式。

作答第一步：先把"身份"交代清楚

  • 候选键：A；主属性：A；非主属性：B、C、D、E

作答第二步：逐级检查，每级都给理由

检查级检查什么本题情况结论
1NF属性是否都是不可再分的原子值全是单值属性满足
2NF非主属性是否完全函数依赖于候选键（无部分依赖）候选键是单属性 A，单属性键根本不可能存在部分依赖满足
3NF非主属性之间是否无传递函数依赖A→B、B→C 且 B↛A ⇒ C 传递依赖于 A不满足

作答第三步：下结论

⚠️【必考】可直接誊写的标准作答（背这段话的骨架）：

本关系模式的候选键为 A，主属性为 A，非主属性为 B、C、D、E。 由于候选键为单属性，不存在非主属性对候选键的部分函数依赖，故 R ∈ 2NF； 又因存在 A→B、B→C 且 B 不能决定 A，非主属性 C 传递函数依赖于候选键 A，故 R 不属于 3NF。 综上，R 最高属于 2NF。

❗【易错】两个高频丢分点：

  1. 单属性候选键的题，范式检查从 2NF 起步，别想当然答 1NF；
  2. 不先写"主属性/非主属性"，后面的"部分依赖/传递依赖"就没有判断对象——阅卷按点给分，这一步是白送的。

12.5 ⚠️【必考】无损连接：Chase 表格法完整演示

题面：R(A,B,C)，F = {A→B, B→C}，分解 ρ = {R1(A,B), R2(B,C)}，判断 ρ 是否为无损连接分解。

第 ① 步：画初始表格

规则：一行 = 一个子模式，一列 = 一个属性；属性在子模式中 → 打 ✓；不在 → 填占位符号（本篇约定填"另一个子模式的名字"；教材用 b₁₃ 一类记号，含义相同，只要两行可比较即可）。

ABC
R1(A, B)✓✓R2
R2(B, C)R1✓✓

第 ② 步：逐条依赖"改写"表格；改完从头再扫，直到表格不再变化

第 1 遍扫描：

依赖检查过程能用吗
A→B看 A 列：R1 行是 ✓、R2 行是 R1，两行符号不同 ⇒ 找不到"A 相同"的两行用不上
B→C看 B 列：两行同为 ✓ ⇒ 把 C 列统一：R1 行的 R2 改成 ✓（向 R2 行对齐）✓ 改写！

改写后的表格：

ABC
R1(A, B)✓✓✓
R2(B, C)R1✓✓

第 2 遍扫描： A→B 仍用不上（A 列符号依旧不同）；B→C 已无新变化 ⇒ 表格收敛，算法停止。

第 ③ 步：判定

  • R1 行出现了一整行全 ✓ ⇒ ρ 是无损连接分解 ✓
  • 判定规则一句话：最终表格出现一行全 ✓ ⇒ 无损；扫到不再变化都凑不出 ⇒ 有损。

顺手记一个"二目分解"快速口诀

只分解成两个模式 R1、R2 时可以不画表：

公共属性 R1∩R2 若能决定 R1−R2 或 R2−R1，则分解无损。

  • 本题：R1∩R2 = {B}，B→C 成立（C ∈ R2−R1）⇒ 无损，与表格法结论一致。
  • 三个及以上模式的分解没有口诀，老实画表格。

反向对照：有损长什么样

R(A,B,C)，F = {A→B, C→B}，ρ = {R1(A,B), R2(B,C)}：

ABC
R1(A, B)✓✓R2
R2(B, C)R1✓✓
  • A→B：A 列 ✓/R1 不同 ⇒ 用不上；C→B：C 列 R2/✓ 不同 ⇒ 用不上
  • 永远停在初始表，凑不出全 ✓ 行 ⇒ 有损。

12.6 ⚠️【必考】3NF 分解：合成法步骤演示

题面：R(A,B,C,D)，F = {A→BC, B→C, AB→D}，把 R 分解为一组 3NF 模式，要求保持函数依赖。

第 ① 步：求最小函数依赖集（三小步：拆右部 → 去冗余 → 去多余左部）

(1) 拆右部（右部有多个属性的，拆成单属性）：

原依赖拆成
A→BCA→B、A→C
B→C单属性，不动
AB→D单属性，不动

得 F1 = {A→B, A→C, B→C, AB→D}

(2) 去冗余（逐条"假装删掉"，用剩下的依赖求闭包看能否推出它；推得出来 ⇒ 冗余）：

假设删掉用其余依赖求闭包推得出来吗处理
A→CA⁺：{A} →A→B→ {A,B} →B→C→ {A,B,C} →AB→D→ {A,B,C,D}，含 C能删
B→C删后 B⁺ = {B}，不含 C不能留
A→B删后 A⁺ = {A}，不含 B不能留
AB→D删后 (AB)⁺ = {A,B,C}，不含 D不能留

得 F2 = {A→B, B→C, AB→D}

(3) 去多余左部（对左部是多属性的依赖，逐个属性试"少了它行不行"）：

  • 检查 AB→D 中 B 是否多余：在 F2 下求 A⁺ = {A,B,C,D}（A→B、B→C、AB→D 全用上），已含 D ⇒ B 多余，化简为 A→D
  • 化简后再复查一遍冗余：删掉 A→D 后 A⁺ = {A,B,C}，不含 D ⇒ 不冗余，保留

得最小函数依赖集 Fm = {A→B, B→C, A→D}

第 ② 步：每个依赖建一个模式

依赖建立的模式（主键）
A→BR1(A, B)，主键 A
B→CR2(B, C)，主键 B
A→DR3(A, D)，主键 A

第 ③ 步：检查候选键是否已被包含

  • 用四步法求 R 的候选键：A 只在左部（L类）⇒ 底座 {A}；B 两端都出现（LR类）；C、D 只在右部（排除）
  • A⁺ = {A,B,C,D} = U ⇒ 候选键 = A
  • R3(A,D) 已包含候选键 A ⇒ 不用再补模式 ✓

第 ④ 步：写结论

ρ = {R1(A,B), R2(B,C), R3(A,D)}，每个模式都是 3NF； 每条依赖都完整落在某个模式里 ⇒ 保持函数依赖； 存在包含候选键的模式 R3 ⇒ 同时是无损连接分解。

❗【易错】合成法最后一步"查候选键"最容易忘。少了这一步，分解可能"保持依赖但不无损"——题目问"既保持依赖又无损"时，这一步就是分水岭。

12.7 演练题（改编自历年真题风格）

演练题一：候选键 + 范式判断 + 3NF 分解

题面：设教学管理关系模式 R(学号, 姓名, 系名, 系主任, 课程号, 成绩)，函数依赖集 F = {学号→姓名, 学号→系名, 系名→系主任, (学号,课程号)→成绩}。回答：

  1. 求 R 的候选键；
  2. 判断 R 最高属于第几范式，并说明理由；
  3. 把 R 分解为一组满足 3NF 的模式，要求保持函数依赖。

【参考答案】

第 1 问：先归类，再求闭包。

属性当过左部当过右部归类影响
学号✓✗L类必在
课程号✓✗L类必在
系名✓（系名→系主任）✓（学号→系名）LR类待验证
姓名、系主任、成绩✗✓R类排除

底座 = {学号, 课程号}，求 (学号,课程号)⁺：

轮次当前闭包应用依赖新增
初始{学号, 课程号}————
第1轮{学号, 课程号, 姓名, 系名}学号→姓名、学号→系名姓名、系名
第2轮{学号, 课程号, 姓名, 系名, 系主任}系名→系主任系主任
第3轮全部属性(学号,课程号)→成绩成绩

= U ⇒ 候选键 = (学号, 课程号)，唯一。

第 2 问：范式判断。

  • 主属性：学号、课程号；非主属性：姓名、系名、系主任、成绩
  • 姓名、系名只由候选键的一部分"学号"就能决定 ⇒ 存在非主属性对候选键的部分函数依赖 ⇒ 不满足 2NF
  • 结论：R ∈ 1NF（顺带说明：系名→系主任还构成传递依赖，但范式等级取最低的那一级）

第 3 问：合成法分解。

  • 最小覆盖：逐条检查无冗余（如删 学号→姓名 后，学号⁺ 不含姓名 ⇒ 不冗余）、左部无多余（学号⁺、课程号⁺ 均不含成绩）⇒ Fm = F
  • 每个依赖建模式：R1(学号,姓名)、R2(学号,系名)、R3(系名,系主任)、R4(学号,课程号,成绩)
  • 候选键 (学号,课程号) ⊆ R4 ✓；左部相同的 R1、R2 可合并以减少表数
  • 最终：学员(学号,姓名,系名)、系(系名,系主任)、选课(学号,课程号,成绩)，均属 3NF、保持依赖、无损连接

评分点表（分值为示意，仅供训练对照）：

问题阅卷找什么关键词示意分值
1属性归类正确；(学号,课程号)⁺ 逐轮展开；答出唯一候选键 (学号,课程号)4
2写明主属性/非主属性；"部分函数依赖"四个字；结论 1NF5
3最小覆盖检查（或说明无冗余）；合成模式并标注主键；候选键被包含；合并说明6

演练题二：求候选键 + 无损判断小题

题面：R(A,B,C)，F = {A→B, B→C}。现给出两个候选分解：

  • ρ1 = {R1(A,B), R2(A,C)}
  • ρ2 = {R1(A,C), R2(B,C)}

①求 R 的候选键；②分别判断 ρ1、ρ2 是否为无损连接分解。

【参考答案】

① 属性归类：A 只在左部 ⇒ 底座 {A}；B、C 只在右部 ⇒ 排除。 A⁺ = {A} →A→B→ {A,B} →B→C→ {A,B,C} = U ⇒ 候选键 = A。

② ρ1 无损。初始表：

ABC
R1(A,B)✓✓R2
R2(A,C)✓R1✓
  • 扫描 A→B：A 列两行同为 ✓ ⇒ B 列统一为 ✓（R2 行的 R1 改 ✓）
  • 改后 R2 行 = (✓, ✓, ✓) 全 ✓ ⇒ ρ1 无损 ✓
  • 口诀复核：R1∩R2 = {A}，A→B 即公共属性决定 R1−R2 ⇒ 无损，结论一致

ρ2 有损。初始表：

ABC
R1(A,C)✓R2✓
R2(B,C)R1✓✓
  • A→B：A 列 ✓/R1 不同 ⇒ 用不上；B→C：B 列 R2/✓ 不同 ⇒ 用不上
  • 无任何改写发生 ⇒ 凑不出全 ✓ 行 ⇒ ρ2 有损 ✗
  • 口诀复核：R1∩R2 = {C}，C 推不动 A 也推不动 B ⇒ 有损，结论一致
  • 附带说明：ρ2 没有任何模式同时装下 A 和 B，连 A→B 都丢了 ⇒ 既不无损、也不保持函数依赖

评分点表：

问题阅卷找什么关键词示意分值
①A 只在左部必在；A⁺ = {A,B,C} = U；候选键 A3
②两张初始表正确；A→B 的改写动作；"全 ✓ 行 ⇒ 无损"结论；ρ2 有损7
