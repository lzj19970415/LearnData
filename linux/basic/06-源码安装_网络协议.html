源码安装与网络协议

Linux基础Linux编译安装网络协议约 3499 字大约 12 分钟

源码安装与网络协议

本篇分两部分：一是源码编译安装（以 Tengine/Nginx 为例的标准四步法），二是网络基础（OSI/TCP 模型、TCP/UDP/IP/ARP/ICMP 协议、交换机/路由器、VLAN）。

源码包安装

应用场景

  • 系统内核版本太旧，或自带库（如 libstdc++.so.6）版本低、依赖的其他软件版本较低，导致无法安装目标软件。
  • 软件/库本质上是对机器汇编指令集的封装；在 X86 体系下不同版本内核指令集差别不大，因此可以自己在机器上编译新版本的依赖库，进而安装需要的软件。
  • 典型场景：需要最新版本、需要自定义模块/参数、yum/rpm 仓库中没有该软件。

如何下载源码包

  • 访问软件官网下载源码压缩包（.tar.gz / .tar.bz2 / .tar.xz）。
  • 课件示例：Tengine（淘宝基于 Nginx 的分支）下载地址 tengine.taobao.org。

源码安装通用四步流程

# 1. 解压源码包
tar xvf 软件名-版本.tar.gz
cd 软件名-版本/

# 2. 配置（检查编译环境、生成 Makefile、指定安装参数）
./configure --prefix=/usr/local/软件名 ...

# 3. 编译
make

# 4. 安装
make install

易错点：./configure 阶段报错十有八九是缺依赖（-devel 开发包），按报错提示用 yum 装对应 xxx-devel 包后重新 configure；前一步没成功，不要急着执行下一步。

实战：源码安装 Tengine/Nginx

# 1. 创建运行用户（编译安装的 nginx 不会自动建用户）
useradd www

# 2. 解压
tar xvf tengine-2.2.0.tar.gz
cd tengine-2.2.0

# 3. 配置：指定用户、组、安装路径和所需模块
./configure \
  --user=www \
  --group=www \
  --prefix=/usr/local/nginx \
  --with-http_stub_status_module \
  --with-http_sub_module \
  --with-http_ssl_module \
  --with-pcre

# 4. 编译并安装
make
make install

# 5. 启动（源码安装没有 systemd 服务文件，用绝对路径启动）
/usr/local/nginx/sbin/nginx

常用参数说明

configure 参数作用
--prefix=/usr/local/nginx指定安装目录（源码安装的软件都集中在此目录，便于管理/卸载）
--user=www --group=www指定 worker 进程运行用户/组
--with-http_ssl_module支持 HTTPS
--with-http_stub_status_module开启状态统计页面
--with-http_sub_module支持响应内容替换
--with-pcre支持 PCRE 正则（rewrite 必备）

源码安装后的管理特点

  • 启动/停止：/usr/local/nginx/sbin/nginx、nginx -s stop、nginx -s reload。
  • 没有像 yum/rpm 那样的卸载记录，卸载 = 直接删除 prefix 目录（干净不残留，这是相对 yum 的优点）。
  • 升级 = 下载新版源码重新走一遍 configure → make → make install。
  • 可编写 systemd service 文件把它纳入系统服务管理。

网络通信基础

通信标准：ISO 与 OSI

  • ISO：国际标准化组织（International Organization for Standardization）。
  • OSI：开放系统互联（Open System Interconnection），ISO 制定的七层结构化模型，让不同系统、不同网络之间实现可靠通信，最主要功能是帮助不同类型主机实现数据传输。

OSI 七层模型

层次名称主要功能典型协议/设备
7应用层为应用程序提供网络服务接口HTTP、FTP、DNS、SMTP
6表示层数据格式转换、加密解密、编码SSL/TLS
5会话层建立、管理、终止会话RPC、SQL
4传输层端到端可靠/不可靠传输TCP、UDP（端口）
3网络层逻辑寻址与路由选择IP、ICMP、ARP（路由器）
2数据链路层MAC 寻址、成帧、差错检测以太网（交换机、网卡）
1物理层比特流传输、电气特性网线、集线器、中继器

分层结构的优点

  • 开放的标准化接口，多厂商兼容；
  • 易于理解、学习和更新协议标准；
  • 实现模块化工程，降低开发实现复杂度；
  • 便于故障排除（逐层定位问题）。

对等通信与封装解封装

  • 对等通信：发送方第 N 层与接收方第 N 层之间按该层协议"对话"，数据实际通过下层逐层传递。
  • 封装：发送数据时，数据从上到下逐层加上各层的头部（传输层加 TCP/UDP 头 → 网络层加 IP 头 → 数据链路层加 MAC 帧）。
  • 解封装：接收方从下到上逐层剥掉头部，还原出原始数据。

TCP/IP 模型

TCP/IP 模型是实际使用的模型，与 OSI 的对应关系（易考对应层级）：

OSITCP/IP对应协议举例
应用层+表示层+会话层应用层HTTP、FTP、DNS、SMTP
传输层传输层TCP、UDP
网络层网络层（网际互联层）IP、ICMP、ARP
数据链路层+物理层网络接口层以太网

什么是网络协议

网络协议是网络上所有设备（服务器、计算机、交换机、路由器、防火墙等）之间通信规则的集合，规定了通信时信息必须采用的格式及这些格式的意义。大多数网络采用分层体系结构：每一层建立在下层之上，向上层提供服务，并把实现细节对上层屏蔽。

重要网络协议

TCP（传输控制协议）

  • 全称 Transmission Control Protocol，面向连接的、可靠的、基于字节流的传输层协议，由 RFC 793 说明；IP 报文中协议号是 6。
  • 可靠性通过"三次握手"建立连接、"四次挥手"断开连接、确认重传等机制实现。

TCP 三次握手：

客户端                    服务端
  | ---- SYN(seq=x) ---->  |    第一次：请求建立连接
  | <-- SYN+ACK(seq=y,ack=x+1) --|  第二次：同意并确认
  | ---- ACK(ack=y+1) ----> |   第三次：客户端确认，连接建立
  • 目的：双方都确认"自己和对方的收发能力正常"，防止已失效的连接请求突然到达造成资源浪费。

TCP 四次挥手：

主动方                      被动方
  | ---- FIN ---->  |   第一次：我数据发完了
  | <--- ACK ----   |   第二次：知道了（被动方可能还有数据要发）
  | <--- FIN ----   |   第三次：我也发完了
  | ---- ACK ---->  |   第四次：确认断开，等待 2MSL 后关闭
  • 为什么要四次：TCP 是全双工，两个方向的数据要分别关闭；第二次与第三次不能合并，因为被动方收到 FIN 后可能还有数据没发完。
  • TIME_WAIT 状态等待 2MSL：保证最后一个 ACK 能重传、让旧报文在网络中消亡。

UDP（用户数据报协议）

  • 全称 User Datagram Protocol，OSI 传输层中无连接的协议，提供面向事务的简单不可靠信息传送服务。
  • 缺点：不提供数据包分组、组装，不能对数据包排序；报文发出后无法得知是否安全完整到达。

UDP 特性：

  • 非面向连接：不用先建立连接、不握手；
  • 不可靠：没有确认机制；
  • 优点：资源消耗小、处理速度快（正是没做可靠性的代价）。

UDP 一般用于（丢一点没关系、但速度必须快的场景）：

  1. 即时通信：QQ 聊天，对准确性/丢包要求低，速度必须快；
  2. 在线视频：RTSP 等保证视频连续，偶尔花一帧可以接受；
  3. 网络语音电话（VoIP）：语音包小、需高速发送，偶尔断音串音无碍；
  4. DNS：同时占用 TCP 和 UDP 的 53 端口，其中 TCP/53 一般在从服务器同步主服务器时使用。

易错点：UDP 的"可靠性"不靠协议本身，靠应用程序/程序员在应用层自己保证。

IP 协议

  • TCP/IP 协议族中最为核心的协议：所有 TCP、UDP、ICMP、IGMP 数据都以 IP 数据报格式传输。
  • 特点：
    • 不可靠（unreliable）：不保证 IP 数据报成功到达；出错时（如路由器缓冲区满）就丢弃并给信源发 ICMP 消息，可靠性必须由上层（如 TCP）提供；
    • 无连接（connectionless）：不维护后续数据报的状态信息，每个数据报独立路由，可以不按发送顺序到达（先发的 A 后到、后发的 B 先到都有可能）。

ARP（地址解析协议）

  • 作用：将网络地址（IP 地址，32 位）转化为物理地址（MAC 地址，48 位）。
  • 属于"数据链路层/网络层"之间的协议：以太网中数据帧从一个主机到另一台主机是按 48 位 MAC 地址确定接口的，而不是 IP 地址；内核（驱动）必须知道目的端硬件地址才能发送数据。

ICMP（Internet 控制报文协议）

  • TCP/IP 协议族的子协议，用于在 IP 主机、路由器之间传递控制消息——网络通不通、主机是否可达、路由是否可用等网络本身的消息；不传用户数据，但对用户数据传递起重要作用。
  • 常被认为是 IP 层的组成部分；一些 ICMP 报文把差错返回给用户进程。
  • 主要功能：
    • 侦测远端主机是否存在（ping 就是基于 ICMP）；
    • 建立及维护路由资料；
    • 重导（重定向）资料传送路径。

常见网络设备

交换机

作用：扩大网络的器材，为子网络提供更多连接端口，连接更多计算机；性价比高、灵活、简单、易于实现，以太网交换机是最普及的组网设备。

主要分类（了解常见维度即可）：

分类维度类型
广义广域网交换机（电信领域）/ 局域网交换机（连接 PC、打印机等终端）
网络构成接入层、汇聚层、核心层交换机（核心层全部机箱式模块化；接入层多为固定端口式）
工作层级（按 OSI）第二层（基于 MAC 地址，最普遍，用于接入/汇聚）、第三层（基于 IP 和协议，用于核心层）、第四层以上为内容型交换机（数据中心）
传输介质/速度以太网、快速以太网、千兆以太网、FDDI、ATM、令牌环交换机
规模应用企业级（500 信息点以上，机架式）、部门级（300 以下）、工作组级（100 以内）
可管理性可管理型（支持 SNMP、RMON，便于监控流量分析，核心层必须是）/ 不可管理型
可否堆叠可堆叠（主要目的是增加端口密度）/ 不可堆叠
普通分法桌面型、工作组型、校园网型（骨干交换机，支持 VLAN 等功能）
交换技术端口交换、帧交换（应用最广泛，微分段减小冲突域）、信元交换（ATM，固定 53 字节信元）

路由器

  • 连接两个或多个网络的硬件设备，在网络间起网关作用。
  • 读取每个数据包中的地址并决定如何传送的专用智能网络设备。
  • 能理解不同协议（局域网以太网协议、因特网 TCP/IP），可把非 TCP/IP 网络地址转换成 TCP/IP 地址（或反之）；根据路由算法把数据包按最佳路线传送到指定位置。

VLAN 虚拟局域网

概念与标准

  • IEEE 于 1999 年颁布 802.1Q 协议标准草案，标准化 VLAN 实现方案。
  • VLAN 是为解决以太网的广播问题和安全性而提出的协议：在以太网帧基础上增加 VLAN 头（VLAN ID），把用户划分为更小的工作组，限制不同工作组间用户互访，每个工作组就是一个虚拟局域网。
  • 交换机根据工作站的 MAC 地址（及端口等规则）划分 VLAN；具有相同 VLAN 标签的以太网帧在同一个广播域中传送。

VLAN 的作用

  • 把同一物理局域网内的用户逻辑地划分成不同广播域：一个 VLAN 内部的广播和单播流量不会转发到其他 VLAN，控制流量、抑制广播风暴。
  • 工作站不受物理位置限制，可以在不同物理网段，按管理功能划分工作组，提高网络规划和重组的管理效率。
  • 不同 VLAN 之间没有路由就不能相互通讯，这增加了部门间安全性；管理员可通过配置 VLAN 间路由管理互访。
  • 好处小结：控制广播范围、形成虚拟工作组、动态管理网络、控制不同部门互访、提高安全性。

关键规则（易错点）

  • 物理位置不同但属于同一 VLAN 的主机 → 可以相互通信；
  • 物理位置相同但属于不同 VLAN 的主机 → 不能直接通信（需三层路由）；
  • 同一 VLAN 中的广播只有本 VLAN 成员能听到。

学习要点与实战清单

  1. 熟记 OSI/TCP 模型：OSI 七层名称与顺序、TCP/IP 四层对应关系、各层典型协议与设备。
  2. 熟记重要网络协议：
    • TCP：面向连接、可靠，三次握手/四次挥手过程；
    • UDP：无连接、不可靠、速度快，适用即时通信/视频/VoIP/DNS；
    • IP：不可靠、无连接；ARP：IP→MAC；ICMP：ping 的底层协议。
  3. 源码安装四步：tar 解压 → ./configure → make → make install，configure 报错先补依赖。
  4. 设备与层级对应：交换机工作在二层（三层交换机除外，工作在三层/核心层），路由器工作在三层并起网关作用。
  5. VLAN 靠 802.1Q 标签划分广播域；跨 VLAN 通信必须经过路由。

本篇要点小结

  1. 源码安装的核心价值是突破系统库/软件版本限制，--prefix 指定独立目录便于管理与卸载。
  2. OSI 七层是理论参考模型，TCP/IP 四层是实际模型；对等通信 + 封装/解封装是数据传输的基本过程。
  3. TCP 用三次握手建链、四次挥手断链，全双工所以挥手要四次；UDP 简单快速，可靠性交给应用层。
  4. DNS 的 53 端口 TCP/UDP 都用：UDP 查询、TCP 区域同步。
  5. 交换机按 MAC 转发（二层），路由器按 IP 路由（三层）；VLAN 隔离广播域，跨 VLAN 必须路由。
