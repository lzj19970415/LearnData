域名申请及解析

本篇覆盖：DNS 基本概念、域名分层结构、DNS 服务器层级、递归/迭代解析全过程、DNS 核心术语、常见记录类型、host/nslookup/dig 客户端排障工具、客户端 DNS 配置三种方法、公网域名申请实战。

一、DNS 基本概念

  • DNS（Domain Name System，域名系统）是因特网的一项核心服务。
  • 作用：作为将域名和 IP 地址相互映射的一个分布式数据库，让人更方便地访问互联网，而不用记住机器才能直接读取的 IP 数串。

二、域名的分层结构

1. 层次树状命名

  • 因特网用户数量多，命名采用层次树状结构。
  • 任何连接在因特网上的主机或路由器，都有一个唯一的层次结构名字，即域名（domain name）。
  • "域（domain）"是名字空间中一个可被管理的划分。
  • 从语法上讲，每个域名由标号（label）序列组成，标号之间用点隔开。
  • 域名可以划分为子域，子域还可以继续划分，形成顶级域、主域名、子域名等。

2. 分层举例

以 www.example.aliyun.com 为例：

层级示例说明
顶级域名.com通用顶级域
主域名（托管一级域名）aliyun.com主要指企业名
子域名（托管二级域名）example.aliyun.com
子域名的子域（托管三级域名）www.example.aliyun.com

三、DNS 服务器的分层结构

域名是分层结构，域名 DNS 服务器也是对应的层级结构。域名解析过程涉及 4 类 DNS 服务器：

类型英文作用
根域名服务器Root nameserver本地域名服务器本地查不到结果时，第一步向它查询，并获取顶级域名服务器的 IP 地址
顶级域名服务器Tld nameserver管理在该顶级域名服务器下注册的二级域名。如查询 www.example.com 时，.com TLD 返回二级域名 example.com 所在权威域名服务器地址
权威域名服务器Authoritative nameserver在特定区域内具有唯一性，负责维护该区域内域名与 IP 的对应关系（如云解析 DNS）
本地域名服务器DNS resolver / Local DNS响应来自客户端的递归请求，并最终跟踪直到获取解析结果。如本机自动分配的 DNS、运营商 ISP DNS、谷歌 8.8.8.8 / 114 公共 DNS

要点：

  • 每个层的域名都有自己的域名服务器，最顶层是根域名服务器；
  • 每一级域名服务器都知道下级域名服务器的 IP 地址，以便一级一级向下查询。

四、DNS 解析过程（8 步 + 2 步）

DNS 查询结果通常会在本地域名服务器中缓存，有缓存则跳过查询直接返回结果。无缓存时完整流程：

  1. 用户在浏览器输入 example.com，由本地域名服务器开始进行递归查询；
  2. 本地域名服务器采用迭代查询方法，向根域名服务器查询；
  3. 根域名服务器告诉本地域名服务器：下一步应查询的 .com 顶级域名服务器（TLD）IP 地址；
  4. 本地域名服务器向 .com TLD 查询；
  5. .com TLD 告诉本地域名服务器：下一步查询 example.com 权威域名服务器的 IP 地址；
  6. 本地域名服务器向 example.com 权威域名服务器发送查询；
  7. 权威域名服务器告诉本地域名服务器所查询主机的 IP 地址；
  8. 本地域名服务器把 IP 地址响应给浏览器。

拿到 IP 后浏览器继续：

  1. 浏览器向该 IP 发出 HTTP 请求；
  2. 该 IP 处的 Web 服务器返回要在浏览器中呈现的网页。

记忆：客户端↔本地 DNS 是递归，本地 DNS↔根/TLD/权威之间是迭代。

五、DNS 核心术语

1. 递归查询

DNS 服务器收到用户请求时，必须返回一个准确的查询结果；本地没有对应信息时，需要去询问其他服务器，把结果提交给用户。

2. 迭代查询

DNS 服务器收到请求时不直接回复结果，而是告诉用户另一台 DNS 服务器的地址，用户再向那台服务器提交请求，依次反复，直到返回查询结果。

3. DNS 缓存与 TTL

  • DNS 缓存：把解析数据存储在靠近客户端的位置（任意位置都可缓存），目的是减少递归查询过程，让用户更快拿到结果；
  • TTL（Time To Live）：告诉本地域名服务器，解析结果可缓存的最长时间。到期后本地 DNS 删除该记录，再有请求则重新发起递归/迭代查询。
    • 排障注意：改了解析记录后，TTL 之内旧结果仍会命中缓存。

4. 其他术语

术语含义
Dual IP Stack（双栈）一个系统中同时使用 IPv6/IPv4 两个可并行工作的协议栈
TLD Server顶级域名服务器
DNS Resolver本地域名服务器，DNS 查找的第一站；ISP 分配的 DNS、谷歌 8.8.8.8 都属于它
Root Server根域名服务器，本地查不到时第一步向它查询
DNS Query Flood Attack域名查询攻击：操纵大量傀儡机发送海量查询请求，超过 DNS 服务器承载能力导致解析超时，影响业务可用性
URL 转发（Url Forwarding）通过服务器特殊设置，将一个域名指向另一个已存在的站点
edns-client-subnetGoogle 提交的 DNS 扩展协议，允许 DNS resolver 把用户 IP 传给权威 DNS（用于就近解析）
DNSSEC域名系统安全扩展，通过数字签名保证 DNS 应答报文的真实性和完整性，防 DNS 欺骗和缓存污染

六、DNS 记录类型

DNS 支持 A、AAAA、CNAME、MX、TXT、SRV、NS、CAA 等记录类型：

记录类型功能描述
AIPv4 记录，将域名映射到 IPv4 地址
AAAAIPv6 记录，将域名映射到 IPv6 地址
CNAME别名记录，将域名指向另外一个域名
MX电邮交互记录，将域名指向邮件服务器地址
TXT文本记录，任意可读的文本（常用于 SPF、站点验证）
SRV服务器资源记录，标识某台服务器使用了某个服务，常见于微软目录管理
NS名称服务器记录，将子域名委托给其他 DNS 服务商解析
CAA限定域名颁发证书和 CA（证书颁发机构）之间的联系

七、DNS 客户端检测工具

正解（域名→IP）与反解（IP→域名）查询命令：host、nslookup、dig。三者默认读取 /etc/resolv.conf 获取 DNS 服务器。

1. host

语法

host [选项] [主机名或IP] [server]
  • -a：列出该主机详细的主机名设定资料；
  • server：默认用 /etc/resolv.conf 中的 DNS 查询，设置该参数则用指定 DNS 查询。

应用实例

host www.baidu.com
# www.baidu.com is an alias for www.a.shifen.com.        ← CNAME
# www.a.shifen.com has address 61.135.169.125
# www.a.shifen.com has address 61.135.169.121

host -a www.baidu.com        # 详细信息，含 NS、A 记录、TTL
host www.baidu.com 8.8.8.8   # 指定 DNS 服务器解析
host www.baidu.com dns.hinet.net

易错点：CNAME 指向的域名（如 www.a.shifen.com、防火墙/高防 IP 生成的 CNAME）是用于 DNS 解析的，不能直接访问。

2. nslookup

语法与实例

nslookup www.baidu.com        # 正解：域名 → IP
nslookup 168.95.1.1           # 反解：IP → 主机名（不是所有 IP 都能解析成功）
nslookup server               # 查看本机使用的 DNS 服务器

输出解读：

Server:         10.0.2.3           # 当前使用的 DNS 服务器
Address:        10.0.2.3#53
Non-authoritative answer:          # 非权威应答（来自缓存）
Name:   www.baidu.com
Address: 61.135.169.121

3. dig（推荐）

功能与 nslookup 类似，建议用 dig 取代 nslookup。

安装与语法

yum install bind-utils          # 系统默认没有时安装
dig [选项] [主机名]
# @：指定 DNS 服务器（默认用 /etc/resolv.conf）
# -b：本机多 IP 时指定用哪个源 IP 发查询

应用实例

dig www.baidu.com
dig @168.95.1.1 www.baidu.com     # 用指定 DNS 查询

dig 输出分区解读（重点）

;; flags: qr rd ra; QUERY: 1, ANSWER: 3, AUTHORITY: 5, ADDITIONAL: 6

;; QUESTION SECTION:
;www.baidu.com.                 IN      A

;; ANSWER SECTION:
www.baidu.com.          1096    IN      CNAME   www.a.shifen.com.
www.a.shifen.com.       290     IN      A       61.135.169.121
www.a.shifen.com.       290     IN      A       61.135.169.125

;; AUTHORITY SECTION:
a.shifen.com.           34      IN      NS      ns3.a.shifen.com.
...

;; Query time: 11 msec
;; SERVER: 10.0.2.3#53(10.0.2.3)
  • HEADER：查询概况，1 个 QUERY、3 个 ANSWER、5 个 AUTHORITY；
  • QUESTION：要查询的内容；
  • ANSWER：查询得到的结果（含 CNAME 链和 A 记录）；
  • AUTHORITY：该域名由哪些 DNS 服务器（NS）提供解析；
  • ADDITIONAL：NS 服务器对应的 A 记录等附加信息；
  • 数字列（如 1096、290）是该记录的 TTL 秒数。

八、DNS 客户端配置

CentOS 7 中直接手动改 /etc/resolv.conf，系统会重新覆盖或清除（NetworkManager 管理）。三种正确做法：

1. 方法一：nmcli（推荐）

# 1. 查看网络连接
nmcli connection show
# NAME  UUID                                  TYPE      DEVICE
# eth0  662a58e0-...-...                      ethernet  eth0

# 2. 修改连接的 DNS（连接可用名称或 UUID 标识）
nmcli con mod eth0 ipv4.dns "114.114.114.114 8.8.8.8"

# 3. 激活配置
nmcli con up eth0

帮助：man NetworkManager.conf、man nmcli。

2. 方法二：关闭 NetworkManager 对 resolv.conf 的管理

# 1. 修改 NetworkManager 配置，在 [main] 段添加 dns=none
vim /etc/NetworkManager/NetworkManager.conf
[main]
plugins=ifcfg-rh
dns=none

# 2. 重启 NetworkManager
systemctl restart NetworkManager.service

# 3. 手工修改 /etc/resolv.conf（此后不再被覆盖）
vim /etc/resolv.conf
nameserver 114.114.114.114
nameserver 8.8.8.8

3. 方法三：网卡配置文件指定 DNS

cd /etc/sysconfig/network-scripts/
vim ifcfg-eth0
TYPE="Ethernet"
BOOTPROTO="static"              # 启用静态 IP
DEFROUTE="yes"
IPV4_FAILURE_FATAL="no"
NAME="eth0"
UUID="8071cc7b-d407-4dea-a41e-16f7d2e75ee9"
ONBOOT="yes"                    # 开机自动启用网络连接
IPADDR0="192.168.21.128"        # 设置 IP 地址
PREFIX0="24"                    # 设置子网掩码
GATEWAY0="192.168.21.2"         # 设置网关
DNS1="8.8.8.8"                  # 设置主 DNS
DNS2="8.8.4.4"                  # 设置备 DNS
HWADDR="00:0C:29:EB:F2:B3"
service network restart         # 重启网络
ping www.baidu.com              # 测试域名解析与连通性
ip addr                         # 查看IP地址

易错点：网卡配置文件中的 DNS1/DNS2 与 /etc/resolv.conf 联动；直接改 resolv.conf 而不改配置，重启网络后会被还原。

九、公网域名申请实战

  1. 域名申请：在域名服务商（阿里云万网/新网等）注册并购买域名，完成实名认证；
  2. 配置解析：在域名服务商后台添加解析记录——
    • 指向服务器 IP 用 A 记录；
    • 负载/CDN 场景用 CNAME；
    • 邮件服务配 MX 记录；
    • 子域委托用 NS 记录；
  3. 测试验证：用 host/nslookup/dig 测试公网域名解析结果，核对解析到的 IP 是否为预期服务器；
  4. TTL 生效注意：新改的记录要等旧 TTL 过期才在全球生效。

十、易错点汇总

  • 客户端→本地 DNS 是递归，本地 DNS→根/TLD/权威是迭代，两者别混淆。
  • CNAME 指向的别名域名用于解析，不能直接在浏览器访问。
  • CentOS7 直接改 /etc/resolv.conf 会被 NetworkManager 覆盖，用 nmcli 或 dns=none 才能持久。
  • dig 输出中的数字是 TTL（秒），AUTHORITY 段给的是 NS 记录不是解析结果。
  • Non-authoritative answer 表示结果来自缓存而非权威服务器。
  • nslookup 反解 IP 不一定成功（PTR 记录未必配置）。
  • 修改解析记录后受 TTL 缓存影响，不是立即全局生效。
