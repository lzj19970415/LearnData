网络维护与管理

千锋 Linux 课件《学 Linux，掌握这 80 个命令就够了》第五篇《网络维护与管理命令》。覆盖：网卡查看配置（ifconfig）→ 远程拷贝（scp）→ 连接端口排查（netstat）→ 路由追踪（traceroute）→ 端口探测（telnet）→ 下载与 HTTP 调试（wget / curl），构成一套完整的网络排障工具链。

命令速查表

命令功能
ifconfig查看 / 配置网络接口
scp跨主机安全拷贝文件
netstat查看连接、端口、路由表
traceroute追踪数据包传输路径
telnet端口连通与服务探测
wget从网络下载文件
curlURL 传输与 HTTP 调试

1. ifconfig：查看 / 配置网络接口

配置网络或显示当前网络接口状态，类似 Windows 的 ipconfig，必须以 root 用户执行。

ifconfig [选项] [interface] [inet|up|down|netmask|addr|broadcast]

选项：

选项含义
-a显示所有网络接口（含活动的和非活动的）
-s仅显示每个接口的摘要，每个接口一行
-v接口出现错误时返回错误信息，帮助发现处理故障

参数说明：

  • interface：网络接口名，如 eth0、eth1、lo（回环）；CentOS 7.x 中变为 enp0s1、enp0s2 这类标识。不指定则显示所有网卡
  • up：激活网络接口
  • down：禁用网络接口
  • netmask：指定子网掩码
  • addr：指定 IP 地址
  • broadcast：设置广播地址

输出解读：

ifconfig
# enp0s3: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
#         inet 192.168.81.232  netmask 255.255.255.0  broadcast 192.168.81.255
#         inet6 fe80::a00:27ff:fe90:55  prefixlen 64  scopeid 0x20<link>
#         ether 08:00:27:90:00:55  txqueuelen 1000  (Ethernet)
#         RX packets 20378  bytes 1845248 (1.7 MiB)
#         RX errors 0  dropped 0  overruns 0  frame 0
#         TX packets 958  bytes 147065 (143.6 KiB)
#         TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0
  • 第 1 行：UP 网卡开启、RUNNING 网线连接、MULTICAST 支持组播、MTU 1500 最大传输单元 1500 字节
  • 第 2 行：IP 地址、子网掩码、广播地址
  • 第 3 行：IPv6 地址配置信息
  • 第 4 行：ether 后为网卡 MAC 地址，Ethernet 表示连接类型为以太网
  • 第 5~6 行：接收数据包统计与接收错误统计
  • 第 7~8 行：发送数据包统计与发送错误统计

配置示例：

# 1. 配置 IP 与子网掩码
ifconfig enp0s3 192.168.60.136 netmask 255.255.255.0

# 2. 在同一网卡上配置第二个 IP（子接口）
ifconfig enp0s3:0 192.168.66.138 netmask 255.255.255.0
# 继续增加则命名为 enp0s3:1、enp0s3:2……

# 3. 修改 MAC 地址
ifconfig enp0s3 hw ether xx:xx:xx:xx:xx:xx

# 4. 禁用后再启用网卡
ifconfig enp0s3 down
ifconfig enp0s3 up

重要：用 ifconfig 配置的网卡信息是临时生效的，网卡重启或机器重启后全部失效；要让配置永久生效，必须修改网卡的配置文件（如 /etc/sysconfig/network-scripts/ifcfg-enp0s3）。

2. scp：跨主机安全拷贝

scp 即 secure copy，用于将文件或目录从一个 Linux 系统拷贝到另一个 Linux 系统，传输基于 SSH 协议，保证数据安全。

# 格式一：远程 → 本地
scp 远程用户名@IP:文件的绝对路径 本地路径
# 格式二：本地 → 远程
scp 本地文件路径 远程用户名@IP:远程绝对路径

示例：

# 把本地 /home/ixdba/etc.tar.gz 推到远程 root 的 /tmp
scp /home/ixdba/etc.tar.gz root@192.168.60.168:/tmp

# 在远程服务器上把源文件拉回本地 /tmp
scp root@192.168.60.133:/home/ixdba/etc.tar.gz /tmp

# -r 拷贝目录（含义同 cp 的 -r）
scp -r /etc root@192.168.60.135:/opt

执行后会提示输入对端用户密码，然后开始远程拷贝。

3. netstat：连接 / 端口 / 路由

显示本机网络连接、运行端口和路由表等信息。

netstat [选项]
选项含义
-a显示本机所有连接和监听端口
-n以网络 IP 地址形式显示有效连接和端口
-r显示路由表信息
-s按协议显示统计信息（IP、ICMP、TCP、UDP 等）
-v显示当前的有效连接
-t显示所有 TCP 协议连接情况
-u显示所有 UDP 协议连接情况
-c 秒数每隔几秒刷新显示一次
-i显示自动配置接口的状态
-l仅显示状态为 LISTEN 的服务
-p显示连接对应的 PID 与 Program name

查看路由表：

netstat -rn
# Kernel IP routing table
# Destination     Gateway         Genmask         Flags   Iface
# 0.0.0.0         192.168.81.250  0.0.0.0         UG      enp0s3
# 169.254.0.0     0.0.0.0         255.255.0.0     U       enp0s3
# 192.168.81.0    0.0.0.0         255.255.255.0   U       enp0s3
  • 0.0.0.0 目标 + UG 标志 = 默认网关是 192.168.81.250，对应接口 enp0s3

查看所有有效连接：

netstat -an
# Proto  Recv-Q  Send-Q  Local Address        Foreign Address       State
# tcp    0       0       0.0.0.0:22           0.0.0.0:*             LISTEN
# tcp    0       52      192.168.81.232:22    192.168.81.30:65409   ESTABLISHED

输出字段：

  • Proto：连接协议（TCP/UDP）
  • Recv-Q / Send-Q：收发队列字节数
  • Local Address：本地 IP 与端口（也可以是主机名）
  • Foreign Address：远程主机 IP 与端口
  • State：连接状态

常见状态：

状态含义
LISTEN服务正在监听端口
SYN_SENT已发出主动连接请求，等待对方确认
SYN_RECV接收到对方的连接请求
ESTABLISHED连接已建立
TIME_WAIT连接已中断，socket 还在网络中等待结束
FIN_WAIT1连接已中断，正在中断过程中
FIN_WAIT2连接已中断，正在等待对方中断确认

实战判断端口对外开放情况：

  • 面向 0.0.0.0 监听的端口（如 80、22、23）对外开放
  • 仅监听 127.0.0.1 的端口（如 25、631）只对本机开放
  • 最后一列显示端口对应的服务名与进程 ID，方便确认每个端口的用途

常用组合（补充）：

netstat -tlnp             # 本机监听的 TCP 端口 + 进程名
netstat -anp | grep :22   # 确认某端口的连接情况
netstat -s                # 协议统计，排查丢包/错包

4. traceroute：路由追踪

显示数据包传输到指定主机的路径信息，追踪数据传输路由状况，类似 Windows 的 tracert。预设数据包大小 38 字节，可另行设置。

traceroute [选项] [远程主机名或IP] [数据包大小]
选项含义
-i 网络接口使用指定的网络接口发送数据包
-n直接使用 IP 地址而不使用主机名
-v详细显示命令的执行过程
-w 秒数设置等待远程主机回应的时间
-x开启或关闭对数据包的正确性检验
-s 来源IP设置本地主机发送数据包的 IP 地址
-g 网关设置来源的路由网关，最多可设置 8 个

示例：

traceroute -i eth0 -s 192.168.60.251 -w 10 www.ixdba.net 100
# 指定 eth0 接口、源 IP 192.168.60.251、超时 10 秒、包大小 100 字节
# 输出显示经过 18 个路由迂回到达目标 221.130.192.57

输出解读：

  • 每行一个路由节点，对每个节点做 3 次回应时间测试
  • 总跳数（hops）反映路径长短；某节点延迟明显升高说明该段网络慢
  • 若在指定时间内检测不到某节点回应，输出 *：可能此节点不通，也可能是防火墙屏蔽了 ICMP，分析网络问题时要注意区分

5. telnet：端口探测

通过 telnet 协议与远程主机通信，或获取远程主机对应端口的信息；运维中最常用作端口连通性测试。

telnet 主机名或IP 端口

登录开启 telnet 服务的远程主机（默认 23 端口）：

telnet 192.168.60.123 23
# Trying 192.168.60.123...
# Connected to 192.168.60.123.
# Escape character is '^]'.
# centos7 login: ixdba
# Password:

连接被拒绝：

telnet 192.168.60.123 25
# telnet: connect to address 192.168.60.123: Connection refused
# → 这个端口对应的服务没有开启，或者端口被屏蔽无权访问

从 banner 识别服务类型与版本：

telnet 192.168.60.88 22
# Connected to 192.168.60.88.
# SSH-2.0-OpenSSH_6.6.1
# → 22 端口运行 SSH 服务，版本 OpenSSH 6.6.1

telnet www.ixdba.net 80
# 连上后（Escape character is '^]'）键盘输入 get，
# 返回信息中可见 80 端口的应用服务组合：
# Apache/2.2.4 (Unix) PHP/5.2.3 mod_fastcgi/2.4.2 Resin/3.1.3

运维核心价值：验证"对方 IP 的某端口是否通"，验证端口开通与放行规则非常高效。注意 telnet 明文传输，远程管理请用 ssh；telnet 只做探测工具。

6. wget：文件下载

从网络上下载软件或文件，对能连接互联网的 Linux 系统非常实用。

wget [要下载软件的网址]
wget https://www.kernel.org/pub/linux/kernel/v4.x/linux-4.0.2.tar.xz
# 显示过程：域名解析 → 建立连接 → HTTP 200 OK → 文件大小与下载进度

常用参数（补充）：-c 断点续传、-O 新文件名、-q 安静模式。

7. curl：URL 传输与 HTTP 调试

curl（CommandLine URL）在命令行下用 URL 语法进行数据传输，支持 FILE、FTP、FTPS、Gopher、HTTP、HTTPS、IMAP、LDAP、POP3、RTMP、RTSP、SCP、SFTP、SMB、SMTP、Telnet、TFTP 等 30 多种传输方式。

对运维人员来说，探测远程服务（HTTP 传输、SOCKET 连接）时，curl 是非常方便的验证与测试工具。

7.1 查看网站 header

curl -I https://www.ixdba.net
# HTTP/1.1 200 OK
# Server: nginx/1.13.9
# Date: Mon, 04 Mar 2019 08:11:31 GMT
# Content-Type: text/html; charset=UTF-8
# Connection: keep-alive

-I（大写 i）获取响应头：状态码 200 表示站点正常，还能看到 Web 服务器类型（nginx/1.13.9）及是否开启 keep-alive。

7.2 只输出 HTTP 状态码

curl -s -o /dev/null -w "%{http_code}\n" http://www.baidu.com
# 200
  • -s：安静模式，不输出错误或进度条
  • -o /dev/null：把响应内容写入空设备（不刷屏）
  • -w：输出自定义元数据，格式 %{variable_name}

常用 -w 变量：

变量含义
http_codeHTTP 状态码
http_connect连接状态码
time_total总耗时（秒，精确到 3 位小数）
time_connectTCP 建连耗时
time_appconnectSSL 握手耗时
time_redirect重定向耗时
size_download / size_upload下载 / 上传字节数
content_type响应内容类型
ssl_verify_resultSSL 证书校验结果

组合示例：

curl -s -o /dev/null -w "%{http_code} %{time_total} %{redirect_url}\n" http://www.ixdba.net
# 301 0.141 https://www.ixdba.net/
# → http 访问被 301 定向到 https；0.141 为总耗时（秒）

Web 页面监控中，经常通过状态码判断网页状态：返回非 200 状态则认为网页异常（301/302 等跳转按业务实际判定）。

7.3 URL 重定向（跟随跳转）

默认 curl 不发送 HTTP Location headers，加 -L 后页面移动到新站点时自动重定向：

curl -L -I http://www.ixdba.net
# HTTP/1.1 301 Moved Permanently
# Location: https://www.ixdba.net/
# HTTP/1.1 200 OK

输出有两部分：先 301，再自动跳转到 https 拿到 200。

7.4 抓取网页内容 / 下载文件

# 用 URL 中的默认文件名保存
curl -O https://www.ixdba.net/archives/2017/06/653.htm

# 下载后重命名为 test.html
curl -o test.html https://www.ixdba.net/archives/2021/06/653.htm
  • -O：使用 URL 中默认的文件名保存到本地
  • -o：保存为命令行中指定的文件名

7.5 断点续传

curl -C - -O https://example.com/bigfile.tar.gz
  • -C -：自动断点续传（注意参数是 -C -，否则需要手工指定断点的字节位置）
  • 下载中途 Ctrl+C 中断，再次执行 curl 下载即从断点继续；输出可见文件总大小、已下载大小、耗时、速度等属性

7.6 限速下载

curl --limit-rate 2M -O https://example.com/bigfile

下载大文件会占满系统带宽，可能影响线上业务；--limit-rate 限制下载网速（示例限速 2M，实际下载速度约 2048k 左右）。

补充：日常排障命令组合

ping 192.168.1.1              # 连通性与延迟（-c 4 指定次数）
ping baidu.com                # 通 IP 不通域名 → 先查 DNS

ip addr                       # CentOS 7 查看网卡信息（替代 ifconfig）
ss -tlnp                      # 查看监听端口 + 进程（替代 netstat，更快）
ss -s                         # 连接状态统计汇总

curl -I http://IP:端口        # 快速验证 Web 服务是否响应
telnet IP 端口                # 验证任意 TCP 端口连通

排障思路小结（补充）

  1. 先链路：ping 网关 → ping 公网 IP → ping 域名（不通域名但通 IP 先查 DNS）
  2. 再路由：traceroute 看数据包断在哪一跳
  3. 再端口：telnet / curl 探测服务端口；Connection refused = 服务未启动或被拦截
  4. 再看服务：netstat -tlnp / ss -tlnp 确认监听状态，查服务日志定位
  5. 最后看配置：防火墙规则、SELinux、网卡配置文件是否永久生效

要点速记

  • ifconfig 改配置临时生效，永久生效要写网卡配置文件
  • 一块网卡多个 IP：enp0s3:0、enp0s3:1 子接口
  • scp：本地→远程 scp 本地文件 user@ip:路径；目录加 -r
  • netstat 三板斧：-rn 看网关、-an 看连接、-tlnp 看监听端口与进程
  • 0.0.0.0 监听 = 对外开放；127.0.0.1 监听 = 仅本机
  • traceroute 输出 * 不一定是故障，可能是防火墙拦 ICMP
  • telnet 是最常用的端口连通验证工具；banner 可识别服务版本
  • curl 调试四件套：-I 看头、-w %{http_code} 看状态码、-L 跟重定向、-C - 断点续传、--limit-rate 限速
