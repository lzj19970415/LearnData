软件管理

Linux（红帽系）安装软件有四种途径：yum、rpm、source（源码编译）、bin（二进制）。日常以 yum 为主、rpm 为辅，特殊需求用源码编译。本篇重点掌握 RPM 包结构与 rpm/yum 两套工具。

Linux 软件包管理机制

红帽系软件管理分类

方式说明典型场景
yum基于 RPM 的包管理器，自动解决依赖，需配置软件仓库日常安装首选
rpm直接安装 RPM 包，不解决依赖离线安装单个包、查询包信息
source源码编译安装（configure → make → make install）需要新版本/自定义模块
bin官方提供的二进制安装包/脚本（如 .run、.bin）JDK 等官方安装器

RPM 软件包命名规则

以 lftp-4.0.9-1.el6.x86_64.rpm 为例：

lftp   -  4.0.9  -  1   -  el6   -  x86_64  .rpm
软件名    主.次.修订  发布号  操作系统   CPU 平台
  • 操作系统：el5/el6/el7（RHEL/CentOS 版本）、fedora、suse、debian、ubuntu。
  • CPU 平台：
    • i386 / 486 / 586 / 686 → 32 位软件；
    • x86_64 → 64 位软件；
    • noarch → 32/64 位通用（脚本、文档类包常见）。

软件依赖性

RPM 包之间存在依赖关系（A 依赖 B 的库才能运行），rpm 命令不会自动装依赖，这是它与 yum 的本质区别——yum 的核心价值就是自动解决依赖。

RPM 工具详解

安装

rpm -ivh 软件包名称
# -i install 安装
# -v verbose 显示详细信息
# -h human 以 # 号显示安装进度
rpm -ivh lftp-4.0.9-1.el6.x86_64.rpm

查询（重点）

rpm -qa                    # 列出系统所有已安装软件（-a all）
rpm -qa | grep lftp        # 过滤查询，输出完整包名：lftp-4.0.9-1.el6.x86_64

rpm -ql 软件名              # 查询软件的安装路径/文件列表（-l list）
rpm -ql lftp-4.0.9-1.el6.x86_64

rpm -qi 软件名              # 查询软件详细信息（版本、厂商、大小等，-i information）
rpm -qi gedit-2.28.4-3.el6.x86_64

rpm -qc 软件名              # 查询软件的配置文件

rpm -qf /etc/passwd        # 反查某文件由哪个软件产生（-f file）
# setup-2.8.14-20.el6.noarch
rpm -qf /bin/rpm
# rpm-4.8.0-32.el6.x86_64

rpm -qf 在排查"这个文件/命令是哪来的"时非常实用。

卸载

rpm -e 软件名称        # -e erase 卸载
rpm -e lftp

特殊参数（易错点）

rpm -ivh 包名 --force    # 强制安装（覆盖已存在文件、降级安装时用）
rpm -e 软件名 --nodeps   # 卸载时不检查依赖关系

易错点：

  1. --force 是安装时用，--nodeps 是卸载时用，别记反。
  2. 卸载时如果别的包依赖它，rpm 会报错；强行 --nodeps 可能导致依赖它的软件损坏，优先用 yum 处理。
  3. rpm 卸载/查询时通常写软件名（如 lftp），安装时才写完整包名（lftp-4.0.9-1.el6.x86_64.rpm）。

Yum 工具详解

yum 源分类

类型baseurl 写法说明
本地 yum 源file:///mnt/cdrom/...用本机光盘镜像/目录作仓库，离线可用
远程 yum 源http://10.18.44.196/...、ftp://10.18.44.196/...走 HTTP/FTP 的内网仓库或公网镜像（阿里云等）

yum 源的本质：一个提供软件仓库（repodata 元数据）的服务端 + 客户端的 repo 配置文件。

配置本地 yum 源

# 1. 挂载系统镜像到本地目录
# rhel6 镜像内有两层目录，需指到 Server
mount -o loop /rhel6u4.iso /mnt/rhel6u4

# rhel7/centos7 直接挂 iso 或光驱
mount /centos7u3.iso /mnt/centos7u3
mount /dev/cdrom /mnt/centos7u3
# 虚拟机场景：把 iso 放进虚拟机光驱并"开机连接"，再 mount /dev/cdrom

# 2. 清空并编写 yum 客户端配置文件
cd /etc/yum.repos.d/
rm -rf /etc/yum.repos.d/*    # 慎用：会删掉原有网络源配置
vim yum.repo                 # 文件名必须以 .repo 结尾
[rhel6-Server]                       # yum 源区分名称（唯一 id）
name=rhel6                           # yum 源描述（comment）
baseurl=file:///mnt/rhel6u4/Server   # 仓库绝对路径（本地 file:// 必须三个斜杠）
enabled=1                            # 1=启用此源，0=禁用
gpgcheck=0                           # 0=不校验 GPG 签名，1=校验（需配 gpgkey）
# 3. 清缓存并验证
yum clean all
yum repolist

配置阿里云网络 yum 源

wget -O /etc/yum.repos.d/CentOS-Base.repo http://mirrors.aliyun.com/repo/Centos-7.repo
yum clean all
yum makecache

yum 常用命令速查

yum clean all            # 清理 yum 缓存
yum makecache            # 缓存软件包元数据，提高搜索/安装速度
yum repolist             # 查询当前可用 yum 源信息

yum search mysql         # 按关键词搜索软件（含未安装的），可用来测试 yum 是否可用
yum list                 # 列出已安装与可安装的软件
yum deplist mysql        # 查看软件的依赖关系
yum provides ld-linux.so.2   # 查看某个文件/库属于哪个软件（类 rpm -qf，但含未安装包）

yum install mysql mysql-server -y    # 安装，-y 跳过确认
yum reinstall 软件名                  # 重装
yum remove mysql-server             # 卸载（yum erase 同义）

yum 软件组

yum grouplist            # 列出已安装与可安装的软件组
yum groupinfo '组名'      # 查看软件组包含的具体软件
yum groupinstall 'GNOME Desktop'    # 安装软件组

注意：软件或软件组名称含空格时必须加引号（或转义空格），否则会被当成多个包名。

源码与二进制安装简介

当 yum/rpm 源里的版本太旧或缺少需要的模块时，用源码编译：下载官网源码 → ./configure（检查环境、指定参数）→ make（编译）→ make install（安装）。详细流程见《源码安装与网络协议》一篇。

二进制 bin 包（如 jdk-xxx-linux-x64.bin）是厂商打包好的可执行文件，chmod +x 后直接运行即可。

实战练习清单

用 rpm 完成以下操作，检验掌握程度：

# 1. 安装一个本地 rpm 包
rpm -ivh lftp-4.0.9-1.el6.x86_64.rpm

# 2. 查看已安装软件
rpm -qa | grep lftp

# 3. 查看安装路径
rpm -ql lftp

# 4. 反查文件来源
rpm -qf /etc/passwd

# 5. 卸载
rpm -e lftp

用 yum 完成以下操作：

# 1. 配置好本地/网络源后清理缓存
yum clean all && yum makecache

# 2. 测试源可用性
yum search mysql

# 3. 安装、重装、卸载
yum install -y mysql mysql-server
yum reinstall mysql
yum remove mysql-server

yum 进阶命令

更新与信息查询

yum check-update          # 检查有哪些可更新的软件（不实际更新）
yum update                # 更新所有可更新的软件
yum update 软件名           # 只更新指定软件
yum downgrade 软件名        # 降级到低版本（新版有问题时回退用）

yum info 软件名            # 查看软件包详细信息（版本、大小、简介、源）
yum list installed        # 只列出已安装的软件
yum list available        # 只列出可安装的软件
yum list 'mysql*'         # 按通配符模糊查询

安装本地 rpm 包（yum localinstall）

yum localinstall /root/lftp-4.0.9.rpm -y
# 用 yum 安装本地 rpm 包，好处：连本地包的"依赖"也自动从仓库解决
# 这是 rpm -ivh 解决不了的问题

yum 历史记录

yum history               # 查看 yum 操作历史（何时装/卸了什么）
yum history info <id>     # 查看某次操作的详细包清单
yum history undo <id>     # 撤销某次操作（一键回滚安装/升级）

相关目录

路径作用
/etc/yum.repos.d/repo 配置文件目录
/var/cache/yum/yum 下载的软件包与元数据缓存（clean all 就是清这里）
/var/log/yum.log（或 dnf history）历史安装/卸载日志

rpm 与 yum 对比（必会）

对比项rpmyum
依赖处理不处理，缺依赖直接报错自动解决依赖
安装来源本地 rpm 包文件软件仓库（本地目录/HTTP/FTP）
优点离线可装、速度快依赖自动、可查询仓库、支持软件组
典型用途已拿到完整包且无依赖、查询包信息日常所有安装/卸载/更新
关系底层基于 rpm 的上层封装

常见问题排查

源不可用 / 找不到软件

# 现象：Could not resolve host / Cannot find a valid baseurl
# 原因：网络不通、repo 文件 baseurl 写错、DNS 问题
yum repolist                       # 先看源是否正常识别
cat /etc/yum.repos.d/*.repo        # 检查 baseurl 拼写与 enabled=1
ping mirrors.aliyun.com            # 测试网络与 DNS

# 现象：No package xxx available.
# 原因：当前源里没有该包 → 换源（阿里云/epel）或 yum search 确认包名

缓存与元数据问题

# 现象：repodata 不存在 / metadata 过期报错
yum clean all      # 清缓存
yum makecache      # 重建缓存

GPG 校验失败

# 现象：Public key for xxx.rpm is not installed
# 处理：在 repo 中导入对应 gpgkey，或学习环境临时 gpgcheck=0

依赖冲突

# 现象：rpm -ivh 报 dependency 错误
# 首选：用 yum localinstall 自动补依赖
# 应急：rpm -ivh --nodeps（跳过依赖，可能装完用不了，慎用）

易错点汇总

  1. repo 文件名必须以 .repo 结尾，否则 yum 不识别。
  2. 本地 baseurl 是 file:///mnt/...（三个斜杠：协议头 file:// + 绝对路径 /mnt）。
  3. yum clean all 之后要 yum makecache 重建缓存，否则可能报错或变慢。
  4. rpm 管"单个包"，yum 管"仓库+依赖"；离线环境配好本地源后 yum 同样好用。
  5. rm -rf /etc/yum.repos.d/* 前先备份，删掉网络源后服务器将无法在线装软件。
  6. 含空格的软件组名要加引号：yum groupinstall 'Development Tools'。
  7. rpm 查询/卸载写软件名，安装写完整包名；--force 用于安装、--nodeps 用于卸载。
  8. 拿到本地 rpm 包但缺依赖时，用 yum localinstall 而不是死磕 rpm -ivh。
